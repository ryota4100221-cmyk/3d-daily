## 何を再現したか（1点だけ）

**「面の重なりだけで奥行きが出ていて、中央の光点だけが明るい」** ——この1点。

この記述を読んで引っかかったのは「面の重なりだけで」のほうだった。奥行きが面の
重なりで出ているなら、**明るさも面の重なりで出せるはずだ**。つまり光源が要らない。

## 分解した装置: 累算開口（accumulated aperture）

装置の主張はひとつ。**光源を1つも置かない。明るさは「視線が横切った面の枚数」でできている。**

そのために描画のスイッチを2つ切った:

| | 切る前 | 切った後 |
|---|---|---|
| `depthTest` | 手前の面が奥の面を隠す | 隠さない＝可視性の問題が消える |
| blending | `SRC_ALPHA / ONE_MINUS_SRC_ALPHA` | `ONE / ONE` |

この2つを切った瞬間、画素の値は
`(その画素を通った開口の枚数) × (1枚あたりの寄与 gain)` という**ただの数え上げ**になる。
シェーディングは1行も無い。法線も無い。ライトも無い（HUD の `LIGHT SOURCES  ZERO`）。

**中心が明るいのは、中心に光を置いたからではない。** 遠い開口ほど画面上で中心に畳まれ、
単位面積あたりの枚数が距離の2乗で増えるからでしかない。金の光点は置いた結果ではなく、
数え上げの結果として出てくる（色も同じで、リングは1枚ずつは暗い金なのに、
重なった中心だけが白熱する）。

`D` キーで `depthTest` を戻すと、**同じ512枚がただの暗い筒に戻り、芯が消える。**
手前の1枚が奥の511枚を隠した瞬間に光点が死ぬ——これが「芯は枚数でできていた」ことの実演で、
装置がこの2つのスイッチだけで出来ていることの証明でもある。

### 中身

- 開口512枚。頂点は**位置を持たない**。持つのは `(aTheta, aBand)` の2つだけで、
  どこに立つかは毎フレーム頂点シェーダが挽く（InstancedBufferGeometry・CPUは毎フレーム
  頂点を1つも触らない）
- 開口の輪郭は正N角形。`polyR(a,N) = cos(π/N) / cos(mod(a, 2π/N) − π/N)` を半径に掛けるだけ。
  16枚ごとの帯で 7角 → 5角 → 円 → 4角 → 6角 と替わり、`roll(c)` の螺旋と合わさって
  中心付近が星形にねじれる
- 帯を横切る方向はガウス `exp(-band²·2.6)`。硬い縁を作らない（遠くの開口は1画素を割るので、
  縁を立てるとモアレになる）
- 色は距離だけの関数: 手前が銀 `(0.66,0.74,0.96)` → 奥が金 `(1.00,0.82,0.55)`。
  金は1色しか使っていない（元サイトの「金は見出し1語のみ」を色数の制約として借りた）
- `1`/`2`/`3` で gain を 0.038 / 0.098 / 0.240 に。同じ幾何のまま、芯だけが点 → 玉 → 白熱に育つ

### 座標が2つあることについて（今日いちばん時間を取った所）

最初、芯の蛇行も半径も**カメラからの距離 u の関数**で書いた。ビルドも描画も通り、
絵はトンネルに見えた。**しかし くびれ（throat）が永久に近づかなかった。**
常にカメラの136手前に貼り付いたまま、開口だけがその形の中を滑っていく。

形はトンネルの持ち物であって、距離の関数ではない。書き直した結論:

- 形（`spine` / `radius` / `roll`）は **トンネル座標 c** の関数。時間が経っても変わらない
- 見え方（フェード・色温度）は **前方距離 u = mod(c − sc, PERIOD)** の関数
- カメラの現在地 `sc = mod(t·speed, PERIOD)`。横ずれは `spine(c) − spine(sc)` の差で取る
  ＝カメラは管の中心線に乗って運ばれる（本来は接線に合わせて首も振るべきで、
  今日は `exp(-u/190)` で遠くの横ずれを寝かせる代用にした。覚え書き）

これで1周 399.4 の輪の中に くびれ（0.52 R）と 広間（1.38 R）が1つずつ在り、
飛んでいると近づいて、通り抜ける。

## 何を捨てたか

- 実績サムネイル（元サイトで唯一色を持っている場所）とその大判グリッド
- 会社概要・フッター・スクロール尺（元は FV → 会社概要 → フッターの3セクション）
- 元サイトの巨大な一語そのもの（借りたのは「1スクリーン＝1枚のKV／巨大な一語＋読み値」
  という切り取り方だけで、語は `APERTURE` に差し替えた）
- CSSの重なりで空間を作るという実装手段（そこは借りず、同じ結論を面の数え上げで出した）
- 落とし影・環境光・法線・トーンマップ以外のポストプロセス。1つも無い

## つまずき

1. **くびれが近づかない**（上記）。ビルドは通り、絵もそれらしく、**動かして初めて分かる種類の間違い**だった
2. **粒子オーバーレイが空カンバス判定を殺した。** 地に DOM の粒子を敷いたので、canvas が
   1画素も描けていなくても PNG が 400KB 出る。実際に一度、真っ黒のフレームが
   `SHOT_MIN=75KB` を悠々と通過した。実描画は 1.4〜1.6MB なので閾値を **700KB** に貼り直した。
   → 教訓: **バイト閾値は canvas 以外の高周波成分を足した日には必ず貼り直す。**
   撮った1枚を必ず目で見るルールが無ければ、今日は真っ黒の preview を公開していた
3. 最初の gain（0.021）では枚数が足りず、トンネルがほぼ見えなかった。枚数 384→512 /
   間隔 0.92→0.78 に詰め、gain を4倍にして初めて「数え上げが絵になる」密度に届いた
4. `D` モードの初版は手前の開口が画面を灰色で埋め尽くして明るすぎた。`vFade` を
   opaque 側にも掛けて、近づく面が黒に沈むようにした
