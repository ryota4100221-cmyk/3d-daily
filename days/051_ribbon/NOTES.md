## 分解した装置 — ロール露光（roll exposure）

帯を見て「形が複雑だ」と思うのは、たぶん間違っている。帯が持っているのは2つしかない。

```
  P(s)   曲線
  φ(s)   その曲線に沿ったロール角
```

幅 w は最後まで**一定**である。それでも明るい所と真っ黒な所ができるのは、φ が回るからで、
形は一切変わっていない。これが今日の装置。画面右下の `EDGE-ON 21/500` は
「500点のうち何点が今この瞬間ちょうど真横を向いているか」で、**形が固定されたまま
この数字だけが動く**のがロール露光そのものである。

装置は3つの部品でできている。

1. **回転最小フレーム（RMF・二重反射法）** — `rig.js`
   Frenet フレームは変曲点で法線が飛ぶので、帯にすると継ぎ目でねじれる。
   Wang et al. (2008) の二重反射で参照ベクトルを運ぶと、1サンプルあたり内積6回で飛ばずに済む。

2. **ホロノミー（今日いちばん面白かった数）** — 画面表示 `HOLONOMY 52.2°`
   閉じた曲線の上で RMF を一周させると、**同じ場所に戻ってきたのに参照ベクトルが
   52.2° ずれている。** 曲線の形だけで決まる量で、こちらが選べるものではない。
   これを弧長に比例して引き算して均すと R(0) = R(L) になり、そこではじめて

   > **turns が整数なら帯は閉じ、半整数ならメビウスになる**

   が正確に成り立つ（`M` キーがそれ）。均さないでいると、3回転を指定したのに
   継ぎ目に 52.2° のねじれが1本残る。「ちゃんと閉じない」の正体はほぼこれ。

3. **ねじれた帯の法線** — `Scene.jsx` の頂点シェーダ
   X(s,v) = P(s) + v·u(s) を微分すると N = normalize(up − v·φ′·T)。
   幅の端ほど法線が**接線方向へ倒れる**。ねじれの強い区間で帯がサテンらしく光るのは
   この項のおかげで、抜くと平らな紙になる。

照明は3つしか使っていない：表と裏でアルベドを 0.985 / 0.300 に分ける（ねじれるたびに
入れ替わる）、Kajiya-Kay の異方性ハイライトを接線方向にだけ伸ばす、そして
**真横を向いて面積がゼロになった所にだけ縁の polyline を1本足す**。
3つ目は「暗くして消す」のではなく「面積を失って消える」を描くための保険で、
`smoothstep(0.02, 0.26, |N·V|)` の外側でしか出てこない。

## つまずいた所（明日の自分へ）

- **`npm run build` は通るのに preview の DOM が初期値のまま焼き付く。**
  Day 050 の NOTES が同型の事故を書いていて、対策として
  `--run-all-compositor-stages-before-draw` が shot.mjs に入っていた。**足りない。**
  今日も `ROLL φ 0°` `EDGE-ON 0/500` が2回焼き付いた。`--dump-dom` で見ると DOM は
  正しく更新されているので、**canvas だけが最新で DOM のレイヤが最初のラスタのまま**という
  状態が起きている。React の state を捨てて `textContent` を直に書いても直らなかった。
  効いたのは**数字のほうを時間に依らなくする**ことで、ロールを回し続けるのをやめ、
  φ を指数で目標値へ落ち着かせて ±6° 呼吸するだけにし、その落ち着いた先の値を
  `useLayoutEffect` で最初のペイント前に入れた。**絵と数字が食い違わない形に作り替えるのが
  唯一の確実な直し方**で、フラグを足すのは対症療法だった。
- **縁の polyline は面とまったく同じ深度に来る。** 押さないと真横区間がステップル状に
  ちらつく（1回目の実描画で左上に出た）。`polygonOffset` で面を 1.2 押して消えた。
- **黒い絵は PNG が軽い。** 空カンバス判定の閾値 110KB は白地の日の数字で、今日は
  実描画でも 36KB に落ちる撮り方があった（`virtual-time-budget` 11900/13500 で空、
  16000 で 921KB）。閾値を 75KB に下げ、地に ±0.006 linear のディザを乗せた。
  ディザが無いと**実描画と空カンバスがバイト数で区別できなくなる**。
