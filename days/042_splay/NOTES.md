# Day 042 — Loop 15 · 光源の足跡が円でない「Splay」（anisotropic filtering / ripmap）★★★★★

## 狙い

Day 041 の NOTES が最上位に置いた宿題を、書いたとおりの理由で回収した：

> **異方性フィルタ（ripmap か複数タップ）**。今日の唯一の実測上の後退——色相差が
> 半分になったこと——はここに閉じている。ローブの光源平面への射影は一般に楕円で、
> 正方形の box ピラミッドはそれを外接円で近似している。

分離積分近似が訊いている質問は1つだけである——**このローブは窓のどれだけを平均する
のか**。Day 041 はそれに**数を1つ**で答えた。数1つで書ける集合は**円板**しかない。
実際にローブが平均する集合は、自分の角度的な広がりを光源平面に引き戻した**楕円**で、
その理由はこの絵の全ピクセルに2つとも存在している：

- **変換**：M が光源を伸ばす。斜入射の GGX ローブは視線接方向に長く、直交方向に
  狭い——LTC の `Minv` が非一様なのは、まさにそれを表すためにある。
- **splay（開き）**：窓は誰に対しても正対していない。斜めに見た平面は傾き方向に
  短縮されるので、円錐の断面は楕円になる。石を斜めに切り落として内側へ広げた窓の
  reveal（splay）が今日の題名で、幾何としてはこれそのもの。

だから `d`（スカラ）が **2×2 のヤコビアン**になり、正方ピラミッドが **ripmap** に
なった。

## 新しく入れた技法

### 1. フットプリントをヤコビアンで測る（`ltc.js`）

光源平面をテクスチャ自身の座標 (u, v) で張り、方向を微分する：

```
X(u,v) = p1 + u V1 + v V2          着色点から見た点
dω     = P⊥ dX / r                 P⊥ = I - ωωᵗ,  r = |X|
```

これは (du, dv) から ω での接平面への線形写像 J で、**フットプリントの全部**である。
2つの列は V1, V2 の視線直交成分を r で割ったもの——斜めに見た窓の短縮も、M が光源に
したことも、両方この中にいる。

M の後のローブは余弦ローブで、残っているパラメータは角半径 δ ひとつ。半径 δ の円板の
逆像は楕円 J⁻¹(disc) で、ripmap が索引にする**軸平行境界箱**の半幅は J⁻¹ の行ノルム：

```
fu = δ · |col1(J)| / |det J|      fv = δ · |col0(J)| / |det J|
```

（adj の行は J の列を回したものなので、逆行列は作らない。）

**平面が正対・M が等方スケールに退化させると、両方とも δ·N·dist/√area になる**
——Day 041 の式そのもので、δ = K/N = 0.5。**定数は変わっていない。向きを持った。**
`?k=` はそのまま効くので、Day 041 の NOTES の比較はこのビルドでも全部再現できる。

### 2. ripmap を1枚のアトラスに（`glass.js`）

セル (m, n) は横 2^m・縦 2^n で平均した窓。幅 256,128,…,1 の和が 2N-1 なので、
ripmap は **2N×2N に過不足なく敷き詰まる**：

```
列 m の x 原点 = 2N - 2N/2^m,  幅 = N >> m       （行 n も同様）
```

81枚のテクスチャでも 2D array でもなく1枚にしたのは整頓のためではなく**フェッチの
ため**：全ての消費者が**隣接4セルを読んで lerp する**ので、セルはレベル対の算術で
アドレスできる必要がある。アトラスならそれが madd 2回。代償は、ハードウェア
バイリニアがセルの終わりを知らないこと——だから `ripCell` は uv を**半テクセル内側に
詰める**（パディングだと 25% 大きくなる）。

構築は分離 box 2回だけで、これが ripmap が現実的である理由でもある。2×1 box は
その軸上で平均を厳密に保存するので、**アトラス全体が両軸同時に平均保存**になる。
今日これに2重に依存している：「セル (m,n) を読む」が「2^m×2^n で平均する」を意味する
根拠であり、露出が動かない根拠（セル (8,8) は画像全体の平均1テクセル＝構成上の白）
でもある。メモリは mip 連鎖の4倍（Σ4^-m の2乗＝きっちり4）で、RGBA16F 2 MB。

### 3. 消えたもの：**mip 連鎖は ripmap の対角**

セル (m, m) は mip レベル m とテクセル単位で同一。だから

- 空と塵は今も (uGlassSoft, uGlassSoft) を1タップで読む。**昨日と同じ32×32の同じ
  テクセルで、同じ値段。ボリュームは今日1ミリも動いていない——注意深さではなく構成に
  よって。** 影のタップにローブはなく、したがって楕円もない。**異方性は「見る側」の
  性質である。**
- `?aniso=0` は近似ではなく**同じメモリを読む**。
- アトラスに mipmap は無いので**全ての読みがレベル0**になり、レベル対はアドレスに
  なった。結果として GLSL ES 1.00 の2つのシェーダが頼っていた「base level が 0 なら
  bias はレベルと同じ」という**偶然が、どこでも荷重を負わなくなった**。

## 測ってわかったこと（今日の本題は、実はこちら）

### 昨日の後退の原因は、フィルタではなかった

Day 041 は色相差が 0.203 → 0.088 に落ちたことを「等方な箱が方立をまたいで平均する
から」と診断した。**その診断は間違いだった。** 今日それを両側から確かめた。

**(a) 異方性にしても動かない。** フットプリントを楕円にして同じ箱を測ると：

| | 反射・左 R/B | 反射・右 R/B | 差 |
|---|---|---|---|
| `?pass=8` Day 040 の6定数 | 0.917 | 1.102 | 0.185 |
| Day 041 のカルトン・等方（`?aniso=0`） | 0.983 | 1.064 | **0.081** |
| Day 041 のカルトン・異方（今日） | 0.984 | 1.062 | **0.078** |

**0.003。** フィルタの形は、この量に対して何もしていない。

**(b) 算術が全部説明する。** Day 040 の定数は**ペインの上に**あった。Day 041 の色相場
は開口全体に描かれていて、**ペインはその端まで 57% しか行っていない**（cx/half =
0.0657/0.115 = 0.571）。つまり場は石しかない所で ±0.21 に達し、ガラスのある所では
±0.12 しか出していなかった。予測される彩度コントラストの低下は
ln(1.273)/ln(1.678) = **0.47**、実測は 0.43。**後退の全量。フィルタは一切関与しない。**

だから `cartoon()` の勾配を `u / PANE_U` に直した（`PANE_U` は WINDOW から読む——
1つのファイルに書いた数が別のファイルに書いた数と食い違ったのが原因なので、
書き写さない）。直したあと：

| | 反射・左 | 反射・右 | 差 | Day 040 比 |
|---|---|---|---|---|
| `?pass=8` Day 040 の6定数 | 0.917 | 1.102 | 0.185 | — |
| 今日（補正カルトン） | 0.939 | 1.084 | **0.145** | 78% |
| `?pass=14` 灰ガラス基準 | 1.039 | 1.031 | -0.008 | — |

42% → **78%**。残りの差は連続な場をフットプリントで平均している分で、これは
テクスチャ化した時点で払うことに決めた代価そのもの。

**教訓**：測定は正しかった（0.203 → 0.088 は実在した）。**原因の帰属が間違っていた。**
そして間違った帰属を1日抱えたまま「その原因を直す」機構を作りに行った。作った機構は
それ自身の理由で正しいが、**それを検証したことが、昨日の説明を反証した。**

### レンダは今日の問いに答えられない

異方性の効果をコンポジットで測ろうとして失敗した。同じ URL の4回のキャプチャが
1.81 / 1.83 / 2.02 / 2.07 MB で返ってくる——virtual-time バジェットが同じでも TAA が
何フレーム蓄積したかが違う。これは輝度 sd で10レベル分に相当し、効果の1桁上。
**最も静かな等方フレームは、最も騒がしい異方フレームより全ての統計で良く見えた**
（フィルタと無関係な理由で）。`SHOT_BUDGET` を足しても解決しない（決定的でない）。

だから測定を GPU から降ろした。`scripts/aniso-error.mjs` は同じ算術を CPU で回し、
**シェーダが払えない ground truth**——実際の楕円上での level 0 の平均、4096タップ——
に対して3つの規則を採点する。相対 RMS 誤差、%：

```
  anisotropy   major axis    ripmap   Day 041   circumscribed     n
     <1.5x       <15 deg      4.14      4.17            4.10    198
     <1.5x     15-30 deg      3.96      4.01            4.05    197
     <1.5x       >30 deg      4.22      4.29            3.99    190
    1.5-3x       <15 deg      4.55      5.48            5.86    329
    1.5-3x     15-30 deg      4.28      4.82            5.37    336
    1.5-3x       >30 deg      4.60      5.04            5.18    336
       >3x       <15 deg      5.53      7.34            9.95    474
       >3x     15-30 deg      5.87      6.95            8.30    465
       >3x       >30 deg      6.87      7.20            8.35    475

  all                 5.26      6.03            7.11   3000
```

読み方が3つある。

1. **等方（<1.5x）では3つとも一致する**（4.1%）。しなければ実装が壊れている。
   これが表の校正になっている。
2. **異方が強くなるほど ripmap が勝つ。** >3x・軸に近い所で 5.53% 対 7.34% 対 9.95%。
   Day 041 のスカラは楕円の2半軸の**幾何平均**——これは推測ではなく、
   `d = dist/√area` を同じヤコビアンに通すと `1/√det J` になり、それが幾何平均に
   厳密に等しい——なので、長軸方向で**フィルタ不足**（エイリアス側）に、短軸方向で
   平均しすぎに、両方同時に外している。外接円は正当だが常にぼかしすぎ。
   **ripmap は幾何平均の解像度を、外接円の安全性つきで返す。**
3. **45度で ripmap の優位は崩れる。** >3x の中で、軸から <15度なら 25% 改善、
   >30度なら 5% 改善。ripmap は2軸で索引されるので、斜めの楕円は軸平行境界箱で
   囲むしかなく、両軸とも最大 √2 大きい。**これは ripmap 自身の限界で、隠さずに
   binning して印字している。**

床の 4% は箱と楕円の形の食い違い＋セル間バイリニアで、どんな ripmap でも取れない。

## つまずき（記録用）

**`?aniso=0` を最初「2レベルの max」で書いた。** それは外接円で、GPU が mip に対して
選ぶものであって **Day 041 ではない**。この誤りは有害な形で「良く」見えた——A/B が
劇的で、近い漆板が薔薇を1つ失って見えたので、そのまま UI コピーに書いた。
Day 041 の実際のスカラに直したら差はほぼ消えた。**比較モードは「前のビルド」でなければ
ならず、「公平な等方フィルタ」ではない。** 見出しのコピーも書き直した（レンダの中に
無いことを画面に書いていたので）。

**GLSL のバッククォート lint が、6日連続で、仕事をした。** 今朝は2件（シェーダ内
コメントの `` `lobe` ``）。5日目に初めてビルドを落として教えてくれた仕組みが、6日目も
落とした。

**footprint 可視化（`?pass=15`）は白飛びしているのではない。** 画面の大半が本当に
レベル8を読んでいる。粗い面では Minv が多角形を縮めるのでテクセル当たりの
フットプリントが大きくなり、ピラミッドの頂上＝白になる。黒は `direct()` が
早期リターンした所（地平線の裏か完全遮蔽）。読み取るのは**明度ではなく色相**：
赤 = 窓の幅方向のレベル、青 = 高さ方向、緑 = 平均なので、**灰色が等方**で、
灰色でない全てのピクセルが今日と昨日の違う所。近い漆板は褐色に出る。
