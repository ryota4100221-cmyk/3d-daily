# Day 043 — Loop 16 · 斜めの楕円「Rake」（major-axis taps / texram over a ripmap）★★★★★

## 狙い

Day 042 の NOTES が最上位に置いた宿題を、書いたとおりの理由で回収した：

> **斜めの楕円（EWA か長軸方向の複数タップ）**。今日の表が示した唯一の穴で、
> \>3x・45度で改善が 5% しか出ない。ripmap の上に長軸方向2〜4タップを載せるのが
> 素直な直し方で、コストは 4フェッチ→8〜16フェッチ。

ripmap が索引にできるのは「横に 2^m・縦に 2^n 平均した窓」であって、**どこを**では
ない。だから長軸が斜めに走る楕円は軸平行境界箱で囲むしかなく、箱は両軸とも最大 √2
大きい。フェッチはローブが一度も見ていない菱形の窓を平均する。

直し方は「1回のフェッチに楕円を全部背負わせるのをやめる」こと。楕円を長軸に直交する
n枚のスラブに切り、スラブ k を**それ自身の部分楕円**（半軸 (A/n, B)）としてスラブの
中心で ripmap から読み、n個の答えを**そのスラブが占める楕円の面積**で重み付ける。
Schilling の *texram*（長軸に沿ってプローブ・フットプリントは短軸で決める）を、mip
連鎖ではなく **ripmap の上で**やったもの——なのでプローブ自身も丸くなくてよい。

## 新しく入れた技法

### 1. フットプリントを固有値問題として解く（`ltc.js`）

Day 042 は J から境界箱へ直行していた（J⁻¹ の行ノルム、2行、固有値なし）。箱で足りて
いたのは ripmap が箱でしか索引できないから。**今日のタップは長軸に沿って歩くので、
箱には長軸が無い**——楕円を作らないといけない。

```
Q = JᵀJ                    半径 δ の円板の逆像は { x : xᵀQx ≤ δ² }
半軸 = δ / √(Qの固有値)      小さい固有値 → 長軸
```

「J が最も伸ばさない方向が、逆像が最も伸びる方向」。対称2×2なので固有値は二次方程式、
固有ベクトルは Q − λI の1行。**行は2本とも取って長い方を使う**——第1行は円形
フットプリントで、第2行は長軸が u に正確に沿うときに消える。どちらも床が1枚ある絵では
稀ではないし、ゼロベクトルの normalize は NaN で、TAA が4フレームで全画面に広げる。

**これは昨日と違うフットプリントではなく、同じものの違う記述である。**下で作った楕円
の境界箱は、ランダムな J 4000本に対して Day 042 の行ノルムと **6e-9 %** で一致する
（`scripts/aniso-error.mjs` 冒頭の reduction check）。ここがズレていたら今日の n=1 は
昨日のビルドではなく、以下の比較は全部無意味になる。

### 2. 長軸に沿った n タップ（`ltc.js` / `footprint.js`）

部分楕円は**合同**（同じ A/n・同じ B・同じ角度）なので、

- **n個のタップは1組のレベル対を共有する。** ripmap は今も軸平行の仕事をしていて、
  タップが買っているのは**向きだけ**——ripmap に索引が無い部分だけ。
- **タイルする。** 中心 (A − A/n)(2k−(n−1))/(n−1) に半長 A/n を足すとちょうど ±A に
  届く。隙間も重なりも無い。
- **n = 1 は Day 042。** 中心0・半長A＝楕円全体の境界箱。`?tap=1` は昨日の近似では
  なく昨日**そのもの**で、`?aniso=0` が Day 041 そのものなのと同じ理屈・同じアトラス。

重みは**調整していない**。単位円板の x より左の面積は (x√(1−x²) + asin x)/π なので、
スラブ k の重みはそれを2つ引いた差。n だけの定数で、構成上1に和する。

残差は「楕円のスラブは楕円ではない」こと——最外スラブを覆う部分楕円は横に ±B まで
届くが、そこの本当の弦はもっと短い。面積重みがその大半を払い戻す。**主張ではなく
採点した**（下の knobs 表、flat 重みとの比較）。

### 3. 道具

- `scripts/tap-diff.mjs` — 2枚のキャプチャの輝度差を分布と地図で出す。下記の本題。
- `scripts/png.mjs` に `readPng` を移した（`measure.mjs` から）。PNGを開く2つ目の
  手書き inflate は、2つが「PNGとは何か」で食い違い始める道。Day 042 が writer で
  同じ理由の同じ移動をしている。
- `src/footprint.js` — タップ規則の**数**（予算・本数規則・スラブ重み）を1ファイルに。
  シェーダとハーネスが同じ定数を import する。Day 042 が1日失った原因が
  「1つのファイルに書いた数が別のファイルに書いた数と食い違った」ことなので。
- `?pass=16` — タップ数（赤）・異方比（緑）・**長軸の斜めさ**（青）。青が今日で、
  昨日には言えなかった唯一のチャンネル。黒＝丸いローブ、赤シアン＝軸に沿って伸びた
  ローブ（昨日で正しかった）、白＝伸びていて斜め（今日の土俵）。漆板の曲がった縁が白。

## 測ってわかったこと

### 楕円に対する誤差（決定的・CPU）

ground truth はレベル0を実際の楕円上で 4096 タップ平均したもの。相対 RMS 誤差、%：

```
  anisotropy   major axis      taps    ripmap   Day 041   circumscribed    n
     <1.5x       <15 deg      4.14      4.14      4.17            4.10    198
     <1.5x     15-30 deg      3.96      3.96      4.01            4.05    197
     <1.5x       >30 deg      4.22      4.22      4.29            3.99    190
    1.5-3x       <15 deg      4.38      4.55      5.48            5.86    329
    1.5-3x     15-30 deg      4.06      4.28      4.82            5.37    336
    1.5-3x       >30 deg      4.16      4.60      5.04            5.18    336
       >3x       <15 deg      5.06      5.53      7.34            9.95    474
       >3x     15-30 deg      5.14      5.87      6.95            8.30    465
       >3x       >30 deg      5.79      6.87      7.20            8.35    475

  all                     4.76      5.26      6.03            7.11   3000
```

読み方が3つある。

1. **`<1.5x` の3行で taps と ripmap が桁まで同一**（4.14 / 3.96 / 4.22）。異方性が
   丸め閾値未満なら n=1 が選ばれ、n=1 は Day 042 なので、**一致しなければ実装が壊れて
   いる**。これが表の校正になっている（昨日は等方の3ルール一致がその役をしていた）。
2. **狙った穴が埋まった。** Day 042 が「ripmap 自身の限界」と書いて印字した
   `>3x`・`>30deg` が 6.87 → **5.79**。昨日そこで Day 041 に対して 5% しか勝てなかった
   のが、今日は昨日に対して 16% 勝つ。
3. **床は 4.1% で動かない。** 箱と楕円の形の食い違い＋セル間バイリニアで、どんな
   ripmap でも取れない。**床の上の超過分**で見ると 3.29 → 2.42（二乗差）、**26%減**。

### 3つのつまみ、同じフットプリントで採点

```
                       RMS %   mean taps
  n<=4 area round      4.76        2.76     ← 採用
  n<=4 flat round      4.85        2.76
  n<=4 area ceil       4.74        3.14
  n<=2 area round      4.93        1.80
  n<=8 area round      4.76        3.35
  n<=16 area round     4.76        3.35
```

- **面積重み > flat**（4.76 対 4.85）。同じフェッチ数で、asin 1つ分。
- **予算4で頭打ち。** 8 も 16 も 4.76 のまま、平均タップだけ 2.76 → 3.35 に増える。
  4 は慣習ではなく測定値。
- **ceil は round より 0.02 良く、タップを 14% 多く使う。** 比 1.4 の楕円は既に床の
  中にいるので、2枚目のフェッチはほぼ丸いローブ全部に課金して何も買わない。round。

### レンダは今日の変化を「採点」できない——今日はそれを対照実験で示した

Day 042 は「同じURLの4回のキャプチャが 1.81/1.83/2.02/2.07 MB で返る」ことから
測定を GPU から降ろした。今日は同じ主張を、`tap-diff.mjs` で数として置いた。
`?pass=2`（積分だけ・ボリュームもモートも無し）を固定 `SHOT_BUDGET` で撮って：

| | mean \|dL\| | ≥1 levelの画素 | ≥32 | 隣接相関 |
|---|---|---|---|---|
| **tap=4 対 tap=1**（今日の差） | 0.377 | 7.21% | 0.126% | **0.578** |
| **同じビルドを2回**（床） | 0.530 | 10.31% | 0.169% | **0.281** |

**大きさでは、今日の変化はこのフレームの再現性より小さい。** 同じビルドを2回撮った
差の方が大きい。ここまでは昨日の結論の再確認で、今日はそれが**より強く**成り立つ
（今日の改善 5.26→4.76 は昨日の 6.03→5.26 より小さい）。

**しかし場所では分かれる。** 差分画像の隣接画素相関は 0.578 対 0.281 ——今日の差は
**絵**で、床は**斑点**。`diff-taps.png` には近い漆板の上に**鉛桟の菱形格子がそのまま
描かれている**（`diff-noise.png` は半影のスペックル）。時間ノイズは画素間で無相関、
フットプリントの変化は「窓の絵、またはその一部」だから、**同じ大きさの2つの差を、
大きさ以外で見分けられる**。

これが昨日の「レンダは答えられない」の正しい精度だと思う：**順位は付けられないが、
場所は言える。** そして順位はCPUの方に決定的な答えがある。

## つまずき（記録用）

**`step` という変数名を書いた。** GLSL の組み込み関数名で、シャドウイング自体は合法
なので何も言われない。`along` に直した。今日のシェーダ変更で唯一「動くが読めない」
になりかけた行。

**GLSL のバッククォート lint は今朝は仕事をしなかった。** 7日連続で初めて。書いた
コメントの中で `Q - lambda I` のような数式をバッククォートで囲みたくなる場面が2回
あって、両方とも書く前に思いとどまった——**lint が5日かけて習慣を作った方の効き方**。

**`?pass=16` の色は下流のグレードを通っている。** Day 042 の `?pass=15` と同じ但し書き
で、読み取るのは明度ではなくチャンネルの比。今日は3チャンネルとも意味が違うので、
UI ではなくこの NOTES に凡例を置いた。
