# Day 041 — Loop 14 · 光源に絵がある「Grisaille」（textured area light / filtered pyramid）★★★★★

## 狙い

Day 040 の NOTES が最上位に書いた宿題を、書いたとおりの理由で回収した：

> **窓を1枚の画像にする（textured LTC）**。今日の色は「ペインごとに区分定数」
> ——Day 039 のマスクとまったく同じ解像度の制限を、今度は放射輝度側で背負って
> いる。（…）**Day 039 の「ペインの細分割」と今日の「色」は、実は同じ1つの機能で
> 両方消える**。

6つの数字では窓は塗れない。塗れるまでペインを分割すると、`ltc.js` では1枚あたり
辺4本、`shadow.js` では1枚あたり影の推定1回ぶん増える——**二重に払えない**。

Heitz の §5（*Real-Time Polygonal-Light Shading with LTCs*, 2016）はどちらの予算も
触らずに答える。ポリゴン集合はそのまま、**放射輝度をフィルタ済みピラミッド付きの
テクスチャにして、ローブが光源をどれだけ覆うかから決めたレベルで1回だけ読む**。

```
result = ltcClip(Σ w_i e_i)  ×  L̄(uv, lod)
         ^ Day 038-040 のまま    ^ 今日。1フェッチ、窓に何が描いてあろうと1回
```

**ピラミッドが全部**である。平均保存の box ピラミッドのレベル m は「2^m テクセル幅の
フットプリントで光源を平均した値」そのものなので、レベルを選ぶことは
「窓のどれだけを平均するか」を選ぶことと**同じ**。分離積分近似が訊いている質問は
それしかない。粗い面はピラミッドの頂上を読んで白を得る。roughness 0.05 の漆は
4レベルほど下を読んで鉛桟とバラ窓を得る。同じフェッチ、同じコスト。

## 新しく入れた技法

### 1. テクスチャ化された面積光源（`glass.js` + `ltc.js`）

画像は**窓のバウンディング矩形全体**に描かれる——石のある帯も含めて。これは1秒ほど
間違って見えて、実は二重計上しない唯一の配置：**トレーサリーはポリゴンが担っている**
（6枚のペインが形状因子の定義域で、石はそこに入っていない）ので、テクスチャ側でも
方立を黒くしたら石が2回暗くする。だから画像はガラス職人の言うカルトン——**鉛桟を
貫いて連続に描いた下絵**——であり、連続な場のミップは黒い帯をガラス側に滲ませない。

結果として Day 039 と Day 040 の2つの限界が**1つの機構で、別々に**答えられる：
*形状*はペイン解像度のまま、*色*はテクセル解像度（256×256、追加コストなし）。

### 2. 論文からの2つの逸脱

- **読む点**：論文は着色点を光源平面に**直交射影**して読む。この実装は
  **LTC ベクトル自身の向き**——ローブを光源に制限したときの平均方向で、辺の和が
  Day 038 からずっと計算しては捨てていたもの——で平面を突く。`normalize` 1回の
  コストで、構成上つねに光源の凸包の中に落ちる。直交射影はグレージング角で窓の外へ
  出ていき、clamp が面ひとつぶん画像の隅に貼り付く。
- **ピラミッドの底**：3倍ではなく2倍なので、レベルは log3 ではなく素の log2。
  論文の `log(2048*d)/log(3)` は、2048幅の画像に対する base-3 ピラミッドで書いた
  同じ式である。

### 3. 誰も設計していない副産物

`f` は**可視性で重み付けされた**辺の和なので、梁が窓の一部を食うと `f` の向きが
「まだ見えている側」へ寄り、フェッチがそれについていく。**部分的に遮られた窓の色が
変わるのは、まだ見える部分が絵の別の場所だから**。ローブへフェッチを向けた副作用として
落ちてきた。

### 4. 空気には「レベル3」を渡す（`shadow.js`）

タップは着地点の色を**そこで引く**。座標はもう手元にある（返そうとしていたオフセット
そのもの）。ただし level 0 では読まない：froxel は2タップ、塵は1タップしかない。
13度の開口に対して位相関数はほぼ定数なので、空気が欲しいのは*可視部分の平均*であり、
各タップをあらかじめ小さなフットプリントで平均しておくのは**同じ量の、分散が数分の1の
推定量**になる。2タップ × level 3 で 128 テクセルぶんの窓を見ていることになる。
サンプル予算が面の百分の一しかない唯一の場所での、意図的なバイアス・分散交換。

### 5. `scripts/glass-preview.mjs` — 光源そのものを見る

最初のバラ窓は**見えなかった**。窓の中心に描いたからで、この窓の中心は方立と中段
トランサムの交差——**石**であり、石は積分に入っていない。漆板の反射から光源テクスチャの
良し悪しを判断するのは近似を2つ同時に見ることで、画像を1枚 PNG に吐けば1秒で気づいた。
だから吐くようにした（ペインの外を28%に落として、石の位置も重ねて描く）。

`scripts/shot.mjs`（閾値リトライ付きヘッドレス）と `scripts/measure.mjs`
（PNG デコード＋矩形の平均と R/B）も日フォルダに入れた。RUN.md の品質チェックを
毎朝手で組み直していたので、今日から道具になっている。

## つまずき（記録用）

**鉛桟が光っていた。** `smoothstep(0.5, 0.42, max(f1,f2))` は「セルの内側で1」に
なる。`max(f1,f2)` はセル中心で0・境界で0.5なので、桟は**高い側**である。向きが逆で、
明るい格子と暗いガラスの窓——つまり**漁網**——を描いていた。1枚目のプレビュー PNG で
即座に分かった。

**`uGlassK` は測って決めた。** URL に `?k=` を出したので誰でも再現できる。
`?k=700` では手前の漆板の反射が石の十字だけになる——絵が消える。roughness 0.05 の
漆はほぼ鏡なので、これは明らかに平均しすぎ。`?k=96` では2つのバラ窓もその同心円も
クォリーの間の鉛桟も解像し、しかも奥の板（0.125）は依然として窓全体を1色に閉じる
——**板2枚が主張しているのはまさにそれ**。128 はその内側に収まる。論文自身の
2048（＝画像幅と同じ）はこの定数を N とする選択で、こちらはその半分。**論文も
ここも、定数の入った経験則である**ことは正直に書いておく。擁護できる理由は、
1つの数で、単調で、両方の破綻が1枚のレンダで目に見えることによる。

**色相の差は半分になった。** 灰ガラス基準（`?pass=14`）の R/B = 1.05 に対して：

| | 反射・左 | 反射・右 | 差 |
|---|---|---|---|
| `?pass=8` Day 040 の6定数 | 0.924 | 1.127 | 0.203 |
| 今日（テクスチャ, k=256） | 0.988 | 1.086 | 0.098 |
| 今日（テクスチャ, k=128・採用） | 0.999 | 1.087 | 0.088 |

**これは後退であり、後退の理由が今日の近似の正体**である。Day 040 の `Lbar` は
ペインを `max(e_i.z, 0)` ——**ローブ自身の重み**——で加重していた。フィルタ済み
フェッチの重みは光源平面上の**等方な箱**で、ローブの射影が実際に持つ異方性を持って
いない。だから方立をまたいで平均してしまう。得たものは*ペイン内部*の解像度、
失ったものは*ペイン間*の重み付けの正確さ。ripmap か複数タップの異方性フィルタが
正しい直し方で、それは今日の範囲外（下記）。

**`?pass=11`（トレーサリーを外す）が別物になった。** 昨日はここで石と一緒に
ガラスも失われた——1枚のペインは6色を持てないから。今日は**失われない**。絵は
テクスチャにあり、テクスチャはペインが何枚あるかを一度も知らなかった。だから
`?pass=11` は石の十字が1本もない**完全な鉛ガラス窓**になる。作品の中で
「形状と放射輝度が分離した」ことを一番はっきり言っているのはこのモードで、
`palette.js` と `Pipeline.jsx` に残っていた「石を取るとガラスも失う」という
コメントは今日から嘘なので直した。

**GLSL のバッククォート lint が、また、仕事をした。** Day 040 が `npm run prebuild` に
入れた検査に**5件**引っかかった（全部シェーダ内コメントの `` `変数名` ``）。5日連続で
踏んでいる癖だが、5日目にして初めて**ビルドが落ちて教えてくれた**。仕組みは警告に勝つ。

**ペイン加重平均は白から 1.5〜2.6% ずれる。** ピンで留めたのは*画像全体*の平均で、
理由は box の縮小が平均を厳密に保存するから——level 0 で留めれば 1×1 の頂上まで
留まり、広いローブは構成上ちょうど白を読む。Day 040 が留めていたペイン加重平均は
実測 (0.985, 0.980, 0.974)。この積分が実際に読むのはフィルタ済みテクセルであって
ペインの和ではないので、留めるべきはこちらだと判断した。

## 構図・トーン

- 光は1つ。フィル無し・アンビエント無し・環境マップ無し（Day 036 から継続）。
- **主役は板2枚の対比で、それが今日はピラミッドそのものになっている**。手前
  （roughness 0.050）は鉛桟と2つのバラ窓を解像し、奥（0.125）は同じ絵を1色に
  平均する。**何もそれを選んでいない。ジオメトリが選んでいる。**
- 絵は3つの尺度に分けて描いた。連続な色相場（左が古く琥珀、右が冷たく緑、敷居に
  向かって濃く）／クォリーの菱格子（1度ほど、1枚ずつ窯の当たりが違う）／
  グリザイユ（中段の各ライトにバラ窓、頭部と敷居に帯、枠の内側に縁取り）。
  粗いほど深いレベルまで生き残るので、**面の粗さが「どの層まで読めるか」を決める**。
- Day 031 からの規則——作品が中心に据えている物体（窓・絞り板・梁・ガラス・
  今日の絵）は一度も映らない——を継続。

## 次に試したいこと

- **異方性フィルタ（ripmap か複数タップ）**。今日の唯一の実測上の後退——色相差が
  半分になったこと——はここに閉じている。ローブの光源平面への射影は一般に楕円で、
  正方形の box ピラミッドはそれを外接円で近似している。ripmap（2^m × 2^n の
  長方形ピラミッド）なら軸に沿った異方性は取れる。**Day 040 の `Lbar` が持っていた
  ローブ重みを、解像度を手放さずに取り戻す**のがこの宿題の正確な形。
- **可視性も画像にする（textured shadow / マスクのテクセル化）**。今日ガラスに
  対してやったことを、Day 039 のマスクに対してやる。マスクは今もペイン単位の
  6つの数で、それは「影の境界がペインの内側に落ちたら、そのペインは一様に暗くなる」
  という Day 039 の但し書きそのもの。同じピラミッドの上に載るはず。
- **`Lbar` の重みを clip の後に**（Day 040 からの持ち越し。今日の分割では `Lbar` が
  テクスチャに移ったので、宿題は「フェッチの点を地平線クリップ後のローブ重心にする」
  という形に変わった）。
- **ガラスに吸収を（波長依存の透過）**。今のカルトンは「そういう放射輝度」を直に
  与えているが、本当は白い空を**透過**した結果。厚みと吸収係数で書けば、絵は
  そのままでフィジカルな根拠が付く。
- **froxel への影のキャッシュ**（Day 036 からの持ち越し）。
