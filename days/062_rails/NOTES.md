## 分解した装置：二本の軌条（The Two Rails）

エスカレータの踏段は「水平に保たれている」のではない。**水平になってしまう**。

踏段は前後2本の車軸を持ち、前軸（main roller）と後軸（trailing roller）が
**別々の軌条**を走る。踏面は2つの車軸を結ぶ剛体なので、その角度は
`atan2(A − B)` そのもの。つまり角度は入力ではなく出力になる。

`src/rig.js` には「踏面を水平にする」式が一行も無い。書いてあるのはこれだけ：

```
p(s) = −D · sin( clamp(θ(s), −α, α) )      ← 2本の軌条の垂直距離
```

`θ(s)` は軌条Aの傾きで、`D` は軸距。あとは毎サンプル

```
|A(s) − B(u)| = D  を u について解く（粗いスキャン → 26回の二分法）
```

を通すだけ。傾斜角 θ の直線で、Aから垂直距離 p 離れた平行線B上に距離Dの点を取ると、
2点を結ぶ線は必ず水平になる：

```
A(t) − B(u) = (t−u)(cosθ, sinθ) − p(sinθ, −cosθ)
y成分 = 0  ⇔  t−u = −p·cotθ   →   |A−B| = |p|/sinθ = D   ⇔   p = −D·sinθ
```

だから **乗降口（θ=0）では p=0、つまり2本の軌条が1本に合流する**。
合流すれば前後の車軸が同じ高さに並び、踏段は畳まれて平らな板の列になる。
画面で「踏段が生まれる／畳まれる」あの動きは、演出ではなく
**軌条が別れていく／合流していく過程そのもの**。

書いていないのに出てきたもの（数値は node で実測）：

```
s= 3.00  乗降口   踏面 +0.00°   p = 0.000
s= 4.00  遷移     踏面 +5.58°   p = −0.206
s= 4.50  遷移     踏面 +10.27°  p = −0.368   ← ここが「踏段が生まれる」区間
s= 5.50〜17.00 傾斜 踏面 ±0.00°  p = −0.400（= D·sin30°）  13m ぜんぶ 0.00°
s=18.00  遷移     踏面 −8.00°   p = −0.141
s=19.50  乗降口   踏面 +0.00°   p = 0.000
```

**傾斜12.6mのあいだ、踏面角は一度も 0.00° を外れない。** 一度も書いていないのに。
画面右下の TREAD ANGLE がそれで、傾斜を走っているあいだは +0.00° に貼り付き、
遷移に入った瞬間だけ振れる。プレビューの数字（−8.51° / RAIL GAP −5.33 cm）は
「いま踏段が畳まれている最中」を指している。

**今日ゆいいつの有彩色（#E61E1E）は軌条Bに置いた。** 装置は2本目の軌条なので、
色をそこに1つだけ置けば、絵の中で説明が要らなくなる。

## 中身

- 軌条は閉ループを作ってから**上行路だけ切り出して**描く（返り路と端部スプロケットは
  実機ではトラスの中にあって見えない。切ったら画面に「2本の線と、その上の踏段」しか残らなくなった）
- 踏段は59個の InstancedMesh 2本（本体＋車輪4個）。姿勢は毎フレーム `poseAt(s)` から。
  踏面・19本のクリート・蹴上げ（ExtrudeGeometry の円弧板）・側ブラケットを1つに merge
- 蹴上げ400mm／踏面奥行693mm は軸距800mmと傾斜30°から出る（`D·sinα` / `D·cosα`）。
  実機の 400/230mm と同じ比になるので、寸法表を引き写した所は1つも無い
- 光源は3灯＋RoomEnvironment を PMREM に通した環境のみ。影は落としていない
  （白い虚空に浮かせる＝技術図の register にする）
- カメラは踏段と同じ `poseAt()` から位置を出し、鎖と同じ 0.50 m/s で軌条をなぞる。
  三脚は一度も立てていない

## つまずき

1. **`mergeGeometries` が黙って null を返す。** `ExtrudeGeometry` は非indexed、
   `BoxGeometry` は indexed。混ぜたまま渡すと `null` が返り、`<instancedMesh>` が
   `Cannot read properties of null (reading 'id')` で落ちる。**画面に出るのは
   「DOMオーバーレイだけが残った白」で、空カンバスと完全に同じ見た目**。
   全部 `.toNonIndexed()` してから渡して解決。エラーは console にしか出ない
   （Day 061 の normalMatrix と同じ形の事故。ビルドは通る）
2. **軌条Bの符号を逆に置いていた。** 最初 `p = +D·sinθ` で書いたら傾斜部の踏面角が
   きれいに **60.00°**（= 90°−α）になった。傾斜を後ろへDだけ**水平に**戻ると
   鎖の線より上に出る（鎖は下がるが踏面は下がらない）ので、後軸の軌条は鎖の**上**。
   数字が 0 でなく 60 という「意味のある別の角度」だったので、式ではなく符号だと分かった
3. **車輪が踏段の内側にあると装置が1ミリも見えない。** 最初 Z_A=0.455（踏段幅1.02の内側）に
   置いたら、横から見ても踏段の側面に隠れて2本の軌条が画面に出てこない。
   0.63 / 0.55 に出して（実機も車輪は踏段の外）、ブラケットを伸ばした。
   **「装置を作った」と「装置が見えている」は別のこと**
4. **空カンバス判定の閾値はまた貼り直し**（Day 042・057・059・060 に続き5度目）。
   地がほぼ白一色なので実描画 122KB／空カンバス 49KB。`SHOT_MIN=95` に置いた。
   今日も救ってくれたのは画面の数字で、TREAD ANGLE が `---` のまま焼き付いた1枚が
   最初に出た（`useFrame` が一度も回っていない＝落ちている、とその場で分かる）
5. **DOMと3Dの衝突を、版面のほうを動かして避けた。** 機械は画面の対角（左下→右上）に乗るので、
   空くのは左上と右下。見出しを左上、計器と脚注を右下に移して、文字と3Dが一度も重ならない
   構図にした（最初は脚注が全幅で、踏段の上に載っていた）
