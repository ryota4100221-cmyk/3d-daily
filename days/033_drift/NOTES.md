# Day 033 — Loop 06 · 空気が二度散る「Drift」（multiple scattering / froxel diffusion）★★★★★

## 狙い

Day 031 で初めて**面と面のあいだ**を描き、Day 032 でその積分を**グリッドに焼いて資産に**した。
どちらも「単散乱」だった。つまり **光源 → 媒質 → 目、一度きり**。

単散乱の絵には必ず同じ癖が出る：

- シャフトの**肩が硬い**（境界の外側で急に何もなくなる）
- シャフトの**横の空気が、光の無い部屋の空気とまったく同じ暗さ**

後者が本質で、単散乱の式には**エネルギーを横に運ぶ項が一つも無い**。
ビームの中で散った光は目に届くか消えるかのどちらかで、**隣の空気に渡ることが構造的にできない**。

今日はそれを渡す。Day 032 の NOTES に自分で書いた宿題「多重散乱」の回収。

## 新しく入れた技法

### 1. 多重散乱 ＝ **1フレーム1回のヤコビ反復**（今日の主題）

本当の多重散乱は大域解（全セルの輝度が全セルに依存する）。だが式の形はこう：

```
L(x) = S(x) + albedo · <L>(x の近傍)
```

これは **ヤコビ反復そのもの**。1回回せば2バウンス、n回で n+1 バウンス。

そして **froxel グリッドは既に「前フレームの自分」を持っている** —— Day 032 が
テンポラルフィルタのために置いた、まったく別目的のバッファとして。

→ **毎フレーム1反復だけ回して、残りはフレームに任せる。**
数十フレーム静止すれば、グリッドは**等比級数の和**を保持している。

新しいパスは1本も増えていない。既存の injection パスに**タップが4つ増えただけ**：

```glsl
vec3 gather(vec3 p) {
  for (int i = 0; i < 4; i++) {
    vec3 q = p + (uMsBasis * TETRA[i]) * uMsRadius;   // 世界空間で±1.15m
    vec4 nb; if (!prevAt(q, nb)) continue;            // 前フレームの体積を引く
    sum += min(nb.rgb / max(nb.a, uMsFloor), vec3(uMsClamp));
  }
  return sum / n;
}
...
S += uMsAlbedo * sig * gather(p);   // 位相関数なし＝等方
```

設計上の判断が4つある：

- **rate ÷ sigma で「輝度」に戻してから渡す。** セルが持っているのは
  `σ_s·L`（単位長あたりの散乱率）で、これは**その場所の空気の濃さが混ざった量**。
  隣に渡せるのは場所に依存しない `L` の方なので、一度 σ で割り、
  受け取る側で**自分の σ を掛け直す**。これで「濃い所は光り、薄い所は光らない」が自動で出る。
- **位相関数を掛けない。** 2バウンス目の光子は**どちらから来たかを忘れている**。
  それが「拡散」という語の物理的な中身で、ここに前方ローブを付けたら嘘になる。
- **カーネルは正四面体4方向を、毎フレーム黄金角で回す。**
  4タップは本来スカスカだが、回転させてテンポラルに積めば十数フレームで球面を覆う。
  Day 028 の「カーネルを回して時間で積む」を、スクリーン空間の円盤ではなく
  **3D世界空間の球**に対して適用した形。
- **カーネル半径はメートルで定義した**（セル数ではない）。
  カメラが動いてもフロクセルの厚みが変わっても、拡散長は部屋の性質として一定。

**発散しないことの保証は albedo だけ。** 級数は `1/(1-albedo)` に収束するので、
0.50 なら「一次散乱のおよそ2倍で必ず止まる」。ここを 1.0 に近付けると白飛びして帰ってこない。

そして**一番きれいだった発見**：Day 032 のテンポラルフィルタを**1行も変えずに**済んだ。
`mix(cur, hist, fb)` の不動点は `cur == hist` の状態であり、`cur` は
「直接光 + albedo·近傍(hist)」なので、**落ち着く先は拡散方程式の解そのもの**。
`uFeedback` は収束の**速さ**しか決めない。ノイズ除去のために置いた仕組みが、
そのままソルバとして動いた。

比較は作品内に入れてある（`?pass=9` / キー `9` = Single scatter）。
シャフトの肩が硬くなり、横の空気が落ち、部屋が一段暗くなる。

### 2. **体積を読む** ソフトパーティクル、7,000枚

Day 032 のモートは 130 個で、毎フレーム JS が 130 個の行列を書いていた。
7,000 にはそのやり方では行けない。理由は行列の本数ではなく、**行列が表現として間違っている**から。
モートの位置は**時刻の閉じた関数**で、バッファに焼くとその情報を捨てたうえに転送費を払うことになる。

→ 位置を頂点シェーダに置き、per-instance のシードは **vec4 一つだけ**。
CPU は毎フレーム `uTime` を1個書く以外に何もしない。

そして関数にした瞬間、行列版には不可能だったものが**タダで**手に入る：
**前フレームの位置 = 同じ関数の `t - dt`**。Day 030 は「前フレームの姿勢」を知るために
per-instance の mat4 属性を丸ごと1枚増やしたが、解析的な粒子は**ただ知っている**。

3つの読み取りが、粒子を「手前に貼られた点」ではなく「部屋の中の粒」にする：

| 読む先 | 何が起きるか |
|---|---|
| ライト深度マップ（空気と同じ・同じバイアス・同じ世界単位） | 影のレーンに入った粒は**消える**。シャフトの中だけがきらめく |
| G-buffer 深度 | 床に近付いた粒が最後の60cmで**溶ける**（ソフトパーティクル）。硬い円が床に押されない |
| froxel 体積（**粒自身の深度**で1フェッチ） | 奥の粒は8mの霧の向こうに正しく沈む。Day 032 のガラスと同じ主張 |

加算合成なのは手抜きではなく、**光学的に薄い散乱体は `σ·L·T` を足すだけで遮蔽しない**から。
副作用として**順序非依存**になり、7,000枚の重なりにソートが1回も要らない。

### 3. 透明レイヤを **TAA の外**に出した

Day 032 のガラスは TAA の**手前**にあり、速度を書かないので背景の速度で再投影されていた。
NOTES にも「嘘だが分散クリップが吸っている」と書いた。7,000粒ではその嘘が通らない。

だが**速度バッファでは直せない**。1ピクセル1速度であり、透明レイヤは1つの面ではないから。
→ 直すのではなく、**渡さない**。モートは専用ターゲットに描いて TAA の**後**に加算する。
resolve が見るのは、速度を書いた不透明面だけになった。

代わりのブレは粒自身が持つ：**速度方向にビルボードを伸ばす**（velocity-stretched billboard）。
ゲザーも履歴も要らない per-particle モーションブラー。
なお露光時間は 1/30 秒ではなく 0.42 秒にしてある。実測どおりの 1/30 では
0.3 m/s の塵の軌跡は**0.05ピクセル**で、正しいが見えない。静止画を「流れている場」として
読ませるための、意図的な長時間露光。

## つまずき（記録用）

**7,000枚のビルボードが1ピクセルも出ないまま、ドローコールだけ成功していた。**
`gl.info.render` は 1 call / 14,000 triangles と報告するのに、ターゲットは真っ黒。
フラグメントを定数色に置き換えても、キャンバスに直描きしても黒。

原因は**ビュー空間で組んだビルボードの基底が左手系だった**こと：

```glsl
vec2 a = normalize(dv);       // 進行方向
vec2 b = vec2(-a.y, a.x);     // ← これだと det < 0 で三角形が鏡像になる
```

鏡像 = ワインディング反転 = `side: FrontSide` で**全部カリング**。
シェーダのバグでもユニフォームのバグでもなく、**幾何の向きのバグ**が
「描画は成功しているのに何も出ない」という一番読みにくい形で出た。
`b = vec2(a.y, -a.x)` に直し、保険として `side: DoubleSide` も入れた（コメント付きで）。

教訓：**ビュー空間でクアッドを自作したら、基底の行列式の符号を必ず疑う。**
ビルボードの向きは毎粒子で変わるので、「たまたま合っている」ことがある。

もう一つ：**この環境（SwiftShader）ではこのパイプラインが 1.8 秒/フレーム**しか出ず、
9秒待つ従来のヘッドレス撮影では **5フレーム**しか回っていなかった。
froxel の拡散は数十フレームで収束する仕組みなので、**撮れた絵が収束前の絵**になる。
撮影の待ち時間を 75 秒に延ばして初めて本来の画になった。
ビルド成功≠描画成功、に加えて **描画成功≠収束後の描画**。

## 次に試したいこと

- **froxel → 面 の放射照度。** 今日いちばん大きな穴。空気は自分が光っていることを知っているのに、
  そこに立っている柱はそれを受け取れない。セルの等方成分を面から引けば
  「霧に照らされた石膏」になるはずで、そうなれば代役のヘミスフィアを消せる。
- **拡散カーネルの多重解像度化。** 1.15m 固定は「近くの細かい滲み」と「部屋全体のかぶり」を
  同じ半径で扱っている。ミップ的に粗いレベルをもう1枚持てば、反復回数を増やさずに拡散長が伸びる。
- **albedo をスペクトルに。** 今は1つのスカラーなので、多重散乱しても色が変わらない。
  波長ごとに albedo を変えれば、深い霧が青く（あるいは暖かく）転ぶ本物の挙動が出る。
- **モートが体積に注入し返す。** 今は体積を読むだけ。粒の密度を injection 側の σ に足せば、
  「粒が濃い所は霧も濃い」が閉じる。
- **Day 032 からの持ち越し**：ライト深度マップのカスケード、ブルーノイズ・ジッタ、
  霧の実在レンジに合わせた froxel near/far の自動追従。
