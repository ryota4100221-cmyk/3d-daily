## 何を再現し、何を捨てたか

キー演出は**FVの全画面動画**——つまりサイトの動きではなく、その動画が映しているもの。
1つに絞った：**刷毛目が消えていく状態**。

それが 幾何／シェーダ／カメラ／時間／入力 のどれでできているかを言葉にすると、
**時間**だった。正確には「時間そのもの」ではなく **時間の尺度**。
形でも光でもカメラでもなく、何がいつ消えるかの順番だけの話。

**捨てたもの**：サイト全体・会社概要・実績グリッド・組格子のディスプレイ（鯨館）・
工房の写真・動画・Neue Haas Grotesk の実ファイル（外部フォントは403。
72px/100%/-7.5%/W400 と 14px/171% という**組みの数値だけ**借りた）。

## 分解した装置 — 四乗（the fourth power）

書いたのは3つだけ。

1. 薄膜の潤滑方程式を平均膜厚まわりで線形化したときの、モードごとの時定数
   ```
   ∂h/∂t = −(γ/3μ) ∇·( h³ ∇∇²h )
   h = h̄ + ε cos(k·x) を入れて ε の1次だけ残すと
   ∂ε/∂t = −(γ h̄³ / 3μ) k⁴ ε
   τ(λ) = 3μ λ⁴ / (16π⁴ γ h̄³)
   ```
2. 見本板6枚。刷毛目の間隔だけが1段ごとに**ちょうど2倍**（2 / 4 / 8 / 16 / 32 / 64 mm）。
   塗料も膜厚も初期勾配も塗った時刻も全部同じ。
3. 表示は「映り込んだ縞板」1枚。

これだけで、板の上に「もう平ら／まだ波」の境目が出る。
**「消える」「閾値」「臨界波長」と書いた行は1つも無い。** 式に臨界値は存在しない
（どの間隔の稜線も、常に減衰し続けている）。境目を作っているのは**指数の4**だけ。

材料定数はニトロセルロースラッカーの実用域：μ = 0.05 Pa·s、γ = 0.028 N/m、
h̄ = 60 µm（1回塗りのウェット膜厚）。ここから C = 3μ/16π⁴γh̄³ = **1.591×10¹⁰**、
τ = C·λ⁴。

```
λ        τ         残っている勾配 s/s₀
                   t₀=65.2s   16t₀=17.4min   256t₀=4.6h
 2 mm    0.25 s     0.009       0.000          0.000
 4 mm     4.1 s     0.114       0.012          0.000
 8 mm    65.2 s     0.407       0.089          0.010
16 mm   17.4 min    0.924       0.373          0.074
32 mm     4.6 h     0.996       0.937          0.458
64 mm     3.1 d     1.000       0.996          0.934
```

**16倍待って、境目はちょうど1段しか動かない。**（画面の上下2段がこれ）
半分まで落ちる λ を連続で解くと λ½ = (t / C·ln2)^{1/4}：

```
t = 65.2 s   → λ½ =  8.77 mm
t = 17.4 min → λ½ = 17.54 mm     時間 ×16 で λ½ ×2
t =  4.6 h   → λ½ = 35.07 mm
t =  3.1 d   → λ½ = 70.14 mm     時間 ×4096 で λ½ ×8
```

だから **鏡面は「待って得るもの」ではない**。木地の 64 mm のうねりを
レベリングだけで 1/100 まで落とすには **14.2 日**かかる。ラッカーは20分で乾く。
残るのは「長い波長を最初から作らない」——研ぎと重ね塗り、つまり
サイトのナビにある「保有技術」と「木工塗装ライブラリー」のほうだけになる。
指数が4であることが、この会社の商売の理由そのものになっている。

## 読み取っているのは光ではなく映り込み

**高さは1ピクセルも見えない。** 稜線の高さは 0.22〜7.1 µm、板は 260 mm。
幾何として押し出したところで画面上では完全にゼロ。見えているのは**傾き**で、
傾きを可視化しているのは**縞板の映り込み**のほう（反射光線のずれ = 2 × 勾配、
それが 8.5 m 先の縞板の上で位置のずれに変わる）。塗装現場で塗膜のうねりを
見るときにやっているのと同じ道具立てで、**ライトオブジェクトは0個**。

- 板は平面ジオメトリ1枚（分割 1×1）。稜線は全部フラグメントシェーダの中の
  法線の傾きで、頂点は1つも動いていない。
- モードは9本（毛筋7＋刷毛の返し2）。波数を**ベクトル**で持ち、向きに ±24° の
  散らばりを入れてある。
- 時間に依るのは**振幅だけ**。位相も波数も一度も動かさない——
  レベリングはモードを混ぜないし、動かしもしない。落とすだけ。
- 1画素より細い稜線は `fade` で落とす。エイリアス除けではなく
  「カメラが積分してしまうものを足さない」ため。

## つまずき

1. **1枚目：両端の板が真っ黒。** 板を弧に並べて1枚ずつカメラへ向けたら、
   外側の板の反射光線が縞板の外（hit.x = 6.05 m > 4.2 m）へ飛んでいた。
   原因は向きの符号——x>0 の板は `rotation.y = −θ` で**カメラのほうへ**
   向けなければならないのに `+θ` にしていて、板は外を向いていた。
   反射は「板が少し傾いたら消える」ので、光源を置く描画と違ってすぐには気づかない。
2. **弧をやめた。** 符号を直すと今度は、板ごとに映り込んだ縞が傾いて（外側ほど強く）
   「曲がっているのは勾配のせい」という読みが壊れた。全部同じ平面に置いた。
   ※**正投影にすれば入射角まで揃うが、それはできない**——平らな鏡を平行光線で
   見ると板の全面が縞板の**1点だけ**を映して真っ平らな一色になる。縞が要るので
   透視のまま。代わりに入射角が列で 0〜12.7° ばらつく（縞の間隔がわずかに変わる）。
3. **縞が「曲がる」のではなく「太さが変わる」だけだった。** 場を y だけの関数
   （完全に平行な溝）で書いていたので dh/dy が x に依らず、横縞は上下に伸び縮み
   するだけで曲がらなかった。波数をベクトルにして向きを ±24° ばらしたら曲がった。
   実際の刷毛目も平行ではない。
4. **振幅は3回調整した。** 0.25° → 0.08° → 0.04°。0.25° だと反射のずれが縞の
   半周期を超えて縞が折り返し、板がバーコードになる。現実のうねりの勾配も
   0.01〜0.1° 程度で、大きいほうが嘘だった。
5. **目盛りを `useFrame` から外した。** 板の位置を投影してDOMのラベルを置いていたら、
   headless で「板は出たが目盛りが出ない」フレームが撮れた。カメラは固定なので、
   同じカメラをJS側で1つ立てて射影するだけにした（描画ループに依存しない）。
6. **空カンバス判定の閾値はまた貼り直し。** 今日は地が白でDOMに文字が多いので、
   **空カンバスでも 69KB 出る**（3回とも寸分違わず 69KB）。実描画は 111〜127KB。
   前日の 200KB のままだと実描画を弾き、60KB だと空を通す。95KB に置いた。
   なお空になる頻度は budget=18000 でも3回に2回で、梯子を6段に増やした。
