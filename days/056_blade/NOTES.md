## 何を再現したか

**羽根の集合でできたリング、1つだけ。** それを何でできているかに分解すると **幾何** だった
（シェーダでもカメラでも入力でもない。頂点の位置の決め方そのもの）。

羽根1枚は、リング上の角度 θ に生えた1本の円弧である。仰角 ψ で立ち上がり、
そこから曲率 bend で反り、自分の軸まわりに twist だけねじれ、根元と先端で幅が 0 になる。
方向を σ について積分すると閉じた形になるので、頂点シェーダの中で1枚が数行で書ける：

```glsl
ia = (sin(psi + bend*s) - sin(psi)) / bend;   // 外向き成分
ib = (cos(psi) - cos(psi + bend*s)) / bend;   // 上向き成分
axis = C(θ) + len * (ia * Nr + ib * Up);
```

ここまでは「羽根が288本ある」だけで、まだリングではない。

## 分解した装置：羽根の位相（blade phase）

作りながら気づいたのは、**この形のどこにも「リング」が書かれていない**ということだった。
`C(θ)` は最初から円周上にあるが、根元の点は細すぎて円には見えない。目に見えているのは
羽根の面のほうで、面が環に見えるのは、隣り合う羽根の ψ・bend・twist・len が
**ほぼ同じ値だから**でしかない。

そこで係数を1本のスカラー `coh` で2つの法則のあいだに置いた：

| coh | ψ / bend / twist / len | 見え方 |
|---|---|---|
| 1 | θ の滑らかな関数（288枚が同じ法則に従う） | 面が閉じて環になる |
| 0 | 羽根ごとの乱数 | 根元は円周上のままなのに、環が消えて鱗片の散乱になる |

**根元は coh に依存しない。** 位置は1ミリも動かないまま、環が現れたり消えたりする。
これが今日の装置で、名前を「羽根の位相」と付けた。

`coh` を定数にせず θ に沿って進む波にした：

```glsl
coh(θ) = smoothstep(-0.56, 0.56, cos(θ - seam))
```

`seam`（継ぎ目）が21秒で1周する。だから静止画1枚の中に、揃った側の層状の面と、
崩れた側の鱗片が同時に写る。画面右下の `SEAM θ ___°` がその継ぎ目の現在地。

## 今日踏んだ罠（次に同じ所で落ちないために）

- 🔴 **自前の fragment shader は three の色空間変換に乗らない。**
  `#include <colorspace_fragment>` を書き忘れると linear の値がそのまま sRGB のバッファへ行き、
  絵が丸ごと沈む。「暗すぎるから明るくしよう」と shader の係数をいじって30分溶かした。
  ビルドも描画も成功していて、ただ全部暗いので気づきにくい
- 🔴 **地を「見ている方向」で塗ると、広角では下端だけ落ち込む。** fov 58 だと画面下端の
  `d.y` が -0.8 まで行くので、実測の主色 #7A2ACC が画面のどこにも出てこなくなった。
  地は `gl_FragCoord.y / uRes.y` の素直な縦グラデーションに書き直した
- 🔴 **DOM の数字は setState にしない。** `SEAM θ ___°` を state にしたら headless の1枚で
  `000°` のまま焼き付いた（Day 050 と同じ）。virtual time の下では React の
  スケジューラが最後まで回りきらない。ref で `textContent` を直接書く
- ⚠️ **空カンバス判定の閾値は毎日貼り直す。** 今日は実描画 1.8〜1.9MB／空カンバス 172KB で、
  `SHOT_MIN=90` にしていたら空カンバスを1枚 preview として通していた（実際1回通した）。
  400KB に引き上げてから、リトライが正しく2周目に入るようになった
