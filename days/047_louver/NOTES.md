## 今日の新しいもの

### `scripts/vis-error.mjs` — 遮蔽物のある初めてのハーネス

ブロッカーは**光源 uv 上の半平面**である。これは簡略化ではなく厳密で、**まっすぐな
遮蔽エッジを1点から見たシルエットは、光源平面上で必ず直線になる**（点を通る直線の
平面への射影は直線）。1点から見た可視性は二値で、半影は積分の**後**に生まれるので、
硬い半平面がフレーム内の実物の可視関数そのものである。

参照は「**その点から見える部分の**窓」上の D 重み付き平均：

```
reference  =  ∫ L V D / ∫ V D      （6枚のペイン上、384×384、1022構成）
```

第1因子（質量）は参照自身の ∫VD に固定する。今日比べているのは**見えている窓の色**
であって LTC 和ではない（今日は LTC 和に1行も触っていない）。

## 作って、測って、載せなかったもの（4つ）

残り 5.48% に対して4つ機構を作り、**4つとも負けた**。全部ビルドに残してある（既定はオフ、
`?vfit=1` と `?pass=20`）。再現できない否定的結果はただの主張なので。

### (1) スラブごとの可視性プリマルチプライ — 5.48 → 5.85（負け）

昨日の開口マスクと**同じ算術**の続きに見えた。level 0 に `rgb=L·m, a=m` を置くと
`rgb/a` が「ガラスだけの平均」になる。ならタップごとに可視性 V を掛ければ
`(L·m·V, m·V)` が流れ、同じ1回の除算で「**見えているガラスだけの平均**」になる——
`glassFetch` の中で1乗算、シャドウマップ読みはゼロ増。

負けた理由は調整ではなく**算術**である：**平均タップ数は 1.31**。タップが1本のとき、
スカラーは色と被覆率の両方に掛かるので、除算で**完全に打ち消える**。スラブ重みは
定義上**スラブ間の差**しか表現できない。

（`?vfit=1` でオンになる。フレーム上での効果も測ってある：`?pass=2` を同一
`SHOT_BUDGET` で撮って `tap-diff` すると **1レベル以上動く画素は 0.74%**。Day 046 が
測った同一ビルド2回の**床が 6.16%** なので、**この機構はフレームのノイズ床より下**。）

### (2) 適合平面の等高線で核を切る（truncation, level set） — 5.48 → 5.75（負け）

動かすべきはタップの重みではなく**フェッチが読む領域**だ、というのが次の考え。
Day 044 は既に一度これをやっている（窓の縁：2つのガウシアンの積＝分散の逆数和）。
ブロッカーはガウシアンではなく**半平面**で、**半平面で切られたガウシアンの
モーメントにも閉形式がある**（Mills 比、exp 1回と erf 1回）：

```
α = (c − n·m)/s,   s² = nᵀΣn,   λ = φ(α)/(1−Φ(α))
m' = m + Σn λ/s
Σ' = Σ − (Σn)(Σn)ᵀ (λ² − αλ)/s²
```

平均はブロッカーから**離れる方向**へ滑り、分散は**エッジを横切る方向にだけ**縮む。
タップ1本でも効く（動いたのは楕円だから）。**エッジを平面の 0.5 等高線で取ると負ける。**

### (3) 同じ切断、エッジをモーメントから取る — 5.48 → 5.35（全体では勝ち、しかし配分が悪い）

(2) が負けた理由は閉形式で書ける。**ステップ関数を最小二乗で追うのはステップを探す
方法として偏っている**：共分散 C の標本と真のエッジ `n·x = c` に対して回帰係数は

```
k = C⁻¹ n σ φ(β),      β = (c − n·µ)/σ,   σ² = nᵀCn
```

なので (a) **エッジの法線は k ではなく C k の向き**（等方な標本のときだけ一致する。
この窓は縦横比 1.5）、(b) 平面が 0.5 を切るのは `h + βφ(β) = ½` の所で、**β=0 のときしか
エッジではない**。窓の1/6しか見えない点（β≈1）では、等高線は真のエッジより
**41% 暗い側**に置かれる。

そこでタップが最もよく推定する2統計から取る：向きは `C k`、オフセットは**平均可視率**
（マスク自身のスカラー。8本ではなく48本全部が支えている）。逆正規分布関数は要らない——
`|C k| = σφ(β)` が密度を、`h` が符号をくれる。

```
     可視率        Day 046   スラブ重み   等高線切断   モーメント切断   厳密エッジ切断   オラクル      n
     15% 未満        8.74       9.75        8.81         7.53          7.36        2.77     218
     15 - 45%        4.74       4.76        5.50         5.05          4.98        2.44     251
     45 - 75%        3.98       4.05        4.41         4.73          4.33        1.87     238
     75 - 95%        3.15       3.21        3.22         3.49          3.41        1.59     204
     95% 超          4.81       4.81        4.75         4.89          4.89        2.21     111

     全体            5.48       5.85        5.75         5.35          5.19        2.23    1022
```

**全体では 5.48 → 5.35 で勝っている。載せなかった理由は、その勝ちが全部
「15%未満」のビン（8.74→7.53）から来ていて、中間の2ビンでは負けているから**
（3.98→4.73）。理由も分かっている：Day 045 の面積規則は既に `ltcClip(f_V)`——
**可視質量**——で割っているので、切断は**同じ縮小を二重に適用している**。
遮蔽なしの質量から出発して切る形も試した：8.05%（もっと悪い）。
**「暗い所で良く半分見えている所で悪い」を既定にはできない。** 明日の候補に置く。

### (4) 平面を6枚のペインに解析的にクリップして vis_i を作る — 4.28 → 10.47（負け。ただし負けている場所が特定できた）

「タップは**線がどこにあるか**だけ決めて、各ペインが線のどちら側にどれだけあるかは
**幾何が厳密に**答える」——長方形を直線で切った面積は閉形式（Sutherland-Hodgman ＋
靴紐、凸四角形は5頂点まで）。8回のベルヌーイ試行を退役させられるはずだった。

推定量として採点する（同一構成を24通りのデコリレーション位相で振り、厳密なペイン
可視率と比較。これはバイアスではなく**フレームに実際に出るノイズ**の測定である）：

```
                                    RMS %     bias %
  8試行 / ペイン（現状）              4.28       0.00
  線を1本引いてクリップ（回帰の法線）  10.47      -0.03
  同上、法線を重心差から              5.18
  同上、法線が厳密                    3.39            （オフセットは3つとも h から）
```

**最後の行が今日いちばん惜しい数字である。** 厳密な法線を与えれば、線＋クリップは
8試行より **21% 良い**（3.39 対 4.28）。つまり**アイデアは勝っている**——負けているのは
**法線の推定**だけで、オフセットの方は問題ない（`h̄` は48本全部が支えている統計なので、
面積を合わせる二分法で置くと厳密法線でも推定法線でも同じだけ効く）。

法線の候補を2つ試して両方足りなかった：回帰勾配 `C k`（10.47。上の (3) で書いた
偏りが直接効く）と、**通ったタップの重心 − 遮られたタップの重心**（5.18。行列も
条件数も要らず全タップが1票ずつ投じる、素直な推定量）。48本の二値標本から
半平面の**向き**を出すのは、位置を出すよりずっと難しい——これは今日の収穫で、
明日の具体的な課題である。

## 誤差は結局どこにあるのか（明日の順番は、直感ではなく測定で決まった）

```
  3つ全部（オラクル）             2.23
```

**中心が単独で最大の項**である。今のフェッチ点は「ローブの平均方向の射線と平面の交点」
（Day 041 の選択）で、核の重心ではない。安く作れる中心も試した：

```
  ペイン質量の重心（vis_i·max(e_i.z,0) で6枚の中心を加重）   7.46   （大幅に悪い）
  その半分だけ寄せる                                        6.34
  窓の4辺で核を切断（今日の Mills 比を開口に適用）
     中心も形も                                             5.73
```

ガウシアン因子として扱う縮小）の**上に**同じ箱の切断を重ねているので、

——ただし Day 044 が「shift は 2.7 ポイント負ける、shrink だけ載せる」と書いたのと
**まったく同じ形の結果が、まったく違う導出から再現された**のは収穫である。

## つまずき（記録用）

**256構成では「引き分け」に見えた機構が、1024構成では勝っていた**（モーメント切断：
4.30→4.30 が 5.48→5.35 に）。ビンごとに符号が違う機構は、構成数が少ないと
**どのビンが多く引かれたか**を読んでしまう。今日のように「全体は勝ち・中間ビンは負け」と
分かって初めて、載せない判断ができる。**配分を見ずに全体だけ見ていたら載せていた。**

**`?pass=20` が最初は真っ黒だった。** 読み出しを `visAt`（＝スイッチ込みの重み）から
取っていたので、既定でオフにした瞬間に地図まで消えた。地図は**窓と点の性質**であって
スイッチの性質ではないので `visRaw` から取る（?pass=17 や 19 と同じ規則）。
**「機構を既定オフにする」と「その機構の地図を消す」は別の要求**で、1行で両方やっていた。

**ハーネスのブロッカーは必ず窓を切るように置いた**（オフセットを ±0.85·support に制限）。
外れる構成は今日が恒等になる構成で、混ぜると表は「規則の良さ」ではなく
「乱数が何回外したか」を報告する。
