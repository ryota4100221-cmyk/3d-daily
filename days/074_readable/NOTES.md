# Day 074 — The Only Angle That Reads

**再現元：読めない、GUNZE。（グンゼ130周年 特設サイト）**
https://www.gunze.co.jp/130th/

選定はスワイプファイルDB（`深掘り済み = true` 1,181行）から。製造・素材・建築・音楽系の
業種で絞った候補の中で、**サイトが自分の弱点を一つの主張にしている**のはこれだけだった
（「社名が読まれない」を 157px の極太コピーにして先頭に置いている）。SOURCES.md に
`gunze` は0件。※当該ドメインは WebFetch が EGRESS_BLOCKED で到達不可なので、DBの実測値
—— 地の92%が黒 #000000／青 #1100FF が15.8%／ティール #00C8B3・ピンク #FF2D55・
オレンジ #FF9500 がほぼ等量／文字は白／Dela Gothic One 157px の極太／章題は1文字ずつ
分かち書き —— だけを根拠に装置を立てた。

## 何を再現し、何を捨てたか

**再現したのは「読めない」を実際に決めている条件ひとつだけ。** サイト全体は作らない。
分解すると、これは **カメラ** でできていた（幾何でもシェーダでも時間でもない）。

捨てたもの：Movie / From CEO / History の年表、マーキー10本、Dela Gothic One と Modak
（外部フォントはこの環境では取れない。借りたのは「極太」と「分かち書き」という組み方の
ほうだけで、字形は矩形の和と斜めの帯で自分で書いた）、和文コピー、イラスト、祝祭のトーン。
残したのは実測の5色と、地が黒でほぼ埋まっているという比率。

## 分解した装置 — 読める一点（the only angle that reads）

1. 空間に原点 **E**（目の位置）を置く。
2. E から距離1の面の上に GUNZE の5文字を組み、内側を 5,517 点で標本する
   （G 1153 / U 1058 / N 1147 / Z 1006 / E 1153）。
3. 点 (u,v) ごとに **E からその点へ向かう直線を1本引く**。棒はその直線の上に、
   z深さ d から d+L まで置く（L = 4d）。

これだけ。E から見ると棒の全長が自分の視線と重なるので、**長さ 24〜168 の棒が
厚み 0 の点にしか映らない。** 字が読めるのは E に立っているときだけ。

カメラが E から b だけ横へ離れると、二つの量が勝手に出てくる。どちらも 1/d：

| | 式 | 意味 |
|---|---|---|
| 滑り Δu | `b(1/d − 1/d_aim)` | 文字どうしが離れ、語が横へ伸びる |
| 胴 s | `b·α/((1+α)d)`（α=4） | 1本の棒が線分に伸びる＝字が厚みを持つ |

5文字を 6 / 10 / 16 / 26 / 42 の深さに分けてあるので、**手前ほど大きく壊れる**。
撮った1枚（b = 0.439）の胴は画の太さ T に対して
**G 1.14 / U 0.69 / N 0.43 / Z 0.26 / E 0.16**。青い G だけが自分の画より厚い胴を持ち、
白い E はまだほぼ平ら。カーソルを端まで振った b = 1.9 では **4.94 / 2.97 / 1.85 / 1.14 / 0.71**。

副産物がひとつ。画面で5文字の太さを揃えるには半径を視線長に比例させるしかない（r = ρ·ℓ）。
つまり **同じ太さに見えている5文字は、世界の中では 1 : 1.67 : 2.67 : 4.33 : 7.00 の
大きさの差がある。** いちばん奥の白い E が、いちばん巨大。

## つまずき

1. **「読めなくなる」は起きなかった。** 装置を組む前に想定していたのは「E を外れると
   字が散らばって読めなくなる」だったが、実際には散らばらない。1文字の棒は全部おなじ
   深さに居るので視差が文字ぜんぶで揃っていて、**ばらけるかわりに字が厚みを持つ**
   ——ただの押し出しになり、押し出された字はふつうに読める。
   計器の見出しを `BREAKS AT`（壊れる基線）から `BODY s／T`（胴の厚み）に書き直した。
   壊れているのは字ではなく、**字が一枚の平面だったという事実**のほうだった。
   これは装置の失敗ではなく、装置が正しく動いた結果として出てきた事実なので、
   式は変えずに言い方のほうを合わせた。
2. **撮った1枚が撮るたびに変わった。** カメラの b を毎フレーム遅延フィルタで目標へ
   寄せていたので、headless が何フレーム回ったかで b が 1.5 にも 0.44 にもなった
   （1回目の実写が b=1.503）。カーソルが無いときは **時刻から直に b を決める**ように
   書き換えて止めた（Day 050 と同じ穴）。
3. **RUN.md が言う空カンバス誤診が実際に出た。** 同じビルド・budget=12000 で 30KB、
   budget=9000 で 198KB。実写は 190〜270KB／空カンバスは 30KB と6倍以上離れていたので
   `shot.mjs` の閾値を 120KB に置いた。最終の1枚は budget=20000 の3回目で撮れている
   （16000→29KB、18000→29KB、20000→196KB）。梯子は飾りではない。
4. **語が窓から出た。** 面の上の半幅 0.55 に対して画角の半幅を 0.615 で取っていたら、
   胴が伸びたぶんだけ G と E が両端で切れた。画角のほうを 0.74 に広げ、胴と滑りの
   最大値（b=B_HOLD で 0.10）を見込んで取り直した。

## 構成

- `src/rig.js` — 字形（矩形の和＋斜めの帯）、面の上の標本、深さと色、胴と滑りの式。
  三次元の姿勢は持たない。乱数は固定種（`0x47554e5a`）。
- `src/Scene.jsx` — 標本点を InstancedMesh の行列に直す（初期化で一度きり、以後1フレームも
  触らない）。棒の手前端から奥端へ落ちる明るさだけをシェーダが持つ。カメラの b と φ。
- `src/App.jsx` — 計器。3D は胴の厚みを一度も計算していないので、同じ式をDOM側で書き直して
  数字を出している。
- ライトオブジェクトは0個。`engine/` からのコピーも0件（この日の装置は射影だけでできている）。
