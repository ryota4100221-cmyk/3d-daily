# Day 029 — Loop 02 · 反射「Basin」（ループ＆深化 / 静かな水盤）★★★★★

## 狙い

Curriculum は #28 で1周した。29日目以降は「同じテーマを、より高い難易度の変奏で再訪する」フェーズ。
Day 028 の NOTES に自分で書いた「次に試したいこと」が4つ残っていた——
①AO履歴の**モーションベクタ・リプロジェクション** ②同じG-bufferからの**screen-space reflection**
③G-bufferの**MRT 1パス化** ④TAA。今日はこの①②③をまとめて回収する。

そのうえで「レンダラの機能」で終わらせないために、**題材そのものを反射に賭けた**。
水盤（basin）を1枚置き、ビューティパスではそれを**ほぼ真っ黒に塗る**。
画面で「水」に見えているものは1ピクセルも直接描かれていない——全部、スクリーン空間を
歩いて拾い集めた反射。水を"素材"ではなく"上に立っているものの写し"として実装した。

## 新しく入れた技法（前日までの自分から1段）

### 1. WebGL2 の MRT ＋ GLSL3（本プロジェクト初）

28日間、シェーダは全部 GLSL ES 1.00（`gl_FragColor` 1本）だった。今日初めて
`glslVersion: THREE.GLSL3` を使い、フラグメントシェーダから**2枚同時に書き出す**。

```glsl
layout(location = 0) out vec4 outNormalDepth;  // rgb=ビュー法線 / a=線形ビュー深度÷far
layout(location = 1) out vec4 outMotion;       // rg=スクリーン速度 / b=マテリアルID / a=1
```

three r169 は `new THREE.WebGLRenderTarget(w, h, { count: 2 })` で MRT に対応していて、
`rt.textures[0] / [1]` で個別に取れる。ハマりどころは three が GLSL3 のときだけ
`layout(location = 0) out highp vec4 pc_fragColor;` を**注入しない**こと（`WebGLProgram.js` を読んで確認）。
つまり location 0 は自分のものとして宣言してよい。逆に GLSL1 だと衝突する。

**Day 028 は法線パスとビューティで2回シーンを描いていた**。今日は G-buffer が1ドローで
法線・深度・速度・マテリアルIDの4種を吐くので、シーン走査は G-buffer とビューティの2回のまま、
中身の情報量だけが倍になった。

### 2. モーションベクタ（速度バッファ）— 「このピクセルは前フレームどこにいたか」

G-buffer の頂点シェーダに前フレームの `projection * viewMatrix` を uniform で渡し、
**同じワールド座標を「今のカメラ」と「前のカメラ」の両方で射影**して NDC の差を取る。

```glsl
vPrev = uPrevViewProj * world;    // 静物なのでワールド座標は前フレームと同一
vel   = (vCur.xy / vCur.w - vPrev.xy / vPrev.w) * 0.5;   // NDC差 → uv差
```

Day 028 のテンポラル蓄積は「カメラが止まっているほど澄む」＝**動くと履歴を捨てる**設計だった。
速度が分かると `prevUV = uv - velocity` で履歴を**追いかけられる**。デバッグ表示（キー4）で見ると、
奥の壁と手前の器で色が明確に分かれる——視差がそのまま速度差として出ている。

この方式が成立する条件は「ワールドが静止していること」。だから**シーンは意図的に完全な静物**にし、
動かすのはカメラだけにした。オブジェクトごとの前フレーム行列を持てば動体も扱えるが、
今日は「静かな水盤」という題材と噛み合うので、正確さを取って静止を選んだ（メモとして残す）。

### 3. スクリーンスペース反射（SSR）

水面ピクセルだけ：深度から**ビュー空間座標を再構成**（fov の tanHalf と aspect で射線を作る方式・
逆行列不要、Day 028 の SSAO と同じ流儀）→ 波のノーマルで反射ベクトルを作る →
**ビュー空間を48ステップ進みながら毎回 `uProj` でスクリーンへ射影**し、
「そこに実際に写っている深度」と比べる。手前にめり込んだ瞬間を捕まえたら、
直前ステップとの間を**2分探索6回**で詰める。stride は 1.11 倍ずつ伸ばして遠くほど粗く。

反射ベクトルは毎フレーム・毎ピクセル**狭いコーン内にジッタ**させている。1フレーム単体では
ただのノイズだが、2の履歴に積むと**グロッシー反射に収束する**。ノイズを時間で品質に変える構造。

### 4. 「外した光線」は空に当たっている

最初の実装はレイが画面外に出たら固定色にフェードさせていた。結果、水平線の上に
**冷たい灰色の帯**が横一文字に出た（空は琥珀色なのに、水だけ灰色を映す）。
直し方は、フォールバックを定数ではなく**空そのものの評価**にすること——
反射方向を背景プレーン（z = -26）と交差させ、その高さで背景と**同じグラデーション関数**を評価する。
そのために空のパレットとGLSLを `palette.js` に切り出し、**背景メッシュと反射パスが同じ1つの定義を共有**する。
水が「上にない空」を映すことが構造的に起きなくなった。

### 5. MSAA と G-buffer の食い違い（シルエットの点線）

ビューティは 4x MSAA、G-buffer は 1サンプル（解像すると深度と速度が平均されて壊れるので禁止）。
シルエット上ではビューティが「器と水の中間色」なのに、マテリアルIDは**どちらかに丸まる**。
そこへ反射を100%足すと、器のフチ全部に明るい点線が出た。
マスクを1ピクセル分フェザリング（十字5タップ平均）して両者の足並みを揃えた。

### 6. 旋盤（lathe）の器 ＋ 手描き equirect → PMREM 環境（Day 028 の資産を継承）
制御点10個のスプラインを回した回転体。今日の環境は「夕暮れの水面の上」を想定した別室：
広い天蓋光＋**水平線に乗る暖色の帯**。この帯が水盤の下半分を横断して映るので、意図して作ってある。

### 7. 作品自身がパイプラインを見せる（1–5キー / クリック）
Composite / Beauty / Normals / Motion / Reflection。特に **Motion** と **Reflection** は
今日の主張そのものなので切替に入れた。

## ハマった点（次の自分への申し送り）

- **three の GLSL3 は `pc_fragColor` を注入しない**。ドキュメントより `WebGLProgram.js` を読むのが速い。
  推測でMRTを書くと「location 0 が二重宣言」で黙って落ちる系のハマり方をする。
- **フォールバック色は定数にしない**。定数フェードは「そこだけ別の世界」を作る。今日の冷たい帯は
  完全にこれが原因で、直したら画が一段良くなった。反射の見た目の8割はミス時の処理で決まる。
- **1サンプルのバッファとMSAAのバッファを同じ画面で混ぜるとフチが必ず割れる**。どちらかに寄せるか、
  マスクを1px にじませるか。ビルドでもコンソールでも検出できない。
- 構図は実描画でしか分からない（Day 027 の教訓）。初回は**見出し "Basin." に器が突き刺さっていた**。
  カメラを 5.65 → 8.4 に引き、静物を右へ寄せ、左3分の1を水と文字に明け渡して解決。
- 最初の配色（明るい灰色の空）だと水が**コンクリートの床**に見えた。水は「暗いから水」ではなく
  **暗い空を映すから暗い**。空を夕暮れに落としたら、同じシェーダのまま一気に水になった。

## 次に試したいこと

- **オブジェクト単位の前フレーム行列**を持ち、動体でも速度が正しく出るようにする（＝静物の縛りを外す）。
- 反射面のための**リプロジェクションの正しさ**：鏡面はサーフェスの速度と映り込みの速度が違う。
  今は緩やかなドリフト前提でごまかしている。反射先の深度で速度を作り直せば直せるはず。
- 同じ G-buffer から **contact shadow**（Day 028 の SSAO と足せば画面空間の陰影が一式そろう）。
- 最終画像そのものへの **TAA**（速度バッファはもう出ているので、あとは履歴クランプだけ）。
- 屈折（水中）と反射の合成。今は水面下に何もないが、沈んだ部分が見えると水の厚みが出る。
