## 何を再現し、何を捨てたか

キー演出は1つに絞った。**「色を物に塗るのではなく、色そのものを面にしている」**こと。
白・コバルト青・緑の3色タイルが敷き詰められていて、それが背景ではなく画面の実体になっている。

- **残した**：3色のタイルで面を作ること。差し色のライム。極太コンデンスの欧文。余白と疎な情報密度。
- **捨てた**：サイト全体、劇画調のイラスト、選手、試合日程、スクロール尺、和文本文、フッターの黒反転、
  "Ignite Your Engine" の袋文字（画像化されていて読み取れない。組み方だけ借りた）。

そして、**イラストに描けないものを1つ足した**。
劇画は一瞬を描く。ボールが曲がるのは時間の中でしか起きないので、絵には入らない。
そこを装置にした。

分解すると **時間**（と、それを動かす面内の力）だった。幾何でもシェーダでもカメラでもない。

## 分解した装置：二十ヤードの穴 — the twenty-yard hole

### 1. 曲率に速度が残らない

回転軸を鉛直に取る（＝真上から見る）ので重力は面外に落ちて、面内に残るのは2つだけ。

```
マグヌス力  F_M = ½ ρ A C_L |v|²   （速度に直交）
抗力        F_D = ½ ρ A C_D |v|²   （速度と逆向き）
```

このとき軌跡の曲率は

```
dθ/ds = |a_⊥| / |v|² = (½ ρ A C_L |v|² / m) / |v|² = ρ A C_L / (2m) = 1/R
```

**|v| が約分で完全に消える。** 抗力は |v| を削るが、曲率の式に |v| はもう残っていない。
だから軌跡は厳密に円弧で、半径は

```
R = 2m / (ρ A C_L) = 2×0.43 / (1.225 × π×0.11² × 0.33) = 55.965 m
```

質量・空気密度・断面積・揚力係数しか入っていない。**蹴りの強さはどこにも入らない。**
`rig.js` には「曲げる」に当たる命令が一行も無く、書いてあるのは力を速度に足して RK4 で
積分することだけ。円弧はその帰結として出てくる。

数値で言うと（CPU float64・`node scripts/verify.mjs`）：

| v₀ | 飛翔時間 | 着弾 z | 基準（26 m/s）とのずれ |
|---|---|---|---|
| 16 m/s | 1.2835 s | 2.988059566291 m | 4.56e-10 m |
| 24 m/s | 0.8557 s | 2.988059566322 m | 2.94e-10 m |
| 36 m/s | 0.5704 s | 2.988059566978 m | 8.40e-10 m |

蹴り出しを **2.25 倍**振っても軌跡は **8.4e-10 m** しか動かない（残りは RK4 の打ち切り誤差）。
動いたのは飛翔時間だけで、こちらはきっちり 2.25 倍。**変わるのは「いつ」で、「どこ」ではない。**
抗力込みの積分と閉じた式 `z(x) = R(1−√(1−(x/R)²))` の差は最大 5.5e-10 m。

### 2. 離れがいちばん大きいのは、必ず弦の中点

弦を ξ 軸に取ると、弧からの離れは

```
d(ξ) = √(R² − ξ²) − √(R² − (C/2)²)      （ξ ∈ [−C/2, +C/2]）
```

ξ の**偶関数**なので、最大は厳密に ξ = 0 ＝ 弦の中点。近似ではない。
円弧が弦の垂直二等分線について対称、というそれだけのこと
（0.0091 mm 刻みで 200 万点なめても最大は ξ = 0.00e+0）。

### 3. 規則が置いた 9.144 m と、それがぶつかる距離

競技規則 第13条が壁に課しているのは「ボールから 9.144 m（10ヤード）」ひとつ。
これは弦の上の距離なので、壁の弦上位置は ξ_wall = 9.144 − C/2。

**C = 2 × 9.144 = 18.288 m のとき ξ_wall = 0.00e+0。**

| C (m) | 壁の離れ | 最大の離れ | 壁 ÷ 最大 | 壁で済んだ曲がり |
|---|---|---|---|---|
| 12 | 0.2342 m | 0.3226 m | 72.600% | 58.10% |
| 16 | 0.5630 m | 0.5747 m | 97.965% | 32.79% |
| **18.288** | **0.752068146556866 m** | **0.752068146556866 m** | **100.000%** | **25.17%** |
| 22 | 1.0609 m | 1.0917 m | 97.180% | 17.51% |
| 32 | 1.9144 m | 2.3359 m | 81.954% | 7.79% |

差は **0.00e+0 m**。壁は、ボールが自分の狙い線からいちばん逃げきっている、
ちょうどその一点に立たされる。**サッカー自身の数字（10ヤード）が、その穴の位置を決めている。**

### 4. 二十ヤードでだけ重なる二つ

弦の中点は蹴り出しから見て弧の中心角のちょうど半分の位置にある。だから

```
壁までに済んだ曲がり = (1 − cos(φ/2)) / (1 − cos φ) = 1/(2(1 + cos(φ/2)))
離れ ÷ 総曲がり幅 Y  = R(1 − cos(φ/2)) / (R(1 − cos φ)) = 同じ式
```

**「すでに曲がった量」と「それで買えた逃げ」が同じ数になる。**

```
済んだ曲がり     = 0.251691149351533
離れ / Y         = 0.251691149351534
1/(2(1+cos φ/2)) = 0.251691149351534    ずれ 1.28e-15
```

φ → 0（弱い曲がり）の極限はちょうど **1/4**。今日の φ = 18.807° では 25.169%。
放物線で近似したときの「壁で済むのは u² ＝ 25.00%」「離れの最大は Y/4 ＝ 25.00%」は、
この閉じた式の一次の影でしかない。厳密な値との差は C = 18.288 で **−0.294 pp**、
C = 32 まで伸ばしても **−0.373 pp** しか開かない（L/R が効く唯一の場所）。

キーパーが壁の位置で接線を引いて読むと着弾を 2.226 m と見積もり、Y の **25.51%** 足りない
（放物線の予言「残りの二乗」(1−u)² = 25.00%）。

## 面そのものを目盛りにする

再現元のタイルを、**その飛距離までに済んでいる曲がりの割合の網点**として敷いた。
列 i の色タイルの密度 ＝ その列の完了率。だから壁のあたりの床はほとんど白いままで、
いちばん奥だけが青と緑で埋まる。**画面に「ここで 25% です」と書いた文字は一つも無い。床が数えている。**

しきい値を乱数で切ると 14 個しかない列では二項分布のばらつき（σ ≦ 0.1336）が
そのまま密度の嘘になるので、**順位**で切った：列ごとに固定のハッシュで行を並べ替え、
上から `round(frac × NZ)` 個だけ塗る。46 列 × 14 行で
`|色タイル密度 − 完了率|` は **平均 0.01315 / 最大 0.03383**、丸めの上限 1/(2·14) = 0.03571 を超えない。

弦から軌跡へ 20 本の垂線（櫛）を立ててあるので、いちばん長い歯が真ん中にあることは
数字を読まなくても分かる。そこに壁が立っている。

等時間のビーズは弧の左右に2列：黒が v₀ = 18 m/s、白が v₀ = 34 m/s、どちらも 0.06 s ごと。
**玉の間隔だけが違って、玉が乗っている線は1本しかない。**

## つまずき

1. **Y 回りの回転角の符号**。`Math.atan2(-dz, dx)` と書いたせいで弦だけが鏡に映り、
   軌跡を横切る変な直線になった。three で local +X を (dx, 0, −dz) に送る回転は
   `atan2(dz, dx)`。ビルドでも型でも出ない種類の間違いで、撮った1枚を見て初めて分かる。
2. **弦の法線の向き**。弧は弦より z の小さい側に膨らむので法線は (uz, −ux)。
   逆に取っていたので、櫛もライムの離れマーカーも**弧の反対側**に生えた。これも絵でしか出ない。
3. 🔴 **`--virtual-time-budget` は伸ばすほど空カンバスになった。**
   16000〜24000 ms は6回連続で 86 KB（＝DOMの文字だけ）、9000〜12000 ms で 318〜480 KB が出る。
   virtual time の下では rAF が実時間を無視して回り続けるので、budget を伸ばすと swiftshader が
   先に息切れして最後の合成が空になるらしい。**「出なければ伸ばす」という前日までの階段は、
   今日に限っては逆効果だった**ので `scripts/shot.mjs` の既定を
   `[9000, 11000, 8000, 12000, 10000, 9000]` に置き換えた（閾値は 190 KB）。
4. **照明の単位**。three r155 以降の物理単位ではランバート反射が π で割られるので、
   ambient 0.68 + hemi 0.45 + dir 1.35 では紙（#f1f0ea）が灰色に沈む。
   (ambient + hemi + dir·N·L)/π ≒ 1 になるよう 1.32 / 0.5 / 1.72 に入れ直した。
5. **DOM と 3D の衝突**。最初はタイルを画面いっぱいに敷いたので、左下の数値表が青タイルに
   重なって読めなくなった。タイルを**帯**（z ∈ [−2, 5]）に絞り、上下に紙の余白を残して
   そこへ組版を置いた。RUN.md の「撮った1枚は必ず目で見る」はこれ。

## 正直に書いておく

- 回転軸を鉛直に固定している（＝重力は面外）。実際の FK はボールが落ちもする。
  真上から見る限り面内の式は上のとおりだが、**これは「曲がり」だけの話**で、
  高さ方向の話は一切していない。
- C_L と C_D は飛翔中ずっと一定とした。実際はスピン比 S = ωr/|v| が減速とともに上がるので
  C_L はゆっくり動く。曲率が厳密に一定であることは、**C_L が一定である限り**厳密。
- 壁の位置は「弦の上 9.144 m」。規則は「ボールから 9.144 m」なので、これは正しい読み。
- ゴール枠は描いていない（弦の終端に短いティックだけ）。幅 7.32 m を入れると帯からはみ出すため。
- 揚力係数 0.33 はよく巻いた曲球の実測帯。UI では 0.20〜0.45 まで動かせる。

## 操作

`npm run dev` → ポインタを画面上で動かす。
横がボール→ゴールの距離 C（12〜30 m）、縦が揚力係数 C_L（0.20〜0.45）。
ポインタを外すと C = 18.288 m / C_L = 0.33 に戻る（二十ヤードの穴）。
`node scripts/verify.mjs` で上の数字を全部その場で再計算できる。
