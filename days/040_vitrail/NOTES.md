# Day 040 — Loop 13 · 光源に色がある「Vitrail」（non-uniform area light / 積分の中の色）★★★★★

## 狙い

Day 037 から 3 日かけて、この作品はランプに**形**を与えてきた。2つの角度 →
6枚の矩形 → その上のマスク。しかしその間ずっと、開口は**1色**だった。
`LIGHT.color` という単一の暖白がすべての項に掛かっていた。

これは「ガラス」についての主張であり、そして偽である。鉛桟の窓は開口ではなく、
**1つの石枠に収まった6つの別々のランプ**であって、部屋はその違いを知っている。

だから今日、`WINDOW.glass` が入った。6枚のペインがそれぞれ違う放射輝度を持つ。
左の灯は古くて琥珀、右は冷たく緑、敷居に向かって濃くなる。**光源が非一様に
なった**。そして非一様な光源は、それを読む3者すべてに「1つの数」ではなく
「3つの数」を要求する——**積分・空気・塵**。

Day 039 の NOTES が最上位に書いた宿題は「ペインの細分割」だったが、今日はそれを
やらなかった。細分割は**マスクの解像度**の話で、その手前に「そもそも光源の
放射輝度が定数だと仮定している」という、より大きな1行があったからだ。

## 新しく入れた技法

### 1. 色を LTC 積分の *中* に入れる（`ltc.js`）

昨日の根拠は1文だった：*辺の和はベクトル積分であり、ベクトル積分は領域の分割に
ついて加法的である——重みが付いていても*。今日は重みが**色**になるので、その
1文をもう一度検算する必要があった。

前半は生き残る。`Σ_i c_i · w_i · e_i` は3チャンネル分のベクトル積分で、各々
昨日と同じ意味で厳密。**壊れるのは次の行**：`ltcClip` は地平線クリップの
*近似フィット*で、非線形。チャンネルごとに3回走らせるのは「赤い窓・緑の窓」
という**存在しない3つの形**について問うことで、ペインが地平線をまたぐところで
3つの答えがバラバラに動く。物理的理由なしに。Day 038 の二重補正の、色版。

なので答えを**大きさと色度に分ける**：

```
F      = ltcClip( Σ w_i e_i )                        ← 形は1つ、クリップも1回
Lbar   = Σ w_i·max(e_i.z,0)·c_i / Σ w_i·max(e_i.z,0)  ← ローブが見る平均放射輝度
result = F * Lbar
```

近似は**地平線補正をペイン間でどう配分するか**の1点に閉じ込められる。全ペインが
同色なら厳密（＝昨日のフレーム、＝`?pass=8`）、地平線をまたぐペインが無ければ
厳密（＝この絵で色が読めるほど明るい面はすべてそう）。

拡散項と鏡面項は**同じ配列から違う色を得る**。ここが今日の絵になっている：
漆板（roughness 0.06）のローブが届くのは2〜3枚だけなので、ハイライトは
「石を挟んだ2色」になる。その1cm横の石膏は6枚全部を平均して白に戻る。
**1つのランプから、隣り合う2つの面が測定可能に違う色の光を受ける。**

### 2. 空気には「マスク」ではなく「色」を渡す（`shadow.js`）

Day 039 の NOTES は froxel にマスクを持ち込む方法を考え、240万セルに配列は
持てないので**SH 2次あたりへの射影**が答えだろうと書いた。**この予想は
外れていて、外れ方が有益だった。**

空気は「どのペインが見えているか」を知る必要が一度もない。13度の開口に対して
位相関数はほぼ定数なので、位相関数は積分の外に出る。froxel が必要とするのは

```
∫ L(ω) vis(ω) dω   —— 3つの数。6つでもなく、基底でもない。
```

だから**タップが色を運ぶ**。`srcSample` は既に CDF を歩いてペインを選んでおり、
既にどれを選んだか知っていた——`return` の行までは。今はそのペインの色も返す。
タップは面積比例に配られているので、色の平均は**可視部分の面積加重平均放射輝度
そのもの**（不偏推定量）になる。追加コスト：シャドウマップ読み **0回**、
タップあたり足し算2つ。SH 射影は1行も要らなかった。

正規化には注意が要った。`col / vis`（**ヒット数**で割る、タップ数ではなく）が
「通ってくる光の色」で、呼び出し側が `vis` を掛けて「どれだけ通るか」を足す。
タップ数で割ると遮蔽が色の中に畳み込まれ、呼び出し側がもう一度掛けて**影が
2回落ちる**。

### 3. 平均を白に固定する（`palette.js`）

6つの色は**面積加重平均が厳密に (1,1,1) になるよう正規化**される。中段は上下段
より背が低いので、素朴な6色平均では中段の色が窓の取り分以上に効いてしまう。

これがこのシリーズの規則（比較は1つのことだけを変える）を色に適用した形で、
`?pass=8` が「ガラスを灰色にする」だけで、露出も放射照度も `uSrcRad` も
1つも動かない理由。**色と量が分離している。**

### 4. GLSL バッククォート lint（`scripts/glsl-lint.mjs`）

Day 039 の NOTES の最優先項目：「シェーダ文字列のバッククォートを lint で
止める。3日連続で踏んでいる」。**4日連続で踏んだ**（今朝は froxel.js の
コメント内の `` `softVisTint` ``）。大文字で警告を書いた本人が翌日踏むなら
警告は仕組みではない。

`npm run prebuild` に入れたので、**バッククォートが1つでも入ると `npm run build`
が通らない**。ルールは意図的に狭い：GLSL テンプレートリテラルは
「バッククォートだけの行」で閉じ、その間の他のバッククォートはすべてエラー。
（この判定自体を植え付けたバッククォートでテストして exit 1 を確認した。）

## つまずき（記録用）

**振幅を1.6倍間違えた。** 最初の実装は ±13%——カラーピッカーで見れば充分すぎる
量——で、レンダを測ったら反射の左右が R/B = 0.95 と 1.09、灰ガラス基準の 1.04 に
対して。**本物で、スクリプトで証明でき、そして見えない。** 食っている犯人は2つ：
①平均が**構成上**白なので、窓全体が見える面はこの効果を1つも受け取らない
②トーンマップが、窓がいちばん明るいところでいちばん強く圧縮している。
±21% にして 0.92 対 1.16。方立が「影の境界」ではなく「色の境界」になる。
G チャンネルは全ペインで 1 に固定してあるので、赤と青を交換しているだけ
——窓は幅方向に**色相だけ**変え、輝度は変えない。それが礼拝堂にならない条件。

**ヘッドレスは同じURLで 10% 明るさが揺れる。** `?pass=8` を2回撮って
フルフレーム平均 46.56 と 42.26。TAA と froxel の蓄積が何フレーム目で
スクリーンショットされるかによる。**つまり 3〜4% の差を「効果あり」と読んでは
いけない**。今日のエネルギー保存の検証（tint 45.04 対 grey 43.53 = 3.4%）は
この分散の**中**にあり、それが結論——色相は変わり、量は測定精度内で不変。
色度比（R/B）は蓄積フレーム数にほぼ依存しないので、主張はそちらで測った。

**`--no-sandbox` が要る。** root で走る Chromium は sandbox 無しでないと
起動もせず、スクリーンショットは 0 バイトで返る。RUN.md の「空カンバスは
28KB」は**描画に失敗した**場合の話で、**起動に失敗**すると 0 バイトになる。
閾値ループはどちらも弾くが、原因は別物なので次回のために書いておく。

## 構図・トーン

- 光は1つ。フィルもアンビエントも環境マップも無い（Day 036 から継続）。
- **主役は手前の漆板の反射**。方立の左右で色が変わり、石がその境界になっている。
  奥の板は粗くて窓を閉じたロゼンジにしてしまうので、6枚を平均して**暖かい1色**
  ——同じ1枚の絵の中に「光源を解像した面」と「しなかった面」が並ぶ。
- Day 039 の梁（lath）はそのまま。食で欠けるのが**特定の色の灯**になったので、
  欠けた側の反射が冷える。マスクと色は掛け算で素直に合成する。
- Day 031 からの規則——**作品が中心に据えている物体（窓・絞り板・梁・今日の
  ガラス）は一度も映らない**——を継続。今日はいちばん徹底していて、
  ガラスは石の上の色としてしか存在しない。

## 次に試したいこと

- **窓を1枚の画像にする（textured LTC）**。今日の色は「ペインごとに区分定数」
  ——Day 039 のマスクとまったく同じ解像度の制限を、今度は放射輝度側で背負って
  いる。Heitz の textured light（LTC ローブの立体角から mip レベルを選んで
  プリフィルタ済みテクスチャを1回引く）なら、区分定数をやめて**連続**にできて、
  しかもペイン数に依存しない。**Day 039 の「ペインの細分割」と今日の「色」は、
  実は同じ1つの機能で両方消える**。次はこれをやるべき。
- **`Lbar` の重みを clip の後にしたい**。今は `max(e_i.z, 0)`——クリップ前の
  形状係数——で配分している。地平線をまたぐペインでは配分が実際の寄与とずれる。
  正しい直し方は多角形の地平線クリップ（可変長ループ）で、それは `ltcClip` の
  フィットを捨てるということ。**このシリーズで初めて「近似をやめる」が
  「安くなる」ではなく「高くなる」側にある**宿題。
- **froxel の色にも時間フィルタの色クランプが要るかもしれない**。今は輝度で
  ネイバークランプしているので、色相だけが暴れるケースを拾えない。今日の絵では
  シャフトが細いので出ていないが、開口をもっと分けたら出るはず。
- **ガラスに吸収を（波長依存の透過）**。ペインの色は今「そういう放射輝度」で
  与えているが、本当は白い空を**透過**した結果。厚みと吸収係数で書けば、
  すりガラス（Day 038 からの持ち越し・光源自身が等方でない）と同じ枠に入る。
- **froxel への影のキャッシュ**（Day 036 からの持ち越し）。
