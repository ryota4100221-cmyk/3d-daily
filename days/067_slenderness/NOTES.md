## 何を再現したか

キー演出は1つに絞った。**「硬い → 柔らかい」を説明する仕掛け**である。
UNIPLEX はそれを2色の対比でやっている。こちらは同じことを、
**それを実際に決めている一つの数**でやる。

分解すると **幾何** だった。硬い／柔らかいを分けているのは、力でも材質でもない。

```
ε_cr = π² (I/A) / (K L)²  =  π² r² / L²        （K = 0.5, 円断面 I/A = r²/4）
```

材料定数 E がどこにも出てこないのがこの式の要点で、座屈は「強さ」ではなく
「形」の問題だから正しい。同じ長さ・同じ材料・同じ板でも、**細さ λ = 2L/r
だけ**が倒れる順番を決める。

## 分解した装置：細さだけが決める（the slenderness threshold）

1. **状態を持たない。** `rig.js` にも頂点シェーダにも「この棒は倒れている」という
   変数は一つも無い。あるのは板の縮み `uDelta` と、棒ごとの `iCrit` だけで、
   絵は `max(uDelta - iCrit, 0.0)` という1行の比較の結果でしかない。
2. **振幅は剛性が決めていない。** 座屈後の形は第1モード
   `w(s) = (A/2)(1 − cos 2πs/L)`、その振幅は「棒が伸びない」ことだけで決まる：
   `δ − δ_cr = ∫½w′²ds = π²A²/(4L)` → `A = (2/π)√(L(δ − δ_cr))`。
   つまり曲がり具合を出すのに材料の話は一度も要らない。
3. **前線が板と同じ速さで走るように場を組む。** 太さを x に線形に並べると
   ε ∝ r² なので前線が左で走って右で止まる。`ε_cr` のほうを x に線形にして
   `r = √ε·L/π` で逆に引いた。これで「板が下りた量 = 前線の位置」が一対一になり、
   画面の左右が板の高さの目盛りとして読める。
4. **画面の数字は装置から引く。** `survey()` が返す座屈本数・前線の λ を
   そのまま DOM に流す。別ロジックで数えない。
5. **色は7段に量子化する。** UNIPLEX が蛍光色を7段に割って一系統で回しているので、
   陰影も同じ7色の階段でしか塗らない（`pick(q)`）。連続階調にすると
   「7段に割った」という設計そのものが絵から消える。

## つまずき

1. **1回目の実描画で棒が全部真っ黒になった。** 陰影の式ではなく、チューブの
   インデックスの巻きが逆で、カメラを向いている面が全部 back-facing になっていた
   （`gl_FrontFacing` で法線を反転していたので、見えている側だけ裏返っていた）。
   `(a,c,b)` を `(a,b,c)` にして直し、反転の行を捨てた。
2. **板を面で描くと画面の3割が灰色の板になる。** 俯角28°では奥行き4.2の面は
   巨大な帯として写り、押されている側が全部隠れる。板は**輪郭と支柱**だけにした。
   棒の頭が全部同じ高さで切り揃うので、面が無くても板はそこに在る。
3. **台に縁を付けると、その縁が見出しにぶつかる。** この俯角では奥の縁は
   画面の上のほうに来る。縁を作らず、地の色ごと空へ溶かした。
4. **同じビルドから違う δ が出た。** 自動送りを「1フレームあたり9%で目標へ寄せる」
   遅延フィルタで書いていたので、到達点が rAF の回数に依存した。headless の
   virtual time では回数が決まらないので、δ/L = 0.0050（15本座屈）と
   0.0292（94本座屈）の両方が撮れてしまう。**バイト数の閾値では捕まらない**
   （どちらも実描画）。自動送りのときは補間を外して直した。
5. **空カンバス判定の閾値はまた貼り直し。** 実描画 144KB／空カンバス 41KB。
   前日までの 150KB のままだと実描画のほうを弾く。90KB に下げた。
