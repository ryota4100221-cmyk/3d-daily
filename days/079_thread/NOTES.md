## 何を再現したか

このサイトのキー演出は canvas の FV ではなく、**商品名の一語**だと判断した。「逆みたらし」は、
ふつう外にかける蜜を中に入れてしまった団子である。だから今日は**裏返した側**を測った——

> 蜜を外に出したままにすると、何が起きるのか。

答えは「衣のままではいられない」。円柱状の液体は周長より長い波長のゆらぎに対して必ず
不安定で（Plateau 1873 / Rayleigh 1878）、衣は必ず玉になる。**逆みたらしが存在できる理由は、
外の蜜が信用できないことにある。** それをそのまま画面にした。

分解すると **シェーダ（幾何を1本の式で駆動する頂点シェーダ）** だった。カメラも時間も入力も
主役ではない。

## 分解した装置 — 勝った波長

7 本の糸は 7 つの**時刻**である。太さ（R = 0.072）も長さ（L = 4.70 = 65.3 R）も雑音の種も
7 本とも同一で、違うのは「垂れてからどれだけ経ったか」だけ。左端 t=0 は白色雑音そのもの——
46 本の波が等振幅で乗っていて、プロファイルの山を数えると **22 個**、間隔 2.97 R、意味は無い。
右へ行くほど式が選抜を進め、t=21 以降は **7 個・間隔 9.38 R** で動かなくなる。

  ω² = x (1 − x²) · I₁(x) / I₀(x),   x = kR       （σ/ρR³ = 1 と置いた無次元時間）

- `x ≥ 1`（＝周長 2πR より短い波）では ω が虚数になり、伸びない。46 本のうち **10 本**だけが育つ
- 最大は `x* = 0.6970` → `λ* = 2πR/x* = 9.014 R`
- 材料定数は式から消える。**蜜でも水でも樹脂でも 9.014 R**
- 有限長の糸なので k は 2πn/L に量子化されている。実際に勝つのは x* に最も近い `n = 7`（x = 0.6738）で、
  だから測ると `L/7 = 9.38 R`——**予言 9.014 R との 4% の差は、糸が有限だということそのもの**

いちばん面白かったのはここ: **勝ちは僅差だった。** n=7 の成長率は n=8 のわずか 2.14% 上でしかなく、
21.6 e-fold（初期振幅 4e-10·R ＝熱ゆらぎの桁）伸ばしても、負けた n=8 はまだ 64% 残っている。
右端の玉が等間隔に揃っていないのはその跡で、**きれいに揃った玉の鎖のほうが嘘**になる。

## 何を捨てたか

- サイト全体（LP 11 セクション・ページ全長 15293px・横並びの商品カード・お知らせ）
- Zen Kaku Gothic New W900 / 字間 +18% の和文見出し（外部フォントは取れない。**組み方だけ借りて**
  英文の細いサンズに置き換え、太さではなく字間と余白で階層を作った）
- 団子そのもの。丸い餅を描いた瞬間、絵の主語が「団子」に移って蜜が背景になる
- 非線形段階。ここで伸ばしているのは線形理論の解だけで、玉は余弦の山であって球ではない。
  ちぎれる寸前のくびれは `max(p, 0.018)` で髪の毛一本ぶん残してある（実際の糸もこう見える）
- 振幅の絶対値。モード比だけが時刻 t の情報で、全体の倍率は画面に収めるための正規化。
  比を変えないので選抜は壊れない——ただし**これは演出であって物理ではない**ので明記しておく

## つまずき

1. **地の色が実測値より暗く出た**（`#E5E0CA` のはずが `#C8BE97`）。ShaderMaterial は
   three が出力カラースペースの変換チャンクを付けてくれないので、linear のまま書き出していた。
   `#include <colorspace_fragment>` を 3 つのフラグメントに足して解決。
   **meshBasicMaterial の黒と赤だけ正しく見えていた**のが手がかりだった
2. **DOM の見出しと 3D の衝突**（RUN.md が言うやつ）。目盛り行に
   「PEAKS COUNTED ON THE PROFILE」と書いたら左端の糸の `t 0` ラベルに乗った。`PEAKS →` に縮めた
3. **空カンバス誤診が梯子ごと外れた回がある。** budget 16000/18000/20000/22000/24000 の
   **5 本とも 26KB**。同じ dist を別プロセスで budget=20000 一発にしたら 240KB 出た。
   前の `vite preview` がポートを掴んだままだったのが原因で、
   **梯子が尽きたときは「描けない」ではなくサーバ側を疑う**。閾値は 90KB に置き直した
   （実描画 228〜284KB／空カンバス 25〜27KB）

同じビルドから別の絵が撮れた事故があったので、headless の仮想時間で撮るならこの形しか無い。
