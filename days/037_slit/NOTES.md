# Day 037 — Loop 10 · 光源に形がある「Slit」（異方性PCSS / 面積光源のBRDF）★★★★★

## 狙い

Day 036 は自分の NOTES の「次に試したいこと」の一番上に、こう書き残した：

> **面積光源の直接項も面積にする。** 影だけが大きさを知っていて、拡散反射と
> ハイライトはまだ点光源のもの。

昨日、ランプは大きさを手に入れた。だがその大きさ（半角 `θ`）が届いていたのは
**影のテストだけ**で、その6行上の BRDF は相変わらず `max(dot(n,L), 0)` と
「1つの方向のまわりの GGX ローブ」を評価していた。つまり**同じ1枚の中で、影は
「ランプは1m幅だ」と言い、ターミネータは「ランプは点だ」と言っていた。**
気づきにくいが、一度気づくと元に戻れない種類の不整合。

今日はその大きさを全部に配る。そして配った瞬間、**それが1つの数である理由が
なくなる**。光源の角度的な広がりは円ではなく**楕円**で、楕円は2つの数を持つ。

そこから今日の主張が出てくる：

> **影の柔らかさは、それを落とす物体が「どちらを向いているか」で変わる。**

昨日の円形光源には絶対に言えない文。円には「向き」に対して比較すべき何もない。

## 新しく入れた技法

### 1. 異方性PCSS（今日の絵）

Day 036 の3手順はそのまま。変わるのは `θ` が `vec2` になったこと：

```
1. BLOCKER SEARCH   楕円で探す（`search` = (2.20m, 0.34m)、光源自身のフレームで回転）
2. PENUMBRA SIZE    w = angles * gap    ← vec2。メートル。Day 031 以来ずっと線形だから書ける
3. PCF              そのサイズの楕円で
```

タップの作り方に**順序の罠**があり、これはこの日いちばん「知らないと踏む」箇所：

```glsl
vec2 shOffset(int i, int n, vec2 rr, vec2 radiiUV) {
  //   ①単位円をデコリレーション角で回す → ②楕円に潰す → ③光源フレームへ回す
  return shRot(shRot(shSpiral(i, n), rr) * radiiUV, uSrcAxis);
}
```

**先に潰してから回すと、ピクセルごとのノイズパターンにも光源のアスペクト比が
乗る。**2つの楕円が干渉して、テンポラルフィルタを生き延びるモアレになる。

絵の上での結果が今日の全部：**同じ厚み11.5cmの板を7枚、ヨーだけ90度スイープして
並べる**と、左端の板（光源の長軸に正対）は影が自分の5倍幅に広がって**芯が
どこにも残らない**、右端の板（短軸に正対）は**線のまま**。高さも隙間もランプも
同じで、違うのは角度だけ。

### 2. 面積光源の拡散項＝ターミネータ（`area.js`）

Lambert の `max(ndl, 0)` は**大きさゼロの光源の放射照度**。角半径 σ の光源は
幾何学的な地平線の**手前から沈み始めて向こうで沈み終わる**ので、境界は折り目では
なく幅 2σ の帯になる。地平線をまたぐ円盤の解析解（Frostbite, *Moving Frostbite to
PBR*, listing 10）を `π sin²σ` で割って正規化し、**σ→0 で厳密に Lambert に戻る**
形にした。帯の外では昨日のフレームとビット単位で一致し、帯の中だけが新しい。

**どの σ か**、が楕円だと問題になる。楕円は方向ごとに半径を持つので
`r(d) = 1/sqrt((d.x/a)² + (d.y/b)²)`、そして意味のある方向は
**その面が転がって光から外れていく向き**——法線の L に垂直な成分を、光源自身の
軸で読んだもの。だから縦の板と横の梁は、同じスリットの下で**違う幅の
ターミネータ**を持つ。調整ではなく計算でそうなる。

`direct()` の早期リターンも動いた。`dot(n,L) <= 0` は点光源なら厳密に正しいが、
22度の広がりを持つ光源では**地平線を数度越えた面もまだ開口の上端を見ている**。
リジェクトを `-sin(θmax)` まで押し出し、そこから0までの帯がターミネータになる。
アンビエントが1つも無いフレームなので、この帯は昨日まで**真っ黒**で、
Day 034 の wash だけが立っていた場所。

### 3. 面積光源のスペキュラ＝ハイライトが「帯」になる

Karis のスフィアライト（*Real Shading in UE4*, 2013）を円盤から楕円へ一般化：

- **representative point**：鏡面反射方向 R を光源の**楕円錐にクランプ**する。
  R が開口の内側に落ちる範囲では面は開口の*内部*を見ているので、そこ全体が明るい
  ——点ではなく**帯**になるのはこれ。
- **ローブの異方的拡張**：`a' = a + θ/2` を軸ごとに。2つの α は**異方性 GGX**なので、
  光源の長軸を面に射影した接空間で評価する（D は Filament の安定形、可視項は
  Smith height-correlated の異方版）。

### 4. パスは1つも増えていない

froxel.js も passes.js のモート材質も、**今日は1行も編集していない**。
どちらも `softVis(p, rot)` を呼ぶだけで、光源の記述が1ファイルにあるから、
シャフトの縁も塵も自動的に開口の異方性を受け取る。
**「光源をどう書くか」を1箇所に押し込んだ配当が、今日まとめて返ってきた。**

そしてこれは構図の判断でもある。アパーチャのスリットは光源の**短軸**を横切る向きに
置いてあるので、**シャフトの縁は3度弱の数字で支配されて鋭いまま**、地面に立つ物の影
だけが22度の数字で溶ける。実際のスリット窓はまさにこうなる——矛盾ではなく、
同じ開口を2つの方向から見ているだけ。

## つまずき（記録用）

**エネルギー正規化を貼ったらガラスが真っ黒になった（今日の最大の1時間）。**
Karis のスフィアライトのノートには `(alpha/alpha')²` を掛けると書いてあり、
異方版として `a²/(ax·ay)` を入れた。**係数 0.0385。ハイライトが 26 倍暗くなった。**
実描画では釉薬の玉が完全な黒い穴になり、4倍にブーストして初めて「帯はちゃんと
出ている」ことが分かった。

理屈：GGX の D は**すでに正規化されている**（∫D·cos = 1）ので、ローブを広げても
エネルギーは作られず、消えもしない。広げること自体が補正の全部。しかも
`(a/a')²` は a→0 で 0 に行くので、**完全な鏡がスリットを何も映さなくなる**。
正しい答えは有限で、光源自身の輝度 × F。

検算は意見ではなく数字でできる。ピークで本実装が返すのは

```
E · F / (π · ax · ay) = 2.24        （E=3.05, F=0.045, ax=0.20, ay=0.023）
```

対して真の鏡は `L_src · F = (E/Ω) · F = 2.65`（Ω = π·θa·θb = 0.050 sr）。
**4行で15%。**正規化を消すのが正解だった。

**θ/2 であって θ ではない。**ハーフベクトルが半角ぶん動くと反射方向は1角度ぶん動く。
GGX がパラメトライズされているのはハーフベクトル側。上の 2.24 対 2.65 は
この 0.5 を含めた数字で、θ を丸ごと足すと今度は明るすぎる。

**板が9枚・幅66cmでは「壁」だった。**最初の構図は Day 036 の rake をそのまま板に
置き換えたもので、実描画すると**画面の奥半分が板のシルエットで埋まり、影を書く
ページが1ミリも見えなかった**。物として読める幅の板は、影を隠すのにも十分な幅。
7枚・34cmに落として初めて主題が見えた。**今日の主役は板ではなく板が書くもの**、
という当たり前が、幅の数字としてしか効かない。

**カメラを1m上げるのはタップ数より効く。**斜めから読む影は線でしかない。
上から読むと**幅を持った形**になり、その幅の違いが今日の主張そのもの。
`y 3.05 → 4.05`、注視点 `0.95 → 0.58`。

**梁は最初また文字組みに当たった**（Day 027・036 と同じ再発）。カメラを上げると
奥の門は画面の上に寄るので、昨日の高さのままではヘッダの罫線に刺さる。
梁 3.24m→2.64m、柱 3.02m→2.42m、門ごと奥へ 0.75m。

## 構図・トーン

- 光は1つ。フィルもアンビエントも環境マップも無い（Day 036 から継続）。
- **7本の板が主題ではなく、板が書く7本の影が主題。**左端＝芯の無い滲み、
  右端＝線。同じ物・同じ高さ・同じランプ、違うのはヨーだけ。
- **釉薬の玉**が今日の唯一のスペキュラの証人。粗さ 0.13。ここに乗るのは
  開口のアスペクト比そのままの帯。9で円、0で点になる。
- **鉢**は拡散の証人。遠い側のターミネータが折り目ではなく帯になっている。
- 梁の裏・柱の前面はどれも直接光が**厳密にゼロ**。見えているものは全部 wash
  （Day 034・035 の機能が無傷であることの証明として在庫）。
- Day 031 からのルール——**作品が中心に据えている物体（絞りの板）は一度も映らない**
  ——を継続。

## 検証（RUN.md の品質チェックに従って）

- `npm install && npm run build` 成功。
- ヘッドレス（Chromium / SwiftShader / 1600x1000 / virtual-time 26s）で実描画を確認。
  空カンバス閾値は 250KB（正常 1.58MB）。撮った絵は全部目で見た。
- **3枚並べて主張を確認した**（`?pass=1` / `?pass=9` / `?pass=10`、同じ phase）：
  - `?pass=1`（スリット）：影の柔らかさが**板ごとに違う**。玉は帯。
  - `?pass=9`（同じ立体角の円）：影が**全部同じ柔らかさ**に揃う。玉は丸い点。
    ターミネータは残る＝「面積であること」と「形があること」が分離できている。
  - `?pass=10`（点）：全部が定規の縁。玉は針の先。
- `?pass=7`（wash 単独）：梁の裏・柱の前面にちゃんと乗っている＝昨日までの機能は無傷。
- `?pass=2`（直接光のみ）：構図決定に使用。合成では霧に埋もれて判断できない。
