# Day 068 — The False Centres

**再現元: PIXEL × PIXEL 2026（3DCG・モーションデザイン・VFXのフェス）**
https://pixelpixel.jp/

## 何を再現し、何を捨てたか

キー演出を1つに絞った。**濃紫の地に、色を持たないCGが1枚だけ置かれている状態**。

スワイプファイルDBの実測がこの1点をはっきり示していた——`FVの設計色% = 0`
（全編でも 4.17%）、`地の反転回数 = 0`、`計測の注意 = FVがcanvas / FVの文字が画像 /
FVだけ静か（全編は色を使う）`。つまりあのサイトの第一画面は、**蛍光ピンクを
1ドットも使っていない。** 色は後から、面積の小さいところにだけ出てくる。

だから今日は「濃紫 #18103F を地に敷き、有彩色はタイルの数%にしか出さない」を
制約として先に置いた。これは装飾の判断ではなく、再現元の運用ルールをそのまま
借りたもの。実測: **地 = #18103F（再現元の bodyBg と完全一致）／蛍光ピンク系の
画素 = 1.14%**。

**捨てたもの**: サイト全体・マーキー・横スクロール・動画・スクロールリビール・
登壇者やタイムテーブルの中身・Funnel Display（外部フォントはこの環境から403なので
組みの数値だけ借りた——見出し字間 2%・本文行間 185%）。

再現元は WebFetch が `EGRESS_BLOCKED` で到達できないので、根拠はDBの実測値のみ。

## 分解した装置 — 偽の中心（the false centres）

それが 幾何／シェーダ／カメラ／時間／入力 のどれでできているかを先に言葉にすると、
これは **どれでもなく「標本化」** だった。形でも光でもなく、読み方の問題。

書いたのは3つだけ。

1. **信号** `s(x,y) = ½ + ½·cos( a·(x²+y²) )` — 連続関数。原点から離れるほど密になる
   （zone plate / chirp）。位置 s での空間周波数ベクトルは `g = ∇φ/2π = a·s/π`。
2. **標本器** 一辺 p の正方格子。各タイルは**自分の中心の1点だけ**を読む。平均も補間もしない。
3. **表示** 読んだ値をそのままタイルの高さと色にする。

これで終わり。`rig.js` にも頂点シェーダにも「リング」「中心」「モアレ」と書いた行は
1つも無い。それでも絵には中心が9個出る。

なぜか。周期 p の格子は、逆格子ベクトル `(2π/p)·(m,n)` だけ違う周波数を区別できない。
だから `g·p` が整数ベクトルに一致する場所では**再構成された周波数がゼロに落ちる**——
そこに本物の中心とまったく同じものが生える。位置は

```
x = π·m / (a·p),   y = π·n / (a·p)        m,n ∈ ℤ
```

で、間隔 `G = π/(a·p)` の**正方**格子。**信号は丸いのに、偽の中心の並びは四角い。**
並べているのが信号ではなく標本器のほうだから。サイト名の PIXEL × PIXEL が
そのまま式になっている（ピクセルとピクセルの積＝逆格子）。

ナイキストの壁も同じ式から落ちる。第一ブリルアンゾーン `max(|qx|,|qy|) = ½`
（`q = g·p`）の**内側だけが本当のことを言っていて、外は全部嘘**。この壁も正方形で、
これも信号ではなく格子の対称性のほう。画面のシアンの毛髪線がそれ。

設計値は a ではなく **G（偽の中心をいくつ画面に入れるか）**の側に置いた。
`G = 4.6` → `a = π/(G·p)` を逆に引く。こうすると「何個見せたいか」だけで絵が決まる。

### 動き — 格子は1ミリも動かさない

動かすのは標本点の **p 未満のずれ** `uPhase` だけ（センサが1画素以下だけ揺れる、に相当）。
タイルは全部その場から動かない。それでも外側は激しく脈打つ。

次数 (m,n) の偽が受け取る位相は `2π(m·δx + n·δy)/p` なので、ドリフト方向を
`(1, 0.618)` に取ると **脈拍の速さは `|m + 0.618n|`**。0 になるのは (0,0) だけ
＝本物の中心だけが呼吸しない。0.618（黄金比）を選んだのは、小さい (m,n) に対して
`|m + 0.618n|` の最小値を最大にするから（最も近似しにくい数）。実際 (±1,∓1) の
0.382 が最小で、これ以上は上げられない。

## 実測（数字を書かないと嘘になるので全部載せる）

**面で平均した版との差**（`?filter=1`／F キー・平均|Δ| 0-255）:

| 場所 | 平均 \|Δ\| |
|---|---|
| **壁の内側**（正しく読めている所） | **5.42** |
| 壁のすぐ外・右 | 17.14 |
| 壁のすぐ外・手前 | 19.14 |
| 場の外周 | 16.62 |

**壁の内側は平均で3倍動かない。** 内側は元から正しかったので平均しても変わらず、
外側は全部でっち上げだったので平均すると消える。これがこの壁が実在する証拠。

**時間差**（t=6.5 と t=10.8・δ が 0.494 ピッチ進む間の平均|Δ|）: 真の中心 10.56 /
偽(1,0) 16.80 / 偽(-1,0) 15.27。**同じ奥行きで比べると本物は約35%動かない。**
手前や奥の偽（20.94 / 11.45）と直接比べてはいけない——遠近で画面上の面積と
コントラストが変わるので、この数字は動きの速さだけを測っていない。
なお真の中心も 0 にはならない。位相をずらせば滑らかな信号でも読み値は少し変わるからで、
これはエイリアスではない。**止まっているのはリングの位置であって、画素の値ではない。**

## つまずき

1. **1回目 — 式は正しく、偽の中心が 5×5 に並びすぎた**（span=12 / n=168）。25個が
   全部小さく、本物が奥の豆粒になり「壁の内側では正しく読めている」という肝心の主張が
   画面に出なかった。3×3 に減らして大きく見せる方に倒した。
2. 🔴 **2回目 — 全部リニアのまま出ていた。** 地が #18103F ではなく **#02010d**、
   平均輝度 6.8/255。`ShaderMaterial` には three が色空間変換を自動で挿してくれない
   （挿さるのは組み込みマテリアルだけ）ので、フラグメントの末尾に
   `#include <colorspace_fragment>` が要る。加えて `setClearColor` は変換を通らず
   リニア値をそのまま `gl.clearColor` に渡すので、地はCSS側の1色に任せて canvas は
   `setClearAlpha(0)` で抜いた。**ビルドも描画も通るので、画面を測るまで分からない種類の間違い。**
   バイト数の閾値でも捕まらない（どちらも実描画）。
3. **3回目 — 色を直したら今度は場が一面の紫になった**（高彩度画素 30%）。再現元は
   設計の色 4.17%・FVは 0% なので、地に寄せる係数を入れて 1.14% まで落とした。
4. **構図は3回撮り直した。** 左下に実測値を置くと場の手前左の角がそこまで伸びていて
   罫と1行目がタイルに乗る。左の1列に積み直しても下2行が板の左縁に触る。最後は
   **場そのものを画面の右へ 2.2 ずらして**、左の列が地の上だけを通るようにした。
   ビルドでは絶対に出ない種類の問題で、RUN.md が Day 027 で書いている通り実描画でしか分からない。
5. 空カンバス判定の閾値はまた貼り直し。実描画 530KB / 空カンバス相当は数十KB なので
   `SHOT_MIN=60`（KB）に置いた。前日の 90KB でも通るが、今日は余裕がある。

## 副産物

`?filter=1` で面平均に切り替えると、**外側の起伏は消えるのに、偽の中心の場所に
ピンクの平らな円盤だけが残る。** 色は値ではなく `fold`（折り返しまでの距離）から
引いているので、値が均されても「そこに偽が立っていた足跡」は残る。消し忘れではなく、
残したほうが比較が読めるのでそのままにした。
