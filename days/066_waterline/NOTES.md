# Day 066 — THE WATERLINE

**再現元** 電通 新卒採用サイト（DENTSU INC. RECRUITING 2026）
https://www.career.dentsu.jp/recruit/2026/

スワイプファイルDBの実測にはこう書いてある——
「水色の空 #B0E0F0 と青い海 #3898E0 で画面を上下に割り、境界線に肌色のキャラクターを
泳がせる。紺 #202038 が文字色。**フラットな塗り分けだけで写真を1枚も使わない**」。

## 何を再現し、何を捨てたか

**再現したもの＝境界線ひとつ。** 画面を上下に割る線と、そこにだけ人がいるという構造。

**捨てたもの:**

- コピー（「いま、自分にないものを。」）とその文字組み、A1 Gothic B の見出し
- スクロール尺・固定セクション・読み物セクション——サイト全体は作らない
- 肌色のキャラクター表現そのもの（人の描き方は借りず、位置と役割だけ借りた）
- 再現元の色そのまま（#3898E0 は明るすぎるので、地は #2b6d8d に落とした）

キー演出は **幾何** でも **シェーダ** でもなく、**カメラと座標系**でできている、と読んだ。
上下に割れて見えるのは、目が水面の高さの近くに置いてあるからで、
そこから先は「線の上か、下か」だけが効く。だから作ったのはその1本の線の扱いだけ。

## 分解した装置 — 見かけの深さ（apparent depth）

**水面のメッシュは1枚も無い。** 海は色の領域であって、面ではない。
背景は「カメラから出た光線が y=0 の高さを下に切ったか」を1ピクセルずつ聞いているだけで、
だから水平線は無限遠まで正確で、遠景で1pxも割れない（有限の板を敷くとここが割れる）。

では水があることを何が言うのか。**水面より下に落ちた頂点を、もう一度だけ読み直す**こと。

```
d  = waveH(p.xz, t) - p.y            // その点の真上の水面からの深さ
if (d > 0) {
  d′    = d / η                       // 見かけの深さは浮き上がる（η = 1.34）
  p.xz += waveGrad(p.xz, t) * d′ * k  // 面が傾いていれば横へ流れる
  p.y   = surf - d′
}
```

この分岐に入る条件は「その点の真上の水面より下か」だけで、
**胴・腕・脚・頭の区別を一切していない。** 腕が水を切る瞬間は腕の都合ではなく、
水面の側の都合で決まる。`rig.js` に「ここから水中」と書いた行は1行も無い。

色も同じ場所で決まる。`1 - exp(-d′ · 1.35)` で地の青へ寄せるだけで、
透明度は1つも使っていない。**沈むほど淡くなるのは、水を半透明にしたからではなく、
深さがそのまま色の混合比だから。**

副産物が2つ:

- **カプセルの作り方が絵に効く。** カプセルは「単位球の赤道に、同じ点を16本重ねた縮退した帯を
  挟んだラース」で、頂点シェーダで `aStretch * aHalf` だけ開くとはじめて円筒になる。
  ここを1枚のクアッドで済ませると、水面をまたいだ腕が**折れずに直線で刺さる**——
  つまり二度目の読みが効いていないように見える。曲がるためには、そこに頂点が要る。
- **入水の輪だけは水面の上に置いた。** 手先が水面を下向きに切った瞬間だけ輪を1つ置く。
  輪の高さは常に `waveH(...)` なので、波と一緒に上下する。
  水面を描かない代わりに、水面が「そこにある」と言わせる唯一の装置。

## 詰まったところ

1. **`ShaderMaterial` は sRGB へ書き戻してくれない。** 最初の1枚は海が黒に近い紺で出た。
   組み込みマテリアルと違い、自前の fragment には `#include <colorspace_fragment>` が
   入らないので、リニア値がそのまま sRGB のフレームバッファへ落ちる。3本とも追加した。
2. **`instanceColor` は宣言されないことがある。** `mesh.instanceColor` が null のうちは
   three が `USE_INSTANCING_COLOR` を立てないので、シェーダ側で参照するとリンクに失敗して
   何も出ない。自前の `aTint`（InstancedBufferAttribute）に替えて、生成時に一度だけ書いた。
3. **headless_shell が同じ budget で 73KB → 24KB と揺れた。** 大きいほうの中身も空だった
   ので、バイト数のリトライでは救えない。Playwright の chromium（実時間で待てる）へ替えた。
   閾値も置き直した——地が2色のベタなので実描画でも 78〜106KB しかなく、
   過去の日の 400KB をそのまま持ってくると**正しい絵を空カンバス扱いで捨てる**。
4. **目の高さを水面ちょうどに置くと、装置が絵に出ない。** 最初は y=0.60 に置いたが、
   体がほぼ全部 y≈0 にいるので水中に深く入る点が無く、見かけの深さがどこにも現れなかった。
   y=1.30 まで上げて 5° 見下ろすと、水を掻いている腕が線の下で淡く・短く・横へずれる。
   **上下に割る強さは少し譲ったが、譲らないと装置が見えない。**
