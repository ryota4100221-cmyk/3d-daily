```

               他はすべてCPU側で1回だけ、ここから導出される。
```

そして今日の主張はこう書ける：

昨日も同じことを言った。そして**球でそれを言おうとした**——これが、光源に方立が

今日の画面に**平らな鏡**が2枚ある理由がこれ。

## 新しく入れた技法

### 1. LTC（Linearly Transformed Cosines）— 今日の絵

Heitz, Dupuy, Hill, Neubelt, *Real-Time Polygonal-Light Shading with Linearly
Transformed Cosines* (SIGGRAPH 2016)。3文で言うと：

- **コサインローブ**の多角形上の積分には閉形式がある（球面射影した多角形の辺ごとに
  弧長項を足して1成分を読む）。
- GGXローブは**コサインローブの3x3線形変換**でよく近似できる。
- よって「GGXを多角形で積分」は「多角形に**逆変換**をかけてコサインを積分」になる。

行列は 64x64 の LUT に入っていて、**three が既に同梱している**
（`RectAreaLight` が r87 以来まさにこれを必要としているため）。
`three/examples/jsm/lights/RectAreaLightTexturesLib.js` を `init()` して
`LTC_FLOAT_1 / LTC_FLOAT_2` をそのまま使った。

だから `ltc.js` は小さく、中身のほとんどは **three がやらない部分＝光源が
1枚の矩形ではないこと** に費やされている。

**複数ポリゴンがタダで済む理由**：辺の和はまだ form factor ではなく **ベクトル**
（立体角上の方向の積分）で、ベクトル積分は領域の分割について加法的。つまり
6枚のペインは「4辺のループ×6」を同じ `vec3` に足すだけ。そして地平線クリッピング
（`ltcClip`＝この手法で唯一近似が入る場所）は **合計に対して1回だけ**適用する。

これは three の矩形1枚ルーチンを6回呼んで足すより**安いだけでなく正しい**：
ペインごとにクリップしてから足すと、地平線をまたぐペインすべてで補正が
二重に入る。1枚の窓の6ペインは全部同時に地平線をまたぐ。

拡散項は**同じ関数を単位行列で**呼ぶ。それは多角形集合の地平線クリップ済み
放射照度そのもの。昨日の「円盤の解析解」というフィットではなく、答え。

### 2. カーネルが窓になったPCSS（`shadow.js`）

半影とは、受光点から見た**光源自身のシルエット**と遮蔽物のシルエットの畳み込み。
2005年以降のPCSSは全部この文の上に立って、そのあと**こっそりシルエットを円盤に
差し替えてきた**。人がシミュレートする光源はランプで、ランプはだいたい円盤だから。
窓は違う。

カーネルが本当に光源なら、方立のある窓は部屋のあらゆる柔らかい影に**淡い筋**を
引かなければならない。そしてそれはコストゼロでできる——形からの点のサンプリングは、
**定数時間で内部の点を選べるかぎり**円盤のサンプリングと同じ値段だから。

```
1. BLOCKER SEARCH   開口のバウンディング矩形で
2. PENUMBRA SIZE    bound * gap（クランプは「角度のスケール」に戻して適用する。
                    切り詰めると別の窓の絵になるが、縮めれば同じ窓の小さい絵）
3. PCF              CDFで面積比例に**ペインへ**配る
```

**そしてデコリレーションを変えなければならない。これが今日いちばん細かい罠。**

前日までは毎回タップ螺旋を**ピクセルごとの角度で回して**いた。円盤は回転不変
なので、回してもサンプル位置が変わるだけで推定している形は変わらないから成立する。
**今日のカーネルは回転不変ではない。絵が入っている。**ピクセルごとに回すと
方立の筋が円環に塗り拡げられ、「単にノイジーなだけ」に見える*間違った*柔らかい影
になる。

正解はサンプル空間でデコリレートすること：単位正方形上の層化点列を、
ピクセルごとのオフセットで**トーラス的にシフト**する（Cranley–Patterson rotation）。
隣接ピクセルは同じ光源の**別の点**を使う——欲しかったのは元々これで、
誰も「回転したランプ」は欲しがっていない。

### 3. 光源の記述はやはり1箇所

`froxel.js` も motes も**1行も編集していない**。どちらも `softVis()` を
呼ぶだけで、光源の記述が1ファイルにあるから、シャフトの縁も塵も自動的に
窓のトレーサリーを受け取る。Day 037 で払った配当が今日も返ってくる。

## つまずき（記録用）

**GLSLテンプレート文字列の中にバッククォートを書いた。**今日いちばん間抜けな1時間。
シェーダは `` /* glsl */ `...` `` の中に書かれているので、ドキュメントコメントで
`` `dot(n,L)` `` のように識別子を囲むと**そこで文字列が終わる**。しかも一括で
剥がそうとしたスクリプトの終端検出が甘く、`vertexShader: /* glsl */ \`` 以降の
バッククォートを**全部**消して passes.js を破壊した。前日フォルダから復元して
編集をやり直した。教訓は2つ：シェーダ文字列内のコメントはバッククォートを使わない、
そして**一括置換の終端条件はファイル末尾で当たるものにしない**。

**辺のフィットは θ/sinθ ではなく θ/sinθ/2π。**流通しているフィットには両方あり、
2πを含まない方を貼ると全表面が6.28倍明るくなる。トーンマップが飽和するので、
**スケールのバグがシェイプのバグに見える**のが厄介なところ。

**T2 の符号。**three は `T2 = -cross(N, T1)` に「論文から反転。座標系の
handedness の違いか」というコメントを付けている。これは化粧ではない：反転を外すと
基底が左手系になり、全辺の外積が符号反転し、form factor が負になって
`max()` に食われる。**バグではなく「光が当たらない面」に見える。**

**遠い方のタブレットが真っ黒だった（30分）。**最初は roughness の問題だと思って
0.26 → 0.145 → 0.055 と下げていったが、同じ粗さでも黒いままだった。原因は
**釉薬の玉がタブレットに影を落としていた**こと。ライトは (0.395, 0.845, -0.362)
から来るので影は -x/+z へ伸び、玉を右前に置くと**その斜め後ろにある板を殴る**。
玉を 60cm 動かしたら直った。「シェーディングのバグ」を疑う前に `?pass=2` を
見るべきだった。

**傾きは選ぶものではなく解くもの。**タブレットの法線は `normalize(V + L)`
——ハーフベクトル——で、これが鏡面反射方向を開口の真ん中に落とす唯一の向き。
水平に寝かせた最初の版では、同じ板が窓から47度離れた**空の天井**を映して何も
出なかった。しかも**板ごとに解く必要がある**：2枚は3m離れていて視線が10度違うので、
共有法線（より原理的に見えた最初の修正）では遠い方が黒いままだった。
比較しているのは2つの粗さであって、狙いの比較にしてはいけない。

**平らな鏡が映すのは窓の一部**。板は幅2.4m・視距離10.6mで約0.20 rad を掃くが、
窓は 0.23 x 0.36 rad ある。つまり板は窓への**覗き穴**で、見えているのは
中央の方立と中連子が作る十字＝4ペインぶんのクロップ。全景を出すには板を
3m級にするしかなく、それは画面を板で埋めることを意味する。**クロップのまま
出すのが正解**と判断した（絵として読めるし、主張には十分）。

**幅1mの板は「壁」だった**（Day 037 と同じ再発）。半影の筋を見せたくて
ブレードを 0.34m → 1.05m に広げたら、奥の門を隠して画面が黒い矩形の列になった。
0.62m に戻した。**今日の主役は板が書くものではなく板が映すもの**なので、
ブレードは静かな縦のリズムでよい。

## 構図・トーン

- 光は1つ。フィルもアンビエントも環境マップも無い（Day 036 から継続）。
- **主題は2枚の漆板**。同じ物・同じ傾き・同じランプで、違うのは粗さだけ
  （0.050 と 0.125）。手前は窓が読める、奥は昨日のロゼンジに閉じている。
- **釉薬の玉**は「不十分であること」のために置いてある。板の隣に立って、
  球にできることの限界を示す＝今朝構図が変わった理由そのもの。
- **鉢**は拡散の証人。遠い側のターミネータが折り目ではなく帯。今日はそれが
  フィットではなく積分。
- 梁の裏・柱の前面はどれも直接光が**厳密にゼロ**。見えているものは全部 wash
  （Day 034・035 の機能が無傷であることの在庫）。
- Day 031 からのルール——**作品が中心に据えている物体（窓・絞りの板）は
  一度も映らない**——を継続。

## 検証（RUN.md の品質チェックに従って）

  - `?pass=1`（LTC・トレーサリーあり）：板の上に**方立と中連子の十字**。
  - `?pass=8`（Day 037 の representative point）：板が**真っ白な板**になる。

    「15%の誤差」ではなく「絵が別物」として出る。
  - `?pass=9`（トレーサリーを外した1枚の矩形・**同じ放射照度**）：明るい面と
    鋭い縁があるだけで十字が消える＝十字は石が作っている。
  - `?pass=0`（点光源）：全部が定規の縁。
- `?pass=7`（wash 単独）／`?pass=11`（return を切る）で Day 034・035 の
  経路が無傷であることを確認。
