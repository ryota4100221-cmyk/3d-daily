# Day 077 — The Waterline That Tells You Nothing

**再現元：uki by non Editions** — https://ukibynoneditions.com/
（青山のぞみ / non Editions が 2024年4月に立ち上げたライフスタイルブランド。
ブランド名の「uki」は **ウキウキ** と **浮き** の二重読みだと本人が言っている。
今日はその二つ目のほうを、言葉のあやではなく物理として読んだ。）

## 何を再現したか

**キー演出を1つに絞った**：「横スクロールで canvas がひとつ動く」。それだけ。
サイトは FV → コピー → 製品 → Collections/Archives → お知らせ → Stockist → フッター の
7セクションあるが、**再現したのは canvas 1枚と、それを動かしているのがスクロールだという事実**だけ。

分解すると、**幾何**だった。シェーダでもカメラでも入力でもない
（入力はスクロールだが、スクロールが動かしているのは波の位置ひとつで、
絵を決めているのは全部この幾何のほう）。

## 分解した装置 — 教えない喫水線

27隻の箱を浮かべる。**高さは全部 H = 1.000、密度は全部 ρ = 0.600。**
それだけ揃えれば、喫水は一意に決まってしまう：

```
T = ρH = 0.600   ——  27隻とも、例外なく
```

幅 b は 0.72 から 2.02 まで 0.05 きざみ、長さは 0.95 〜 2.73 のばらばら。
なのに水に入っている深さは **全隻 0.600000**（実測：直立している隻の喫水が
6桁まで 0.100000＝重心から水面までの距離。船底までは 0.600）。
だから水面は27隻を横切る**1本の直線**になる。

**その線は、どれが立っていられるかを一言も教えない。**

教えているのは、線を**横切る**寸法ではなく線に**沿う**寸法のほうだった：

```
GM = b²/(12T) − (H − T)/2        GM = 0  ⇒  b_c = √(6·T·(H−T)) = √1.44 = 1.200
```

この式に残っていないもの：材料、質量、長さ、水深、波の高さ、隻数。
残っているのは幅だけで、しかも**二乗で**入る。対する項には幅が一度も現れない。

### 書いていないこと

rig.js に「転覆」「復原力」「ロール角」「安定／不安定」に当たる判定は**一行も無い**。
書いてあるのは1つの操作だけ：

> 矩形を角度 φ 傾け、水平線を下ろしていって、線の下の面積が
> 排水すべき面積 ρbH に一致したところで止める。
> 止まった高さが喫水。**残った図形の重心が横へずれた量が、そのまま復原てこ GZ。**

Sutherland–Hodgman で水平線に切って、多角形の面積と重心を出す。20行。
GM も b_c も**画面の数字を検算するためだけに**書いてあって、何も動かしていない。

| 0.870 | −0.09488 | 113.0° |

| 0.970 | −0.06932 | 49.4° |

| 1.070 | −0.04099 | 35.7° |
| 1.120 | −0.02578 | 28.5° |

| **1.220** | **+0.00672** | **−3.2°** |
| 1.270 | +0.02401 | 0.0° |

- **1.200 を跨いだ瞬間に 0 になる。** 手前まで 28.5° あったものが、次の隻で消える。
- 0.870 の隻が 113° ＝ **横倒し（90°）も安定ではない**。横に寝たときの「幅」は H = 1.000、
  「高さ」は b = 0.870 なので、そこでもう一度 GM を計算すると負になる隻がいる。
  判定を書いていないので、こういう隻は勝手に90°を通り越して落ち着く。
- 1.170 だけ **逆側** に倒れた。倒れる側は決まっていない（熊手分岐なので符号は波が決める）。
  決まっているのは**大きさ**のほうだけ、という事実がそのまま絵に出た。
- 1.220 が40秒たっても **−3.2° 残っている**。しきい値のすぐ上は、
  戻るのにも時間が要る。**b_c の両側で時定数が発散する。**
  （だからページはプリロールしてから開く。波が通っただけの瞬間を写すと嘘になる。）

## 波について書いた式は1本だけ

`swell(x, front)` — 幅2.0・高さ0.10 の非対称な山ひとつ。
**上下（浮き沈み）も傾き（倒れ）も、この1本から読んでいる。**
高さがその隻の基準面を決め、同じ高さの**差分**が水面の傾きになって傾ける。
「波が浮体に何をするか」という第二の法則はどこにも無い。
GLSL 側も同じ文字列（`SWELL_GLSL`）を import しているので、
水面の形と船体の濡れている範囲が物理とずれようがない。

## つまずき

1. **喫水線が1枚も映らなかった。** 1枚目は海を不透明な板にしていたので、
   「線が船体のどこを切っているか」＝この作品の主題そのものが、
   ちょうど海に隠れる。**ビルドは通る。絵も破綻しない。ただ主題が無い。**
   海を α=0.60 にして最後に描き、インクの線は水面の**わずかに上**
   （`vW.y − wl ∈ [0, 0.034]`）に置いた。水が上から被さっても消えない位置。
2. **1枚目が全面シアンだった。** 水面を 140×90 で敷いたので画面が海で埋まり、
   生成りの紙が消えた。海を**有限の帯**にして、遠い縁をフォグで紙へ溶かした。
   uki は「紙の上のグラフィック」なので、世界ではなく帯でよかった。
3. **しきい値の目印が画面を斜めに切る黒い筋になった。** 水面に引いた
   `depthTest:false` の長い罫が全部の手前に出ていた。罫をやめて、
   b が 1.200 を跨ぐ位置に棒を1本立てるだけにした。
4. **`ρ` が `P` と表示された。** CSS の `text-transform: uppercase` が
   ギリシャ小文字を大文字 Ρ に変えていた。定数表だけ解除。
5. **透視だと「1本の直線」が1本に見えない。** 各隻を中心で z=0 に置くと
   長さがばらばらな分だけ手前の面の奥行きが変わり、画面上の喫水線の高さがずれる。
   **中心ではなく手前の面（z = 1.25）で揃えた。** 長さは奥へ伸びる＝
   「長さは効かない」が構図そのもので言える。

- engine/ からのコピー **0ファイル**、相対 import **0件**。
- 空カンバス誤診は今回は出なかった（budget=16000 の1回目で 100KB／閾値 60KB）。
