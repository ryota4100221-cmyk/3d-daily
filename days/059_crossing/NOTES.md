# Day 059 — 交差の投影 / Crossing Projection

再現元： **中央大学 スポーツ情報学部（仮称）特設サイト** — https://sdb.chuo-u.ac.jp/
（制作: 株式会社米 + IE3 ／ MUUUUU.ORG 2026-04-08 最高金賞 ／ SANKOU! 掲載）

1. スワイプファイルDBの実測行 — 「赤 `#DE2525` から青紫へ流れるグリッチ状のCGを
   左半分に敷き、右半分を紺 `#1E2939` の半透明パネルで覆う」「地の明度=中間色地」
   「カウンター的に流れる数字（等幅字形が必須）」「分散した3カラムタイポグラフィ」
2. 2026-07-30 の深掘り日報 — 制作サイド（IE3）が公開しているビジュアル原則
   **「データから立ち上がる幾何学的な形態」**、ブランドカラーは
   **「青と赤のグラデーション ＝ スポーツ領域とビジネス領域の交差」**、
   および **時間帯連動グラデーション（同一URLが時刻で違って見える）**
3. シェーダー使用は制作サイドの公開情報で確定（ライブラリは不明）

## 何を再現したか

キー演出を1つに絞った。**「青と赤のグラデーションで2領域の交差を表す」**の1行。

これを「2色を並べて中間色で繋ぐ」と読むと、ただのグラデーションになる。今日は
これを **投影のグラデーション** として読み直した。交差しているのは色ではなく、
**ものの見え方**のほうだ、と。

| | 左 | 右 |
|---|---|---|
| 色 | 青 `#2F6BFF` | 赤 `#DE2525` |
| 領域 | データ／ビジネス | スポーツ／身体 |
| 投影 | **正投影**（測る目） | **透視投影**（見る目） |
| 奥行き | 持たない。32本が1枚の図に重なる | 持つ。32本が扇に開く |

装置は幾何でもシェーダの模様でもなく、**カメラ**でできている。

## 分解した装置 — 交差の投影（crossing projection）

点群は1つしかない。32本 × 160サンプル = **5120点**の、接地のある波形
（立脚で跳ね、遊脚で沈む。正弦のままだと32本が綺麗に重なりすぎて、正投影側が
図ではなく模様になる）。この5120点が毎フレーム `Float32Array` に測り直される。

頂点シェーダは、その1つのワールド座標からクリップ座標を**2本**作る。

```glsl
vec4 wp = modelMatrix * vec4(position, 1.0);
float w = smoothstep(uCrossX - uCrossK, uCrossX + uCrossK, wp.x);
vec4 cO = uOrthoVP * wp;                        // 正投影
vec4 cP = projectionMatrix * viewMatrix * wp;   // 透視投影
gl_Position = mix(cO, cP, w);
gl_PointSize = uSize * uPix / max(0.34, gl_Position.w);
```

肝は `mix` を**同次座標のまま**やっていること。透視除算の前に混ぜるので、
`w = 0.4` の点は「4割だけ奥行きを持つ点」という、どちらのカメラにも属さない
場所に落ちる。だから左半分と右半分は「2枚の絵を並べたもの」ではなく、
**同じ5120点の同じ瞬間**であり、継ぎ目は線ではなく勾配になる。

副産物が2つ出た。どちらも書いていないのに出てくる。

- **点の大きさを一度も書いていない。** `gl_PointSize` は同次 `w` で割っているだけで、
  正投影側は `w = 1` なので粒が一定になり（＝図の目盛りになり）、透視側は
  `w = -z` なので奥ほど小さくなる（＝空間になる）。遠近の有無が、
  分岐ではなく除算1つから出ている。
- **罫線も同じ `mix` を通る。** 後ろに立てた1枚の方眼は、左では図のグリッド、
  右では奥へ逃げるパースの線になる。ここを別処理にした瞬間、装置は1つでなくなる。

## 時間帯連動

再現元の「同一URLが時刻で違って見える」は、色ではなく**交差の位置**に効かせた。
`uCrossX = 0.74 · sin(2π · JST位相)`。交差点は1日で画面を1往復する。
朝は交差が右に寄って画面の大半が図（青）になり、夕方には左へ抜けて大半が
空間（赤）になる。端に停めないのは構図の都合で、**片側が消えた瞬間、
この装置は「2つのカメラ」ではなく「1つのカメラ」に戻ってしまう**から。

時計は実行環境のローカルではなく **JSTに固定**した。クラウドで撮ると UTC になり、
「日本の朝」のはずの絵が「日本の夜」で出てくる（この連載で1度やっている）。

## 数字が飾りにならないようにしたこと

下段のカウンターは絵と**同じ表**から引いている。`ORTHO 3296 / PERSP 1824` は
5120点を交差の重みで数え直した実数で、`MEAN / PEAK` は表の統計そのもの。
別々に計算した瞬間、数字は「等幅で信頼っぽく見せる装飾」に落ちる
（等幅＝実測の記号、というのは Alethia の回で拾った話）。

## 今日ひっかかった罠

`scripts/shot.mjs` の空カンバス閾値（既定 110KB）を**そのまま持ってきたのが間違い**だった。
今日は DOM に濃いグラデーションのヴェールを敷いているので、canvas が1画素も
描けていなくても PNG が **459KB** 出る。実描画は 827KB。閾値 110KB では
「空カンバスなのに合格」が通り、実際に1枚それを掴んだ（カウンターが `0000` と
`00:00:00` のまま焼き付いていたので気づけた）。

**教訓は Day 042 と同じで、今日また踏んだ**：空カンバス判定のバイト閾値は
canvas 以外の高周波成分を足した日に必ず貼り直す。今日は `SHOT_MIN=600`。
そして DOM のカウンターが初期値のまま写っている1枚は、それ自体が
「rAF が1回も回っていない」の証拠になる——数字を画面に出しておくと、
プレビューが自分で自分の不合格を申告してくれる。
