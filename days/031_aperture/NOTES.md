# Day 031 — Loop 04 · 光の体積「Aperture」（ループ＆深化 / ボリュメトリック）★★★★★

## 狙い

30日間、この企画が描いてきたものは**すべて「面の上」で起きていた**。
Day 028で自前のディファードレンダラを建て、029でSSR、030で動きを解禁したが、
描いていたのは最後まで**サーフェス**だった。

今日の主題は**面と面のあいだ**——空気そのもの。
視線に沿ってレイマーチし、48回「この点に光は届いているか」を問い、
**面では絶対に描けないもの＝光の筋そのもの**を返す。

Day 030のNOTESに自分で書いた宿題「反射の**厳密な**再投影：hit点の深度から速度を作り直す」も、
今日ここで**別の形で回収**した（後述 §3）。速度バッファは面の量であって、
面の手前の霧の量ではない——という、029・030が2日連続で逃げた問題である。

## 新しく入れた技法（前日までの自分から1段）

### 1. 自前の「線形」ライト空間深度マップ（パス0・新設）

three はこのライトの影マップをすでに描いている。それでも2枚目を描く。理由は意地ではない。

- three の影マップは**「面のピクセル」ごとに1回、ライティングマテリアルの内側で**
  問われる前提の作りで、`shadow.map` も `shadow.matrix` も**ライトのuniform**として
  ライティングシェーダに配られる。今日の問い手は**どの面にも乗っていない点**を
  1ピクセルあたり48回問う、ライティングマテリアルですらないフルスクリーンシェーダ。
- しかも three は深度を**投影空間で比較する用に**梱包している。マーチが欲しいのは
  **自分で計算した距離とそのまま比べられる素の線形距離**。

→ 光方向を向く `OrthographicCamera` 1台 ＋ float 1本。頂点シェーダで `-view.z`
（正射影なのでこれがすでに線形）を書き、`/uLightFar` で正規化するだけ。

**クリアは白（=far）**。「ここには何も遮るものが無い」がシルエット外の全テクセルの
正しい答えで、黒でクリアすると**ホール全体が影になる**。

比較は**ワールド単位で**やる（`m * uLightFar` してから引く）。52ユニットのレンジの
何分の一、というバイアスは誰にも推論できない。7cmは7cmである。

**`scene.overrideMaterial` は使えない**（Day 030はper-object行列が理由、今日は別の理由）。
このパスは**オブジェクトを飛ばす必要がある**：バックドロップはライトの向こう側に
立っているので、ライト深度マップに入れると**ホール全体の最近接オクルーダ**になり
シーンが丸ごと影に沈む。`castShadow` をシーン自身の「これは光を遮るか」の宣言として
使い、push/pop で拾う。床も除外（この作品に床より下の物は無い）。

### 2. レイマーチ単散乱（ハーフ解像度・48ステップ）

視線を G-buffer の深度まで進み、各ステップで

```
L += T · σ · vis · p(θ) · dt ,   T *= exp(-σ·dt)
```

を積む。σ=密度、vis=ライト深度マップ、p=Henyey-Greenstein 位相関数（g=0.70、前方散乱）。
返すのは**入射散乱光と透過率の2つ**で、合成は `beauty·T + inscatter`。

安く・ノイズに見えなくするための3点：

- **ハーフ解像度**。媒質は**シルエットを持たない**ので、画面内で唯一
  アンダーサンプルしても誰も気づかない信号（ただしアップサンプルが深度を知っていれば。§4）。
- **8×8 Bayerの秩序ディザ**。マーチはN点からの積分推定で、全ピクセルが同じ位相で
  始めると誤差が**同心リング**になる。ブルーノイズの方が良いが、Bayerはテクスチャ0本で
  誤差が**構造化されている**＝時間フィルタが最も得意とする形。毎フレーム黄金比で回す。
- **`sampler3D` のノイズ体積（この企画で初の3Dテクスチャ）**。GLSLの値ノイズは
  1回8ハッシュ＋7ミックス。内側ループで48回×2オクターブ回すと死ぬ。
  32³にランダム値を詰めて `LinearFilter` + `RepeatWrapping` にすると、
  **ハードウェアの三線形補間がそのまま値ノイズ**になり、1フェッチで済む。
  さらに、安い解析項（高さ・半径フェード）で**ノイズフェッチを拒否権付きにする**：
  天井に向かうレイは大半のステップを「そこに無い空気」に費やしている。

### 3. 「散乱重心」での厳密な再投影 ＝ Day 030 の宿題

速度バッファは**面**を語る。面の手前の霧は**その面ではない**。
面のモーションベクタで霧の履歴を戻すのは単純に誤答で、これは
Day 029 のSSRが踏み、Day 030 が「フィードバックを手放す」ことで**逃げた**のと同じ穴。

今日は正面から解いた。鍵は、**媒質はワールド空間で静止している**こと——
だから**任意のワールド点**は前フレームのビュー射影行列で**厳密に**再投影できる。
問題は「どの点を」だけになる。

答えは**散乱の重心**：`Σ w·t / Σ w`（重み w は各ステップの入射散乱寄与）を積んでおけば、
**このピクセルの光が実際に来た距離**が出る。それを再投影する。

- 光芒を貫いて見ているピクセル → 光芒の距離で再投影される
- 澄んだ空気ごしに壁を見ているピクセル → 壁の距離で再投影される

`outAux.r` に重心の**現フレーム視深度**を書いておき、次フレームは
「今の重心を**前**フレームのビュー行列で測った深度」と突き合わせて棄却する。

**ただし深度棄却だけでは足りない**。スリットの光の筋が通り過ぎると、
ジオメトリは1ミリも動かないのに radiance だけが変わる——深度では見えない変化。
そこで**不一致そのもので棄却**する：`|L_cur − L_hist| / (L_cur + L_hist)` が
大きいピクセルはフィードバックを落とす。静かな隅は積分して収束し、
筋が抜けた場所は即座に描き直される。

### 4. 深度考慮（バイラテラル）アップサンプル

ハーフ解像度のツケはここで払う。単純なバイリニア拡大は、**唯一みんなが見る場所**＝
シルエットで破綻する。壺の口をまたぐ4テクセルは「12mの光る霧」と「30cmの磁器」という
まったく別の答えを持っていて、平均すると**画面中の全エッジに明るいハローが出る**。

→ 通常のバイリニア重みに、**深度の一致度** `exp(-|dH - dF| · k)` を掛ける。

**罠（実装しかけて気づいた）**：各タップの深度をフルres G-buffer から引き直そうとすると、
ハーフresテクセルの中心は**フルresテクセルのちょうど境界**に落ちる。Nearestの境界は
コイントス（マーチ側は varying 補間、合成側は算術で同じ uv を作るので、
最下位ビットが違えば別テクセルを拾う）。
**使った側が書き留める**のが正解で、`outAux.g` にマーチが実際に使った `dLin` を出した。
これで重みが「ほぼ常に正しい」ではなく**厳密に正しい**になる。

### 5. TAAは「プラットフォーム」になった（Day 030から無改造）

Halton(2,3)ジッタ・速度バッファ再投影・深度棄却・YCoCg分散クリップ。
今日は**2つ働く**：20本のフィンと130粒の塵を1spp でアンチエイリアスする本業と、
**ボリューム側の履歴フィルタの上にもう1段乗って、光芒に残ったディザ模様を最後に消す**副業。
（`?pass=5` の生バッファではディザの網目がはっきり見えるが、合成では消えている。）

## 造形の話（レンダリングでは直せないこと）

- **「光の筋」は差分現象である**。初版は密度0.058で、遮蔽物の無い画面右半分が
  **のっぺりした明るい壁**に積分された。光芒は**周囲の霧が暗いから光芒**であって、
  霧を濃くすると消える。0.034まで落とし、代わりに `scatter` を上げた。
- **光の筋には上流にスリットが要る**。open hall にリングを置くと影は**1個**しか出ない。
  「大きな明るいワッシュに、彫刻の下の暗い楔」——光の筋の**補集合**である。
  そこで**ライトと部屋のあいだ**（12ユニット上流、画角外）に24枚のスラットの
  スクリーンを立てた。位置と姿勢は手打ちせず `LIGHT` から導く（`lookAt(target)` で
  ローカル+zがビームに一致するので、切り出される刃は**構造的に平行**）。
  ——**作品名の由来である物体が、ついに一度も画面に映らない**。
- **スクリーンは滑らせる**。静止した櫛は静止した刃を描き、10秒で「描いた背景」に見える。
  1ピッチ10秒でスライドさせると、ホールが**起きている出来事**になる。ラップを掛けて
  移動量を1ピッチ以内に抑える（前フレーム行列機構が巨大なジャンプを見ないように）。
- **26本のフィンは「檻」になった**。20本・高さ2.9に落として初めて列柱として読めた。
  フィンの**半径方向の厚み**（0.185→0.110）が効く：斜めから入る光に対する実効遮蔽幅は
  接線幅ではなく**厚みの方**で決まっていて、ここが太いと円筒が二重の壁になって
  内側に何も届かない。
- **スラットはライト空間マップを縦にも覆い切る**。`?pass=7` で見て、当初17mの
  スラットがマップの中央帯しか覆っておらず、上下の白い帯（=遮るもの無し）が
  意図しない明部を作りうると分かった。34mに伸ばして解決。**自分の影マップを
  1枚絵で見る手段を持っていなかったら気づかない類のバグ**。

## ハマった点（次の自分への申し送り）

- **バイアスの単位**。最初 `step(d - 0.035, m)` を正規化深度で書いていた。
  レンジ52ユニットに対する0.035は**1.6メートル**。単位を持たない定数は嘘をつく。
- **Bayerの再帰の重み**を書き間違えて値域が[0,1.31]になっていた。
  正しくは `bayer2(0.25a)*0.0625 + bayer2(0.5a)*0.25 + bayer2(a)`。
- **GLSL3のフラグメントで `sampler3D` は精度宣言が要る**（`precision highp sampler3D;`）。
  three が入れてくれるのは `sampler2DArray` まで。
- three は GLSL3 のとき `pc_fragColor` を**出さない**（`WebGLProgram` の
  `( glslVersion === GLSL3 ) ? '' : 'layout(location = 0) out ...'`）。
  だから `layout(location=0) out` を自分で書くMRTと衝突しない。Day 029以来
  経験的に使っていたが、今日ソースで確認した。
- **ヘッドレスの空カンバス判定は正常値の1/4**（Day 030の申し送り通り）。
  この作品は1600x1000で約1.6MB。今回は4回中1回もリトライに落ちなかった。
- **`?pass=` は飾りではない**。今日は `?pass=7`（ライト深度マップ）が
  スラットの縦不足を、`?pass=5`（生の入射散乱）がディザの残りを教えた。
  **ビルド成功≠描画成功**の次に**合成成功≠各パス正常**がある。

## デバッグ用URLパラメータ

- `?t=12.5` — シーン時刻をピン留め（速度0＝TAAは完全収束、ブラーは消える）
- `?phase=52` — 止めずに52秒目から。刃の位相と列柱の回転位相で構図が変わるので、
  **どの瞬間を撮るかは設計**（この作品のpreviewは phase=52）
- `?pass=1..8` — Composite / Beauty(媒質なし) / Normals / Velocity /
  In-scatter / Transmittance / **Light depth** / TAA off

## 次に試したいこと

- **散乱の多重化**：今日は単散乱のみ。霧の中の霧（2次散乱）を近似すると
  影側の空気が真っ黒でなくなる。安いのは「透過率に比例した環境色を足す」。
- **フルーステッド・ボクセル（froxel）化**：ピクセルごとに48ステップではなく
  視錐台を 160×90×64 の3Dテクスチャに1回焼いて全画面で読む。
  ボリュームが**再利用可能な資産**になり、透明物にも使える。
- **ライト深度マップの絞り込み**：今日は霧の存在範囲を覆うため halfSize 17 で、
  彫刻は `?pass=7` の中央にごく小さく写っている（=フィンの影が粗い）。
  カスケード2段か、霧用と面用でマップを分けるべき。
- **ブルーノイズのディザ**：Bayerは構造化誤差が残る。1枚の128²ブルーノイズ + 黄金比回転。
- **Day 030 の残り宿題**：TAAのCatmull-Romシャープ化、モーションブラーの
  タイル最大速度（McGuire）、同じG-bufferからのコンタクトシャドウ。
