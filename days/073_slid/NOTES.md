# Day 073 — The Distance the Shadow Slid

再現元：**融点 Gallery and shop**（つくば市が運営する福祉施設の工芸ギャラリー＆ショップ）
<https://yuten.city.tsukuba.lg.jp/>

## 何を再現したか

あのサイトの FV は、青灰 `#85AFD8` の背景に白い階段状の展示台を組み、その上に
編み物のボタン・瓶詰めのジュース・卵パック・藍染めの布を **俯瞰で並べた1枚の物撮り**である。
DB の実測値は「ページの色は全部この写真から来ていて、CSS側の設計色は1.5%しかない／
写真の色が21.3% ＝ **色は撮って作っている**」と言っている。

再現したのは商品ではない。**「真上から撮る」と決めた瞬間に画面に起きること**のほうを再現した。

キー演出は1つに絞った。それが何でできているかを先に言葉にすると——
**幾何（正投影）と光（影）だけ**。カメラは動かず、入力も受けず、時間は光の仰角にしか触れない。

## 分解した装置 —— 影がすべった距離（the distance the shadow slid）

正投影で真下を見ると、高さはシルエットに入らない。床の厚さ 6 mm の円盤（D1）と
高さ 78 mm の円柱（D2）は、**同じ円**として映る。輪郭が一致するだけではない。
天板の法線はどちらも `(0,1,0)` で光源は1つなので、**明るさも 1 ピクセルも違わない**。

高さを画面へ運ぶ経路は、1本しか残っていない。

```
s = h · cot θ          θ = 太陽の仰角
```

だから `rig.js` には「立体」も「奥行き」も無い。あるのは
**平面上の footprint と、その平行移動の帯**だけである。
床に立つ柱は下端 0 から上端 h まで連続に影を落とすので、影は
点ではなく帯（掃引）になり、結果として物体に貼り付いたまま伸びる。

半影も同じ式から出る。光源の見かけの半径を α とすると

```
w = 2·tan α · Δh / sin θ
```

Δh は「その点に影を落とした高さ」なので、**接地点は必ずシャープで、天辺の影がいちばんボケる**。
これを別に書いた覚えは無い。掃引の最小を与える t\* を求めれば、Δh は t\*/cot θ として落ちてくる。

## なぜホリゾント（cyclorama）なのか

壁と床の入隅があると、そこに1本の線が出る。線が出ると人はそれを水平線として読み、
高さをそこから推定しはじめる。融点の FV は地を1色のベタで塗り切っていて、線が1本も無い。
**奥行きの手がかりを影だけに絞るための、いちばん安い装置**である。
だからここでも地は `#85AFD8` の1面だけで、罫も水平線も置いていない。
版面に引いた線は、下の表の中の1本も無い。

## 版の上で何を言わせたか（15本の角柱）

| | 何が同じか | 何が違うか |
|---|---|---|
| **段** S1–S5 | 天板の長方形が5枚とも同一 | 高さ 18 / 40 / 62 / 84 / 106 mm。影のすべりが**等差数列**になる |
| **同じ円** D1・D2 | 輪郭・明るさが完全一致 | 6 mm と 78 mm。13倍の差は影の位置にしか無い |
| **積む** K1・K2 | 真上からは2つの正方形が重なった**1つの輪郭** | 影の縁は2本出る |
| **瓶** T1 | — | この版でいちばん小さいシルエットが、いちばん長い影を持つ |
| **反証** P1・P2 | 同じ帯に並べて逆から言う | P1 は面積最大で影がほぼ無い（10 mm）、P2 は 1/3 の面積で影が12倍すべる（100 mm）。**面積は高さについて何も言わない** |

## 書いていないのに出てきたもの

1. **影は差しか測っていない。** K2（50→90 mm の板）が K1（50 mm の台）の天板に落とす影は
   40 mm ぶんしかすべらない。同じ板が台から外れて床に落ちる影は 90 mm ぶんすべる。
   同一の板の影が、**受け面が変わった瞬間に 2.25 倍に伸びる**。
   受け面の高さ y\_r を式から引いているだけで、「台の上」「床の上」と書いた行は無い。
2. **θ が高いと版が平らな切り紙に戻る。** cot θ → 0 で全部の高さが 0 に潰れる。
   逆に低すぎると段の影が隣の段に届いて互いを食う。
   **全部が同時に読める θ の帯は狭い**（ここでは 38°〜66° に置いた。下限は
   「段の影が隣の段に届かない角度」で決めていて、美意識ではなく間隔 145 mm から出た数字）。
3. **明るさの差が1つも無い。** 真上から見える面は全部水平なので、法線が全部同じ。
   影を消すと、この絵は**白い紙を青い紙に貼っただけ**になる。

## 捨てたもの

- 商品（編み物のボタン・瓶詰めのジュース・卵パック・藍染めの布）。
  位置と個数だけ借りて、中身は円柱と角柱に置き換えた。
- ロゴ「融点 Yu-ten / Gallery and shop」と Jost / こぶりなゴシックの実書体
  （外部フォントはこの実行環境から 403 で引けないので、組み方だけ system の欧文＋等幅で借りた）。
- FV 以外の全セクション、スクロール、写真。
- 入力。この装置は誰も見ていなくても成立していたほうが正しい。
- **シャドウマップ。** 使うと「影が h·cot θ である」ことが測定結果ではなく偶然になるし、
  接地部のボケ幅も嘘になる。影は解析で置いた。

## つまずき

1. **影の縁が階段状になった。** 最初は掃引の帯を 10 点でサンプルして max を取っていた。
   1枚撮って見たら段になっていた——**帯を離散化するのは、装置が生む連続量を10段に量子化すること**で、
   刻みを増やすのは負け。閉じた形で解き直した：`sdf` は凸、`t ↦ q − t·d` はアフィン、
   よって `f(t) = sdf(q − t·d)` は t について凸。凸なら三分探索が使える。
   10反復＝20評価で階段は消え、縁は真の包絡線になった。
   おまけに最小を与える t\* がそのまま「その点に影を落とした高さ」なので、
   半影幅を**点ごとに正しく**決められるようになった（副産物のほうが本体より良かった）。
2. **白い展示台が灰色に、地の青が沈んだ。** `new THREE.Color('#f2f0ea')` は
   ColorManagement が有効なら**構築した時点でリニアに落ちている**。
   そこへ `convertSRGBToLinear()` を重ねていたので二重に暗くなっていた。構築するだけでいい。
   `#85AFD8` を指定して `#85AFD8` が出るまで、実描画を3枚撮った。
3. **露出を θ の中央で決めたら、いちばん見せたい低い側で沈んだ。** 影がいちばん長くて読めるのは
   θ が低いときなのに、そこで展示台が灰色になる。露出は θ=44° の水平面が albedo に写る位置に置き直し、
   高い側は 0.88 から上だけ寝かせる肩を1本入れた。物撮りは露出を1点で決める、という当たり前のことだった。
4. **この日はバイト数ガードが効かない構図だった。** 地はベタ1面、映るのは白い角柱と影だけ＝
   PNG にとって理想的な圧縮対象で、粒子が無ければ実描画でも数十KBまで落ちる。
   地に敷いた ±0.0125 の紙目は見た目のためだけではなく、**空カンバス（47KB）と
   実描画（520〜640KB）を10倍以上引き離すため**でもある。閾値は 300KB に置いた。
