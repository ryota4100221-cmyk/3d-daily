# Day 035 — Loop 08 · 光が一周する「Return」（surface → volume injection）★★★★★

## 狙い

Day 034 は自分の NOTES に、その日いちばん大きな穴を2つ書き残した：

> - **wash の可視性項。** ボリュームは面を知らないので、板は裏の空気からも光を受け取っている。
> - **面 → 空気の注入。** 今日は空気→面の一方通行。明るい床が上の空気を照らし返せば、ようやく閉じる。

この2つは、実は同じ1文を別の角度から言っている。Day 034 までの光は
**ランプ → 空気 → 面 → カメラ** という一本道で、一本道は「光輸送の解」ではなく
**たまたまカメラで終わる効果の連鎖**でしかない。現実の部屋が現実の部屋に見えるのは、
光が*一周する*から——シャフトが降りて、白い床で跳ね返り、その上の空気を照らし返し、
ランプの光が絶対に届かない庇の**裏側**を照らす。

今日はその回路を閉じる。閉じられる場所は1つしかなかった：
**injection パス**——3日間ずっと「ランプが何をしているか」だけを聞かされ、
「部屋が何を返しているか」を一度も聞かれなかったパス。

## 新しく入れた技法

### 1. 面 → ボリュームへの注入（今日の主題）

froxel の injection は各セルに「**光源**がここに何を置いたか」を聞いてきた。
今日はそれに加えて「**部屋**がここに何を置いたか」を聞く。答え方はこの連載の流儀どおり、
**スクリーン空間で、すでに存在するバッファから**：

```
セル p を画面に射影 → その画素のまわり7タップ
各タップで G-buffer から法線と深度 → 面パッチの世界座標 sp と向き n
composite の radiosity バッファから そのパッチの射出輝度 B

E(p) = Σ B · cos(n, sp→p) · 1/(1 + d²/r0²) · phase(θ)   /  ヒット数
S   += uRetGain · σ(p) · E(p)
```

点↔パッチの**フォームファクタ**そのもの（面積項は gain に畳んである）。
**新しいパスはゼロ。新しく描くバッファもゼロ。**すでに4タップ取っていたシェーダに
7タップ足しただけ。

**位相関数を掛ける**——ここが Day 033 の多重散乱と違う点。2バウンス目の光子は
来た方向を忘れているから拡散だったが、**床から来た光は方向を持っている**（既知のパッチから
既知の向き vd で届く）。ただし床は広い面光源で立体角が大きいので、鋭い前方ローブは嘘になる。
ビームの g=0.62 に対して **g=0.24**。

### 2. composite に radiosity アタッチメントが増えた（attachment 1）

「面がどれだけ光を返すか」を知るには、その値がどこかに書かれていないといけない。
composite は毎フレーム画素ごとに `beauty + bounce`（= 面がカメラへ送り出している輝度、
まだ手前のミストに削られる前）を計算していて、**それを使い捨てていた**。
今日はそれを2枚目のカラーアタッチメントに書く。

これは Day 034 が G-buffer にアルベドを足したのと**まったく同じ形の変更**で、
2日続けて「足りなかったのはパスではなくチャンネルだった」という結論になった：

| | 増えたチャンネル | 答える質問 |
|---|---|---|
| Day 034 | G-buffer attachment 2 = albedo | この面はこの光を**どれだけ持って帰るか** |
| Day 035 | composite attachment 1 = radiosity | この面はそれを**どれだけ返すか** |

**画面に出る色ではなく `beauty + bounce` を書く**のが重要で、画面の色には空気自身の
in-scatter が足されている。それを空気に返したら**媒質が自分自身を二重計上する**。

### 3. wash のスクリーン空間・可視性マーチ

Day 034 の宿題その1。ボリュームは面の存在を知らないので、薄い板は**自分の裏側の空気**からも
光を受け取っていた。昨日の防御は「法線方向に 40cm 踏み出して祈る」だけで、
NOTES にも「これは緩和であって解決ではない」と書いてある。

**解決をボリュームに入れるのは2重に間違い**だった。2.36M セルに1チャンネル足して
25cm 解像度で持つのは高すぎるし、そもそも質問の両端（着色点と タップ点）は**画面上にある**。
そして composite は、その両端と、その間にある全ての面の深度バッファを、すでに持っている。

なので**線分 p→q を5ステップでスクリーン空間マーチ**して、G-buffer の線形深度と比較する。
面の向こう側に回り込んだタップは E に寄与しない。Day 028 の SSAO（ビュー座標を再構成して
深度と比較）と Day 029 の SSR（画面上をレイマーチ）を、3つ目の質問に向けただけ。

2つの細部：

- **遮蔽されたタップは重み w には残す。** 早期 return して平均から除外すると、
  壁に押し付けられた面が開けた場所の面と**まったく同じ明るさ**になる。
  暗くなることが可視性項の可視の効果そのものなので、E に 0 を足して w には c を足す。
- **`thick`（3.2m）** は「深度バッファは立体ではない」という定番の白状。
  最近接面より4m 奥のサンプルは、たぶん*別の物体*の裏であって、この物体の中ではない。

そしてこれが効いた結果 **BOUNCE.bias を 0.40 → 0.22 に下げられた**。
遮蔽が本物になったので、bias は「板を跨ぐ」ためではなく「自分の深度量子化を跨ぐ」ためだけに
必要になった。gather は**石に実際に触れている空気**を読めるようになった。

### 4. ループが閉じた、という構造

パイプラインの依存関係が今日**フレームをまたいで循環する**：

```
stage 5 (composite) → radiosity を書く
   ↓ 次フレーム
stage 3 (injection) → radiosity を読む → ボリュームを書く
   ↓ 同フレーム
stage 5 (composite) → ボリュームを読む
```

循環しているのは**そうあるべきだから**で、現実の部屋の光がまさにこれ。
解き方は Day 033 が空気の多重散乱に使ったのと同じ——**1フレーム1回のヤコビ反復**、
テンポラルフィルタが級数を積む。パイプラインの順序は**1行も変えていない**。
ループは時間を通って閉じる。

Day 033 の反復は「空気だけ」で閉じていた（ループに入るエネルギーはランプが空気に入れた分だけ）。
今日それが**面を含む**ようになったので、フレームが収束する先は霧のバンクではなく**部屋**になった。
同じ機械で厳密に大きい作用素を解いている——というのが、この機械をこう作ってきた理由そのもの。

## つまずき（記録用）

**タップ半径は1つでは足りない。** 最初の実装は Day 034 の hemisphere gather と同じ発想で
「セルの投影画素のまわり 1.3m の円に4タップ」だったが、これは**天井を照らせない**。
今日の主題である庇の裏は、それを照らす床の**3〜4m 上**にある。壁際の空気を拾うサイズの円は
床に届かず、床に届くサイズの円は近くの全部を跨いでしまう。
**内側3タップ・外側3タップの二重リング＋中心1タップ＝7タップ**にして解決した。

**r0（逆二乗のソフト化半径）は安全装置ではなく近似の補正だった。** 点↔パッチは 1/d² で落ちるが、
**面は落ちない**——無限に広い明るい床からの放射照度は1mでも4mでも同じ。7タップの
スクリーン空間ギャザーは遠方の面積をまったく回収できないので、r0 を 1.05 → 1.80 に広げるのが
いちばん安い正直な補正だった。

**gain は 0.62 では何も起きなかった。** 直接項が `uScatter(2.15) · σ · phase`
なのに対し、戻り光は `gain · σ · E` で E ≈ 0.15 程度。つまり最初の設定では
戻り光はビームの in-scatter の **4%** で、絵の上では存在しないのと同じだった。
シャフト直下の空気で 30〜40% になるところまで上げて（最終 6.0）、ようやく
「床の形が天井に出る」ようになった。ループゲインは
`(wash 0.235 × albedo 0.82) × (戻りの寄与率)` で 1 を大きく下回るので発散はしない。

**構図：水平な板は、下から見ても板に見えない。** 最初は庇を水平に置いたが、
カメラ高さ 1.3m から見える「裏側」は**視角2度の帯**でしかなく、今日の主役が
髪の毛のような線になってしまった。**14度だけ傾けて奥へ下げる**と、同じ板が
**8度分の面**をレンズに向ける。傾ける向きは重要で、手前を上げて奥を下げる
（＝カメラから遠ざかりながら降りる）でないと裏面がカメラから逃げる。

## 構図・トーン

- 光は1つだけ。フィルは1つも無い（Day 034 から継続）。
- **apron（明るい床）だけが白く、周りの床は暗い。** これが決定的で、床全部が白いと
  戻り光は「アンビエント項」と区別がつかなくなる。天井に出るのは apron の**形**でなければ
  意味がない。
- 庇の裏・jamb の面・pier は、どれも**直接光の項が厳密にゼロ**。
- 直接光に当たっているのは apron と鉢と小石だけ。**比較対象として残した**。
- Day 031 からのルール——**作品が中心に据えている物体（絞りの板）は一度も映らない**——を継続。

## 次に試したいこと

- **戻り光の可視性。** 今日いちばん大きな穴が、また1つ隣に移動した。スクリーン空間の
  ギャザーは「カメラから見える面」しか見えないので、セルから見て壁の裏にある床にも
  照らされうる。距離と cos で稀にはなっているが、原理的な保証はない。
- **フレーム外の面が消える。** 画面外に出たパッチは寄与を止める。全てのスクリーン空間手法に
  かかる税金で、逃げるならボリューム側に radiosity をキャッシュするしかない。
- **拡散カーネルの多重解像度化**（Day 033 からの持ち越し）。1.15m 固定は
  「近くの細かい滲み」と「部屋全体のかぶり」を同じ半径で扱っている。
- **ライティング全体を遅延へ。** アルベドと radiosity が揃った今、three のマテリアルを捨てて
  直接光も自前で解けば、直接光・wash・戻り光が同じ単位で語れるようになる。
- **モートが体積に注入し返す**（Day 033 からの持ち越し）。
