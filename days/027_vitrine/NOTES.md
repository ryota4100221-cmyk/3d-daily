# Day 027 — Vitrine：Awwwards再現 / 無限サーキュラーギャラリー（R3F）

★5 / Week 4 — Composition & Polish（No.27「Awwwards再現 — 受賞サイトのキー演出を1つ分解して再現」）

## 狙い

カリキュラムの指示は「受賞サイトのキー演出を**1つ分解して再現**」。
選んだのは Awwwards / Codrops 系で何度も受賞・掲載されている定番、
**infinite circular gallery（無限サーキュラーギャラリー）** ——
円弧に沿って並んだ画像の帯を、ドラッグとスクロールで無限に流し、
**移動速度そのものが画像を歪ませる**あの演出。

再現にあたって「見た目を真似る」のではなく、**演出を構成する4つの部品に分解**して
それぞれ自分の手で書き直すことを課した：

1. 円弧レイアウト（arc layout）
2. 無限ラップ（infinite wrap）
3. 慣性トランスポート（inertia / auto-drift）
4. 速度駆動ディストーション（velocity distortion）

その上で、26日続けてきた monaka トンマナ（紙・墨・テラコッタ／余白／英字タイポ）に
完全に置き換えている。写真は1枚も使わず、**展示物そのものを手続き生成**した。

## 使った技法

### 新技法① — 本プロジェクト初の「テクスチャ」。Canvas2Dで刷った10枚のポスター

Day001〜026 は26日間**一度もテクスチャを貼っていない**（全部GLSLとマテリアルで面を塗ってきた）。
ギャラリーは画像がないと成立しないが、画像をフェッチすればオフライン安全の原則が崩れる。
そこで `plates.js` で **Canvas2D にエディトリアル・ポスターを10枚描き、`THREE.CanvasTexture` として上げる**。

- 10種のコンポジション・システム（同心アーク／ドットグリッド／バー／分割円／波線／
  ハーフトーン／リング／ブロック／等高線／スラッシュ）を手続き描画
- `mulberry32` のシード付き乱数で**毎回同じ絵**になる（headlessプレビューが再現可能）
- 地色・図色・差し色の10配色を、紙／墨／砂／スレート／テラコッタから組む
- **副産物として「troikaを使わない鮮明なWebGL内タイポ」が手に入った**。
  このプロジェクトで白画面事故を何度も起こしてきた `<Text>` を使わずに、
  ポスターの見出し・キャプション・ノンブルが全部くっきり出る。Canvas2Dの `letterSpacing` で
  トラッキングも効く（非対応エンジン向けに手動アドバンスのフォールバックあり）
- 紙のグレインは **256pxのノイズタイルを `createPattern` で `overlay` 合成**。
  最初 `putImageData` で書いたら**全面が灰色ノイズに置き換わった**——
  `putImageData` は `globalCompositeOperation` も `globalAlpha` も一切無視して
  ピクセルを直接上書きする（アルファ12を書き込むので絵ごと透明になる）。
  合成したいノイズは必ず「別canvasに焼いて `drawImage`/`fillRect` で戻す」。

### 新技法② — 円弧レイアウト：1本の半径式が y・z・回転を全部決める

参照実装から「これは盗む価値がある」と判断した核心。
直線に並べるのではなく、**ビューポート端でちょうど `bend` だけ沈む円**を解いてその上に乗せる：

```
R = (halfWidth² + bend²) / (2·bend)
drop  = R − √(R² − x²)
theta = asin(x / R)
```

x=0 でオフセット0（中央は無歪み）、x=±halfWidth でちょうど `bend`。
**画面サイズごとのチューニングが要らず、リサイズで解き直すだけ**なのが良い。
これ1本から `position.y`（沈み）・`position.z`（奥行き）・`rotation.z`（接線方向の傾き）・
`rotation.y`（円周を向く回頭）を全部導出している。扇状に開く構図はここから出ている。

### 新技法③ — 無限ラップは「モジュロ1発」で解く

最初、参照実装によくある「プレートごとに `extra` オフセットを累積し、画面外に出たら±総長する」方式を書いたが、
**これは壊れる**。`while (x > limit) extra -= total` の直後に `while (x < -limit) extra += total` を回すと、
帯の総長が判定窓より長い場合に**引いて足して元に戻る**（＝永久にラップしない）。実際1回踏んだ。

正しくは、生の位置を **`[-total/2, total/2)` に1回のモジュロで畳む**：

```js
const x = (((lin + half) % total) + total) % total - half
```

方向の記録も累積状態も不要で、**1フレームで帯数個ぶん飛ぶ高速フリックの後でも正しい**
（累積オフセット方式が最も脆いのがまさにこのケース）。帯は画面の約2.4倍あるので、
±total/2 でのテレポートは必ず画面外で起きる。

### 新技法④ — 速度ディストーション：`current` という1つの数字が部屋全体を駆動する

ギャラリーの状態は**スカラー1個（`current`）だけ**。
ドラッグ・ホイール・フリック慣性・アイドル時のオートドリフトは全部 `target` に書き込み、
`current` は `THREE.MathUtils.damp` でそれを追う（フレームレート非依存, Day008系譜）。
そして **`current` の隣接フレーム差分＝速度**を、そのまま2つのシェーダに渡す。

- 頂点シェーダ：交差する2つの正弦で**紙が波打つフォールド**（`amp = 0.02 + uSpeed*0.26`）。
  静止時はほぼ完全な平面、速く動かすほど折れる。加えて **shear**（`p.x += uSpeedSigned * 0.16 * p.y*2`）で
  上端と下端が引きずられる
- フラグメントシェーダ：**速度スケールの色収差**。ここは調整が要った——
  最初 `a = uSpeedSigned * 0.028` の**線形**にしたら、ふつうのドラッグで
  全面が虹色に割れて monaka から完全に外れた（`?speed=0.75` の実描画で発覚）。
  **`a = uSpeedSigned * |uSpeedSigned| * 0.011` の2次に変更**して、
  ブラウズ速度では見えず、強いフリックでだけ滲むようにした。効果の要点はまさにそこ
- フォールドの幾何は**トーンにもエコー**させている（`col *= 1.0 + vFold*0.9`）。
  ライトを1つも置いていないアンリットのマテリアルでも、折れが読める

### そのほか

- **`object-fit: cover` のUV補正**をシェーダで。3:4のプレートを任意アスペクトの面に
  歪めずに載せる、実務そのままの定番（`ratio = min(planeAR/imgAR, 1)`）
- **不透明のまま奥へ溶かす**：フェードは全部「紙色へのmix」で作り、`transparent` は使わない。
  透明ソートも白画面リスクもゼロ（Day019で学んだ「存在/非存在で作る」の系譜）
- 中央のプレートだけ `z` を少し手前に出し、わずかに拡大（`focus`）。
  ドラッグ中でも部屋の中心がどこか目で分かる**奥行きの階層**
- 登場は中央から外側へ**スタッガード・リビール**（`age - dist*0.5`）。
  z方向に沈んだ状態から立ち上がりつつ紙色から現れる
- DOMは3Dと同期：中央のプレート番号・タイトル・レールが `current` から毎フレーム決まる
- 色空間は26日の流儀どおり `<Canvas flat>` ＋ シェーダ内 `pow(2.2)` で線形化 →
  最後にthreeが1回だけsRGBエンコード。テクスチャは `colorSpace = NoColorSpace` で
  生のsRGBバイトのまま渡し、二重変換を防ぐ

## 罠 / 詰まったところ

1. **`putImageData` は合成を無視する**（上記）。ポスターが全部灰色ノイズになった
2. **累積オフセット方式の無限ラップが「引いて足して戻る」**（上記）。モジュロ1発に置換
3. **色収差の線形ランプが強すぎ**（上記）。2次に
4. **構図衝突**：初回の実描画で、DOMの巨大な見出し `VITRINE` と扇の左端プレートが重なった。
   扇全体を `viewport.height * 0.11` 持ち上げ、プレート幅を 0.215→0.203、
   `bend` を 0.34→0.28 に絞り、見出しの上限を104px→86pxに。**ビルドが通っても構図は見ないと分からない**
5. **headless実描画のフレーキーさが再来**。同じ `--virtual-time-budget=9000` で
   2回成功→2回blank（28,453バイトの空カンバス）。8000は空、11000〜11500は安定。
   Day018/024/026と同じ症状で、**バイト数で成否を判定してリトライする**のが確実
   （空カンバスはPNGが極端に小さい）
6. **起動時に detached HEAD**（Day021と同じ）。ローカル`main`はDay023で止まっており、
   HEADはDay026＋今日のコミットを持つ状態。`git push origin main` は
   「behind its remote counterpart」で2回弾かれた。
   `git checkout main && git merge --ff-only <commit>` で早送りして解決。RUN.mdに手順を追記した
7. **GitHub Pagesのデプロイ確認をURLポーリングでやろうとして800秒を捨てた**。
   この実行環境から `ryota4100221-cmyk.github.io` は到達不能（root・前日ページ含め全部HTTP 000）。
   egress制限で、`hooks.slack.com`が403になるのと同種。
   デプロイ確認はGitHub MCPの`actions_list`でワークフローのconclusionを見るのが正解
   （実際、今日のrunは3分4秒でsuccessしていた）
8. **速度演出は静止画では検証できない**。headlessの `--screenshot` はドラッグもフリックもできないので、
   `?speed=-1..1` で速度uniformを直接ピン留めするデバッグパラメータを追加した
   （Day023 `?grade` / Day025 `?t` の系譜）。`?drift=N` でオートドリフト倍率も上げられるが、
   virtual-timeの窓が短くて帯が動ききらないため、検証には `?speed` の方が確実

## 確認方法

```
cd days/027_vitrine
npm install
npm run dev
```

- ドラッグ / ホイールで帯が流れる。手を離すと慣性で滑り、止まるとゆっくり自動ドリフト
- 速く弾くほどプレートが折れ、色が割れる
- `?speed=0.85` — 高速移動時のディストーションを静止状態で固定して見る
- `?drift=40` — オートドリフトを加速
