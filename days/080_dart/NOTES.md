## 何を再現し、何を捨てたか

**再現したのは、この会社の商売が立っている一つの事実。**「着たい服を、あきらめない。」という
FVコピーの下にあるのは、**平らな布は曲がった体に合わない**という、布側ではどうにもならない
幾何の事実で、お直し屋はその差額を毎日ハサミで払っている。キー演出をサイトから取るのではなく、
**サイトが売っているものを支えている装置**を1つに絞って取った。

それが 幾何／シェーダ／カメラ／時間／入力 のどれかと言えば、**幾何**。曲率だけで決まる話なので、
光も時間も要らない（実際この絵に光源オブジェクトは0個で、陰影は全部 ω の地図である）。

**捨てたもの：**

- サイト全体（FV動画・インタビュー・ベルメゾン連携・お知らせ・CTA）。1本に絞る
- Shippori Mincho と Noto Sans JP（外部フォントはこの環境から 403）。**組み方だけ借りた**——
  明朝を1文だけ 43px・行間198%・字間+6px で置き、残りを全部小さいゴシックに落とす型。
  ここでは Bitstream Charter 37px／行間1.98／字間0.115em に置き換えている
- 差し色サーモン #FF8A76 は実測で「3箇所だけ」。それに倣って**布が止まった線**と
  **布を留めた1点**と **claim の1語**の3箇所にしか置いていない
- 実在の人体（このボディは回転体に前後方向の扁平を掛けたトルソーで、誰かの体ではない）
- 重力・曲げ剛性・自己衝突・縫い代・厚みの効果

## 分解した装置：**選べるのは場所だけ**（the tailor chooses where, never how much）

織物は「伸びない2組の糸が、交点で自由に回れる」もの——これを **Tchebyshev net（チェビシェフ網）**
という。伸びないので長さは変えられない。回れるので、**自由なのは経糸と緯糸のなす角 ω ひとつだけ**。

体に当てるときは、与えるのは2本の曲線だけでいい。

- **地の目（grain line）** = 中心前の子午線 v=0。体の鏡映面なので、これは測地線
- **横地（cross-grain）** = バストラインの水平線 u=u₀

残りの交点は選べない。`rig.js` に書いてあるのはこの一行だけ：

> 次の交点 = 体の表面の上で、**左隣からちょうど a、下隣からちょうど a** の点

未知数は (u, v) の2つ、式も2つ（球2枚と面の交点）。前の目の平行四辺形を初期値にすると、
2つある根のうち正しいほう（対角の親から遠いほう）が勝手に選ばれる。状態も時間積分も
緩和反復も無い。**ある節点は、その左隣と下隣だけで完全に決まる。**

これが仕立て屋の「コンパス法」そのもので、繊維CADのドレーピングも同じ式で動いている。

### そこから勝手に落ちてきたもの（全部この実装で実測した）

**① 伸びないのは拘束ソルバのおかげではなく、作図のおかげ。**
全辺の長さ誤差の最大が **1.7e-16 〜 3.1e-16 × a**。倍精度の丸め誤差そのもので、
「伸びないようにする項」を一行も書いていない。

**② 誰も書いていない sine-Gordon を解いている。**
Tchebyshev 網の ω は ∂²ω/∂u∂v = −K·sin ω に従う。積分すると面積分が四隅の角だけで書ける：

```
∫∫K dA = ω(M,0) + ω(0,N) − ω(0,0) − ω(M,N)
```

左辺は**布を1枚も知らない量**（体のガウス曲率）、右辺は**体を1度も測らない量**（網の四隅の角）。
u₀ = 0.590、16×18 の窓で実測すると **2.332 vs 2.339（差 0.007／0.3%）**。
`rig.js` に sine-Gordon も曲率も一度も書いていない。

※ 検算の窓は首から下（u ≤ 1.00）に限っている。首では半幅が 0.09 まで細るので
a = 0.033 に対して a/R ≈ 0.37、つまり**面の曲がりに対して網が粗すぎて**左辺の
求積誤差だけで 200% ずれる。恒等式の限界ではなく検算の限界なので、窓のほうを寄せた。

**③ 網は、地の目について厳密に鏡映対称。**
P(i, j) と P(i, −j) の鏡映ずれが **1051 対で最大 0.00e+0**（ビット単位で一致）。
2本の軸が体の対称面と対称円の上に乗っているというだけで、対称化のコードは一行も無い。

そして**鏡はせん断の向きを裏返す**ので、詰まり方が2種類に割れる：

| u₀ | 閉じて詰まる目 (ω<90°) | 開いて詰まる目 (ω>90°) |
|---|---|---|
| 0.46 | 397 | 395 |
| 0.52 | 413 | 411 |
| 0.59 | **427** | **425** |
| 0.66 | 418 | 417 |
| 0.72 | 416 | 415 |

どの u₀ でも差は 2目以内。**布が詰まる向きは、曲率の符号ではなく「地の目のどちら側にいるか」で決まる。**
左右のダーツが必ず対になるのは、仕立ての流儀ではなく鏡映対称の帰結だった。

**④ いちばん効いた数：留める場所を動かしても、届く量は動かない。**

布を留める1点 u₀ を 0.46 → 0.72（体高の約1/4）まで61点で振ると：

```
届いた面積      60.23% 〜 64.65%（平均 62.32%、振れ幅 4.43pt）
届いた場所      u₀=0.46 と u₀=0.72 の一致度 Jaccard = 0.471（共通 741 目 / 合計 1572 目）
```

**量はほとんど動かないのに、場所は半分入れ替わる。**
地の目をどこに置くかで、ダーツがどこに落ちるかは大きく変わる。けれども
**落とさなければならない総量は変わらない。** 体の総曲率が動いていないからで、
これも ② の恒等式の言い換えになっている。

> 仕立て屋が選べるのは**ダーツの位置**であって、**ダーツの量**ではない。

布が持ち込む数は1つだけ——**どこまでせん断したら目が固まるか**（平織で概ね ±40°）。
実測の最大せん断は 39.84°〜39.99° で、例外なく lock の値に張り付いて止まる。
その1つの数さえ決まれば、**止まる場所を決めているのは全部、体の曲率**である。

## 絵のほうの決めごと

- **陰影は照明ではなく ω の地図。** 糸を線分で描かず、目の四角の中にフラグメントシェーダで
  格子を引いている。糸1本の太さを画面上で一定にすると、単位面積あたりの本数
  = 1/(a²·sin ω) がそのまま濃度になる。**せん断で目が詰まった所が勝手に暗くなる。**
  ライトオブジェクトは0個（トルソーにだけ弱い directional を1本）
- **正投影。** 「どこで止まるか」を読む絵なので、遠近で目の大きさが変わると ω の地図が読めない
- 太い黒の2本＝与えた2本の軸（地の目と横地）。**これだけが入力**であることを絵の中で言う
- 布の解は素の面 S 上で解き、描画だけ法線方向に 0.005 浮かせている（布の厚みぶん）。
  解には一切効かない
- 動くのは**留めた1点だけ**（34秒で u₀ が 0.46↔0.72 を往復）。カメラも体も動かない

## つまずき（実測した順）

1. **`gl_FragColor` が undeclared。** three r169 の `glslVersion: GLSL3` 経路は
   `pc_fragColor` も `gl_FragColor` も用意しない。出力は自分で
   `layout(location = 0) out vec4 fragColor;` と宣言する。**fragment だけコンパイルに落ちるので、
   ビルドは通り、トルソーと線（Basic/Standard マテリアル）だけが出た絵が残る。**
   「3Dは出ているのに主役だけ居ない」という、いちばん気づきにくい壊れ方をした
2. **🔴 空カンバスが 204KB あった。** この日は DOM オーバーレイ（大きな明朝3行・本文・実測値の表）が
   必ず描かれるので、**3Dが1フレームも出ていなくても PNG が 204KB になる**。
   「空カンバス ≒ 28KB」という過去の目安が通らない日で、1回目は `SHOT_MIN=60` を
   楽々通した「文字だけの絵」を掴んでいた。気づいたのは readout が全部 `—` だったから。
   実測 **3Dが出た = 373〜394KB / 出ていない = 204KB** なので閾値を 300KB に置き直した。
   直後の撮影で 5回中2回が 204KB で弾かれて撮り直しに入った＝実際に起きる事故だった
3. **ボディの裾がラッパに見えた。** 筒の上下を塞いでいなかったので内側が見えていた。
   さらに網の定義域がボディより広く、**布が台の外へ 0.14 ぶんはみ出して**
   サーモンの輪郭が宙に浮いていた。網とボディの定義域を同じ [−0.02, 1.10] に揃えた
4. **60fps に届かなかった（24〜54ms/frame）。** Newton の1反復で `A(u)`/`B(u)` を
   素直に呼ぶと `exp` を18回叩く。A/A'/A''/B/B'/B'' を exp 6回で一度に出して u でキャッシュ
   したら **4.4〜8.3ms** になった（5倍）
5. 検算の窓を「生きている最大の矩形」にしたら、首まで伸びた回で差が 454% になった。
   §② の注に書いた通り、これは網の粗さであって恒等式の話ではない

## 今日の1本が、昨日までと別の絵である理由

直近7日は 静物／文字／静物／建築／群れ／地形／液体。**布は初出。**
装置も、直近7日の「1つの数が全部を決める」型（細さ λ・視点 E・歩数の偶奇・枚数 n・幅 b・
時刻 n・波長 λ*）とは向きが違う——今日のは **「決まらないもの（場所）と決まるもの（量）が
分かれている」** という形をしている。選べる自由が1つあって、それでも動かない量がある。
