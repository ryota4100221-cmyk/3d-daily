# Day 032 — Loop 05 · 体積を「資産」にする「Lantern」（froxel volumetrics）★★★★★

## 狙い

Day 031 で初めて**面と面のあいだ**を描いた。ただし、あの答えは **1フレーム限りの絵**でしかなかった。
ピクセルごとに48歩マーチして、コンポジットが1回読んで、捨てる。
**二度読めない・コンポジット以外に読ませられない・ウィンドウを広げると比例して高くなる。**

今日はその積分を**グリッドに1回だけ焼く**。
256×144×64＝**2,360,000セルの視錐台整列ボクセル（froxel = frustum voxel）**。
出てくるのは「霧の絵」ではなく **「任意の (画面uv, 深度) で引ける資源」** で、
そうなった瞬間に、昨日は構造的に不可能だった3つのことが同時に起きる：

1. **透明物が自分の深度で霧を解決できる**（＝この企画で初めてのガラス）
2. **2つ目の光源が実質タダ**（マーチなら48歩×2枚目のシャドウ参照だった）
3. **画面解像度と無関係**（4Kでも720pでも霧のコストは同じ）

Day 031 のNOTESに自分で書いた宿題「froxel化」の回収。

## 新しく入れた技法

### 1. froxelボリューム＝**2Dアトラス**（3Dテクスチャではない）

WebGL2 の3Dレンダーターゲットは **1ドローで1レイヤーしか書けない**。
64スライスなら注入だけで64バインド、積分まで入れると384ドロー。話にならない。

→ **64枚のスライスを 8×8 のタイルに並べた 2048×1152 の2Dアトラス1枚**にした。
ボリューム全体が **1つのフレームバッファ＝1ドロー**になる。

代償はサンプリングで、**三線形補間を自分で書く**ことになる：
タイル内のバイリニアはハードウェアに任せ、**タイル間のlerpだけ手で**やる。

```glsl
vec4 fetchFroxel(sampler2D atlas, vec2 uv, float sIndex) {
  float k0 = floor(s), k1 = min(k0+1.0, N-1.0);
  vec2 h = 0.5 / uFroxel.xy;
  vec2 c = clamp(uv, h, 1.0 - h);   // ← このclampは必須
  return mix(TEX2D(atlas, tileUV(c,k0)), TEX2D(atlas, tileUV(c,k1)), s-k0);
}
```

`clamp` が無いと、**タイルの端テクセルのバイリニアタップが隣のタイル＝部屋の別の場所**を拾う。

### 2. 積分＝**並列プレフィックススキャン**（今日の一番の発見）

視線に沿った前→後の積分は

```
L_k = L_{k-1} + T_{k-1}·l_k ,  T_k = T_{k-1}·t_k
```

で、いかにも**直列依存のループ**に見える。だが演算子

```
(L_a, T_a) ⊕ (L_b, T_b) = (L_a + T_a·L_b , T_a·T_b)
```

は **結合的**（2×2上三角行列の積と同じモノイド）。**結合的ならスキャンできる。**

→ Hillis-Steele で **`out[k] = in[k-offset] ⊕ in[k]` をオフセット 1,2,4,8,16,32 の6パス**。
64歩の直列チェーンが **log₂64 = 6 回のフルスクリーン描画**になる。
**レイヤードレンダリング不要・フィードバックループ不要**（ping-pongで2枚回すだけ）。
終わったとき、**全スライスが「目からそのスライス裏面まで」の完全な積分**を持っている。

単位元は `(0,1)`＝「まだ何も光っていない・何も吸われていない」。ボリュームの手前側は全部これ。

初回パスだけ入力が (rate, extinction) なので、そこで解析形に変換する：

```
T = exp(-σ·s) ,  L = S·(1-T)/σ      (σ→0 は L = S·s)
```

Day 031 のリーマン和を**閉形式に置き換えた**。奥のスラブが数メートル厚でも誤差が出ない。

### 3. 注入は「積分値」ではなく**「レートと消衰」を書く**

これが**時間フィルタを正当化する**。セルのスラブ厚はカメラで変わるが、そこの**密度は変わらない**。
レートを混ぜるのは同じ物理量を混ぜること。積分値を混ぜたら別々の量の平均を霧と呼ぶことになる。

### 4. 時間再投影が**3Dで厳密になった**（Day 031 の重心ハックが不要になった）

昨日はバッファが2Dだったので「このピクセルの霧は前フレームどこ？」に**答えが無く**、
**散乱重心**（寄与で重み付けした平均深度）という代理量を発明する必要があった。

今日は**セルそのものが場所**である。ワールド座標を持っている。
前フレームのビュー射影行列を掛ければ**厳密に**そこ。ハックは要らない。

**ハックが消えたことが、足りなかったのが第3の次元だったという一番の証拠**だと思う。

棄却も弱めた（`smoothstep(0.60,1.20,diff)`）。昨日は再投影が推測だったから強く棄却したが、
今日の再投影は行列であって、フレーム間差分の大半は**自分で入れたジッタ＝積分すべき信号**である。

### 5. セルを**点サンプルではなく面積平均**にする（xyz 3軸ジッタ）

最初の実装は 192×108 でセル中心を1点サンプルしていて、光条のエッジが**グリッドに階段状に量子化**された。
浅い対角線をグリッドで量子化すると、8pxのセルでも**数十pxの水平ラン**になる。

→ **セル境界は固定したまま、セル内のサンプル位置だけを毎フレーム動かす**（xy=Halton、z=黄金比）。
時間フィルタと組み合わさると、各セルは**自分のフットプリントの平均**に収束する。
エッジは階段ではなく**2セルにわたるランプ**になり、階段が消えた。解像度は 256×144 に上げた。

### 6. コンポジットから**バイラテラル・アップサンプルが丸ごと消えた**

Day 031 の40行は全部同じ傷の手当てだった：ハーフ解像度の2Dバッファはピクセルあたり1つしか答えを持てないので、
器の口をまたぐ4テクセルが「12mの霧」と「30cmの磁器」を持ち、平均すると**全エッジにハロー**が出る。

**シルエットとは深度の不連続**で、ボリュームには今**深度軸がある**。
口の両側のテクセルは froxel グリッドでは**隣ではない・別のスライスにいる**ので、三線形読みが**そもそも混ぜない**。
**足りない次元の埋め合わせだったものが、次元そのもので解決した。**

### 7. **ディファードの中のフォワード透明パス**（4日ぶりの新しいパス）

Day 028〜031 は透明物ゼロ。G-bufferはピクセルあたり1面しか持てず、ガラスはそれが嘘になる場合だから。

合成則は**チューニングではなく導出**した。C＝背後の合成済み、L/T＝目からこの面までの入散乱と透過率、
`transmit`＝ガラスを通る割合とすると：

```
final = L + T·surface + transmit·(C - L)
      = transmit·C + [ L·(1-transmit) + T·surface ]
```

これは **α = 1-transmit の premultiplied alpha ブレンドそのもの**。
つまり**ブレンドモード1つで済み、デスティネーションを読み戻さず、しかも入れ子が正しい**：
**裏面→表面の2ドロー**で、深度バッファもソートも無しに2層のガラスが正しい順で合成される。

深度テストは**テクスチャフェッチとdiscard 1行**。HDRターゲットに深度添付は無いし、要らない——
G-buffer が線形単位で「手前に何があるか」をすでに知っている。

そして肝心なところ：**ガラスは自分の深度でボリュームを引く**。
スクリーン空間マーチでは「この面の手前の空気」だけを別途知る方法が無い。1回の三線形読みで厳密に出る。

## ハマった点（次の自分への申し送り）

- **`gl_FrontFacing` は `side: BackSide` で嘘をつく。**
  three は BackSide を「裏面を描く」ではなく **`frontFace(CW)` で巻き方向を反転**して実現する。
  結果、**法線が視線と逆を向いている面ほど `gl_FrontFacing == true`** になる。
  これで裏面のフレネルがシルエット全域で 1 に張り付き、**透明度0.12の「ブリキ缶」**になった。
  正解は `if (dot(N, V) < 0.0) N = -N;` ——**視線ベクトルで向き直す**。薄板なら常にこれでいい。
- **軸上の点光源に Blinn ローブを使ってはいけない。**
  筒の軸に光源があると、**遠い側の壁では半ベクトルが壁全域で法線と揃う**。
  ハイライトではなく**一様なウォッシュ**になり、円筒が牛乳瓶になった。
  ランプがガラスに対してしていることは「両側の空気を光らせる」ことで、それは**ボリュームがすでに知っている**。
- **指数スライス分布は near 次第。** `near=0.35` にしていたら、`?pass=7` のアトラスが
  **8行中6行まっ黒**で返ってきた。カメラは霧のポケットの外に立っていて、5ユニット手前まで何も散乱しない。
  **64枚中47枚を空気に使っていた。** `near=6.0` にしただけでスラブ厚が半分以下になった。
  **グリッドのnearはカメラのnearではない。**
- **アトラスの上流にあるものは画面にも映る。** スラットの衝立（10枚・ピッチ3.4）は Day 031 より
  はるかに幅広なので、**フレーム右上に思いきり映り込んだ**。`rig.screen.visible` を
  **ライト空間パスの1呼び出しの間だけ true** にして解決。ここで three 自身の影マップも
  （`needsUpdate` を立ててあるので）同時に焼かれるので、**衝立が存在すべき瞬間はこの1回だけ**。
  結果、**全面に縞を落としながら一度も画面に現れない**。Day 031 の作法をそのまま継承。
- **2つのボリュームはインデックスが半スライスずれる。** 注入ボリュームのテクセル k は
  スラブ中心 z(k+0.5) のサンプル、スキャン後のテクセル k はスラブ**裏面** z(k+1) までの積分。
  `sampleMedium` / `sampleScatter` を分けた。見て気づける種類のバグではない。
- **スキャンの読みは `texelFetch`。** アトラスは下流のために LINEAR フィルタなので、
  計算した uv がテクセル中心の左に1ビット落ちるかどうかに賭けたくない。
- ping-pong の書き先を `scan[i % 2]` にして**同じターゲットに読み書き**する1行バグ。`(i+1) % 2` が正しい。

## デバッグ用URLパラメータ

- `?t=12.5` — シーン時刻をピン留め（速度0＝TAA完全収束、ブラー消滅）
- `?phase=26` — 止めずに26秒目から（previewは phase=26）
- `?pass=1..9` — Composite / Beauty(乾いた空気) / Normals / Velocity /
  In-scatter / Transmittance / **Froxel atlas（64スライスのコンタクトシート）** / Light depth / TAA off

`?pass=7` は今日2回仕事をした：**近スライスが空だと一目で分かる**のと、
**タイル間の滲みが出ていないことの確認**。Day 031 の「合成成功≠各パス正常」の続き。

## 次に試したいこと

- **透明物のベロシティ書き出し。** ガラスは速度バッファに何も書かないので、
  TAA は背景の動きでガラスのピクセルを再投影している。今のカメラ速度なら分散クリップが吸収しているが、正しくはない。
- **多重散乱。** まだ単散乱のみ。froxel なら安い近似がある：**前フレームの積分済みボリュームを
  「環境項」として注入に戻す**（1フレーム遅れの拡散近似）。マーチでは組めなかった構造。
- **ボリュームの再利用先を増やす。** 今日は composite と glass の2箇所。
  パーティクル、水面、ソフトパーティクルの減衰も同じ1フェッチで正しくなるはず。
- **ライト深度マップのカスケード**（Day 031 からの持ち越し）と**ブルーノイズ・ジッタ**。
- **froxel の xy をもう一段**（384×216）か、あるいは**スライス数を可変**にして
  「霧が実在する深度レンジ」に毎フレーム自動で合わせる（今日 near を手で 6.0 にしたのを自動化する）。
