## 分解（何を再現し、何を捨てたか）

- キー演出は **横スクロール** 1つ。縦のホイールが横の移動になる、あの仕掛けだけ。
- それは何でできているか：**入力（スクロール）→ カメラ**。幾何は舞台装置で、シェーダは何もしていない。
- 再現したもの：345.6px の「Shichifuku」を**そのままの px サイズで**語の面（d = 16 m）に置いた
  （fontSize = 345.6 / 44.625 px/m = 7.745 m）。字間 −5%。地・墨・橙の3色。
  事業の4章（＋1959年創業）を横に並べ、各章に軸組を1棟ずつ立てた。
- 捨てたもの：写真・マーキー・スクロールリビール・縦の本文・会社概要・CTA・深緑 #1B2825・
  Helvetica Neue LT Pro 本体（Liberation Sans＝Helvetica とメトリクス互換で代用）。

## 装置：縫い付けられた奥行き（the depth the page is sewn to）

DOM の横スクロールでは、ストリップ上の要素は全部「1 px につき 1 px」動く。
この日はストリップを動かさず、**カメラを**動かした。すると距離 d の点は Δx·K/d px 動く。
ページのスクロールと1:1になる距離は1つだけで、それを語の面にした。

| 層 | d | 1 スクロール px あたりの移動（three の射影で実測） |
|---|---|---|
| 軸組 Frames | 8 m | **2.000000×** — ページを追い越す |
| ワードマーク | 16 m | **1.000000×** — ページに縫い付けられている |
| 稜線 Ridge | 48 m | **0.333333×** — ページに置いていかれる |

- キャプション（01 Order Housing …）は**ただの DOM**で、動かしているのは `translateX(−scrollY)` だけ。
  3D の座標は一度も読んでいない。それでも語の面に立てた橙の目盛りと
  **最大 1.36e-12 px**（67 スクロール位置 × 3画面）しかずれない。縫い目がその1枚にしか無いことの証明。
- **全層が揃うのは、その真正面に立った瞬間だけ**：各章の軸組は、語の面の目盛りと**同じ world x** に建てた。
  距離が違っても x が同じなら、カメラがその x を通るときにだけ全部が画面中央で重なる。前後ではずれていく。
- レンズはシフトレンズ：カメラは水平のまま（柱は倒れない）、フラスタムを非対称にして地平線を画面の 72% に下げた。

## つまずき

1. **床が y ≈ 0.9 m より下を全部飲み込んだ。** 柱の足元・ワードマークの下半分・稜線の足元が、
   それぞれ違う画面の高さで、でも同じ world 高さで切れていた。床を赤にしても赤が出ない。
   フォグを外すと赤い床が出て、切れ目は床の縁だった。原因は床ポリゴンの頂点が**カメラ面ちょうど（z = 0, w = 0）**
   にあったこと。swiftshader がその三角形のフォグ深度と深度の補間を壊していた。床を 1 m 前から始めて解決。
2. **setViewOffset の射影を R3F が上書きした。** node では正しい行列が出るのに、ブラウザでは縦だけ縮んだ。
   `camera={{ manual: true }}` にして `makePerspective` で行列を毎フレーム自分で書いた。
3. **headless の `--screenshot` は、文書をスクロールした状態を撮れない**（全面が地色）。
   `?s=<px>` でスクロール量だけを固定し、window は動かさない経路を足した。
4. **橙の目盛りがワードマークと z-fight。** 同じ語の面に置いたので、Text に `depthOffset={1}`。
5. **空カンバス判定の閾値**：今日の絵はベタ地＋ベタ塗りで PNG が小さい。実描画 74〜86KB、空 55〜64KB。閾値 72KB。
